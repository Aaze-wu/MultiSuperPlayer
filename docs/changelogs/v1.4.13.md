## 二、卷根为什么算「覆盖全部」

### 症状

偏好页里那一行叫「存储根目录」，但它**永远显示 `0 个文件`**，而它下面挂着的子目录各自显示
`1 / 26 / 16 / 1 个文件`；勾上这一行**也不等于全选**，媒体库只剩直接躺在存储根的那几个文件。

### 根因

`LibraryFolderRules.covers(parent, child)` 只判 `parent == child` 或
`child.startsWith("$parent/")`。而卷根的路径是**空字符串** `""`：

- `"" == ""` 成立 ⇒ 覆盖自己；
- `"Music".startsWith("/")` **不成立** ⇒ 不覆盖任何子目录。

于是把卷根当成「一种和 Music、Movies 并列的位置」，可它实际上是**所有行的祖先**。
计数（`totalCount` 靠 `covers` 累加）与勾选（`accepts` 靠 `covers` 判定）都因此错，
只是错误表现成「显示 0」而不是报错，所以从 1.4.0 加上这个页面起就没被发现。

### 改法

```kotlin
fun covers(parent: String, child: String): Boolean =
    parent.isEmpty() || parent == child || child.startsWith("$parent/")
```

一行，同时修好三件事：

- 根行的 `totalCount` = 全库条目数（实机 `44 个文件`，等于下面四行之和 `1+26+16+1`）；
- `toggle(setOf("Music"), "")` ⇒ `{""}`，即**勾上根 = 全选**；
- `minimize` / `selectAll` 的「最小形式」跟着变：`minimize(setOf("", "Music"))` 现在是 `{""}`，
  `selectAll` 对任何非空列表恒为 `{""}`。

### 代价（写清楚，免得以后被当成 bug）

`""` 的含义从「只有根目录」变成「整个卷」，于是**没有值能表达「只有根目录」**。
一旦卷根不再被选中——用户手动取消它，或取消了一个被它覆盖的子文件夹（`minimize` 会展开成
同级兄弟节点）——**直接躺在存储根的那几个媒体文件就不再进库**。

取舍：优先保证「勾上那一行 = 全盘」这个最常用、也最符合直觉的语义；卷根直属放媒体文件本来
就不是常规做法，而「想连根目录一起要」时勾的就是那一行。用例里显式断言了
`accepts("", result)` 为 `false` 来固化这个取舍。

## 三、否定 / 推迟的方案

- **B｜只把根行的计数改成 `sum(children)`（纯显示修正，勾选语义不动）。** 数字变对了，但
  「勾上却不全选」还在——那是把界面做得更像在说谎，否掉。
- **C｜把卷根那行做成伪节点（独立的「全选」开关，不进路径列表）。** 语义最干净，但要
  `FolderNode` / `LibraryFolderRules` / ViewModel / UI 四层都引入「伪节点」概念，还得重定义
  「已选 N 个文件夹」这句话；改动面比一行大一个量级，收益只是边界场景更准，推迟。
- **D｜把 `buildLibraryUiState` 经 `flowOn` 搬离 Main。** 仍然是真实热点（全量条目在 Main 上重排），
  但与本次修正无关，继续推迟。**仍是下一版优先级最高的一项。**
- **E｜持久化快照。** 同上，继续推迟（理由见 beta changelog §三）。

## 五、测试怎么盖住

- 全量 `.\gradlew.bat test --console=plain`：**191 个 suite / 2576 个用例 / 0 失败**
  （beta 时为 2574，本次 +2 个新用例）。
- 新用例盯的正是「以前测不到」的地方：卷根不再是「只覆盖自己」，而是「覆盖全部」；
  以及展开成兄弟节点后 `""` 不在集合里这一必然结果。

  「展开后根还在」），单测立刻红（`870 tests completed, 1 failed`）。它暴露的不是笔误，
  而是这个取舍真的存在 ⇒ 改成断言 `false` 并把理由写进注释。
- **单测能盖住的部分到此为止**：`covers` 是纯函数，但「那一行显示 44 而不是 0」是 UI 计算的结果，
  只能在设备上看（见 §六）。

## 六、模拟器核查（正式版发布前）

用户要求正式版先在模拟器验证再发。环境：`Medium_Phone` AVD（Android 17），
`installDebug` 装的是本次工作区代码（`当前版本 1.4.13`），媒体库目录里有
`Music`（17 条）、`Movies`（27 条）、`Download`（1 条）、`upload`（1 条）。

| 操作 | 结果 |
| --- | --- |
| 打开 设置 → 媒体库文件夹 | 「存储根目录」显示 **`44 个文件`**（= 1+26+16+1 子项之和；修复前是 `0 个文件`） |
| 勾上「存储根目录」 | 摘要变 **`已选 1 个文件夹`**；媒体库显示 **`全部 44 / 音乐 17 / 视频 27`**，内容没变少 |
| 取消「存储根目录」 | 摘要变 **`一个文件夹都没勾：媒体库现在是空的，但文件都还在。`**，媒体库为空（符合预期：根是兜底项） |
| 勾着根、再取消 `Download` | 摘要变 **`已选 3 个文件夹`**（展开成 `Movies` / `Music` / `upload`），即 §二的取舍成立 |

崩溃缓冲区里唯一的 `FATAL EXCEPTION` 属于系统的 `com.google.android.apps.wellbeing`，与本应用无关。

**模拟器证明不了的部分**（仍需真机/真实数据）：真实耗时、真实 IPC 次数、真实 `ContentResolver`
行为、大目录（含 `.thumbnails`）下的观感。这些的取证口径与 beta 相同（`adb logcat | Select-String '扫描耗时'`），
见 `docs/changelogs/v1.4.13-beta.1.md` §六；alpha 阶段用户已确认「速度有明显提升」，
beta 期间未收到回退反馈。
