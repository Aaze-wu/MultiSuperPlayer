# v1.4.11

发布日期：2026-10-30

## 变更

### 修复

- **切换底部标签不再丢失「浏览」页的目录深度与滚动位置。** 之前切到别的标签再切回「浏览」，
  会回到来源清单、再进目录从第 1 项开始。原因是切标签会弹掉非起始标签的返回栈，
  连带销毁页面里创建的 `ViewModel`；本版把 `BrowseViewModel` 提到 Activity 作用域，
  并作为参数显式传给 `BrowseRoute`。
- **点当前标签回到该标签首页。** 在「浏览」的子目录里再点一次「浏览」会回到来源清单；
  「网络地址」页点「浏览」、「收藏」页点「媒体库」同样弹回对应首页。判断「是不是当前标签」
  用「这个路由归哪个标签管」（`MspDestination.owns`），因为「收藏」「网络地址」是归属别的
  标签的子页面、那时标签本来就是高亮的。

### 不变

- 在播放页点「媒体库」仍然退出播放页 —— 这条路径有回归守卫，实机已复验。
- 「最近」「播放列表」切换标签后仍回到列表顶部（本版只修「浏览」，已单独记录待办）。
- 没有新增权限、没有新增后台行为、没有改动文件格式 / 数据库 / 界面文案。

## 设计取舍（否定过的方案）

切标签时 `navigateToTab` 用 `popUpTo(起始目的地)` 弹掉非起始标签的返回栈 —— 这是当年为了
避开「在播放页点『媒体库』却没反应」刻意选的写法（见 `MspApp.kt` 里那段注释）。被弹掉的
`NavBackStackEntry` 会 `clear()` 它的 `ViewModelStore`，`rememberSaveable` 一并消失。

**方案 A（否决）：给标签加 `saveState / restoreState`。** 读 `NavControllerImpl` 源码可以确认
`executePopOperations` 写的是 `backStackMap[destination.id] = savedState.firstOrNull()?.id`，
**键是「弹到哪里」（起始目的地「媒体库」）**，而 `navigateInternal` 只要
`backStackMap.containsKey(node.id)` 就恢复。于是点「媒体库」可能把**另一个标签的栈连同播放页
一起复活** → 正是那个旧症状。所以这条路不走。

**方案 B（采用）：把 `BrowseViewModel` 提到 Activity 作用域。** `koinViewModel()` 在
`MspAppScaffold` 里解析，Owner 是 Activity 的 `ViewModelStore`，`popUpTo` 无法销毁它；
再作为参数显式传进 `BrowseRoute`（照 `updateViewModel` / `UpdateRoute` 的既有先例）。
`sources` / `snapshot` 仍是 `WhileSubscribed(5_000)`，离开标签后不干活。

「点当前标签回首页」的坑：**「收藏」页属于「媒体库」、「网络地址」页属于「浏览」**，
这两页时标签本来就是高亮的 ⇒ 判断「是不是当前标签」不能只比路由，要用
`MspDestination.owns(route)`。另外「浏览」的目录深度在 `ViewModel` 里、不在返回栈里，
所以 `goToTabHome(BROWSE)` 还要额外 `browseViewModel.leaveSource()`。
