## 一、这一版做了什么

一行装不下的标题不再一律截断成 `…`：列表里**当前播放的那一条**、以及**多选里被勾上的那一条**，其标题会做横向 marquee 滚动；其余行照旧省略号。设置 → 外观 →「列表显示」 →「长文件名滚动」可以关掉，默认开。

范围刻意收在「列表行」：

- 浏览器行、媒体库行、最近行、播放列表行、收藏行（全部走 `MediaEntryRow` / `BrowserPane` 两处）
- 播放页底部弹出的队列（`QueueSheet`）
- **不动**：网格卡片 `MediaEntryTile`（`maxLines = 2`）、播放页竖屏 `TrackInfo`、横屏 `PlayerControls` 顶部标题、`:690` 的 `ChipButton`

## 二、`ScrollingTitleText` 的实现细节

入口只有一个 composable：

```kotlin
ScrollingTitleText(text, entryId, modifier, selected, style, color)
```

### 1. 为什么用 CompositionLocal

调用点在 5 个文件、6 处；每处都需要两个「全局」信息（开关、当前条目 id）。若走参数传递，`MediaEntryRow` / `BrowserPane` / `QueueSheet` 的签名都要加两个参数，再一路往上穿过 `LibraryScreen` / `RecentScreen` / `FavoritesScreen` / `PlaylistScreen` / `PlayerScreen`。用 `LocalTitleScrollState` 把这两件事一次性注入，签名不变 ⇒ 四个 `MediaEntryRow` 调用点一行都没改。

### 2. 为什么 `enabled` 默认 `false`，而真正的默认值在 `TitleScrollRules.DEFAULT_ENABLED`

`TitleScrollState()` 的默认值只服务于 **Compose preview 与忘写 provider 的场景** —— 那种情况下让它别动，比在预览里狂滚好。真正的产品默认值只在 `MspApp` 里读：`display.scrollLongTitles ?: TitleScrollRules.DEFAULT_ENABLED`。两处默认值刻意不是同一个含义，KDoc 里写清了这一点。

### 3. 为什么用 `ValueAnimator.areAnimatorsEnabled()`

`basicMarquee` 自己不看系统的「移除动画」（animator duration scale = 0）。无障碍用户关掉动画后，滚动的标题会变成一块持续抖动的噪声。所以把系统设置显式并进判定：`shouldScroll(enabled, animationsEnabled, isCurrent, text)` 四个条件缺一不可。

### 4. 为什么必须**条件性**加 `basicMarquee`，而不能总是挂着

`BasicMarqueeModifier.measure` 给子项的约束是 `Constraints.Infinity` 的 maxWidth，并自己画两份裁剪过的副本处理溢出。也就是说它是「无论放不放得下都按 marquee 逻辑排版」。如果无条件挂上，再靠 `overflow = Ellipsis` 去兜，两者会打架（ellipsis 永远不会发生，因为文本被认为没有宽度上限）。所以：

```kotlin
modifier = if (scrolling) modifier.basicMarquee(...) else modifier
overflow = if (scrolling) TextOverflow.Clip else TextOverflow.Ellipsis
```

### 5. 滚动时 `softWrap = false` / `maxLines = 1` / `TextOverflow.Clip` 三者必须一起换

marquee 的位移是「单行内容整体平移」。若还允许折行，被平移的是一段折好的多行文本，第二行会跑到第一行的位置下面 —— 必须钉成单行。而单行 + `Ellipsis` 会让 marquee 量到的是「已经加了省略号的字符串」，所以滚动期间用 `Clip`。三者是一组，不能只改其中两个。

### 6. 纯函数为什么单独抽出来

`feature/library` / `feature/player` / `core/ui` 都**没有** `compose-ui-test` 依赖 ⇒ 这些模块里的 Compose 行为在 JVM 上测不了。能测的只有不依赖 Android 的部分：`isCurrent` / `shouldScroll` / `DEFAULT_ENABLED` / 两个节奏常量。`TitleScrollRules` 就是为此存在的，与仓库里 `LyricsScrollRules` / `ReorderDragState` 同一套路。

## 三、DataStore 的 `Boolean?` 与键名契约

`DisplaySettings.scrollLongTitles: Boolean?`：

- `null` = **没设置过**（全新安装 / 从没动过那个开关）
- `true` = 明确打开
- `false` = 明确关掉

映射函数 `Preferences.toDisplaySettings()` 对这个键**不加 `?:`**，原样保留 `null`。默认值只在 UI 层出现一次（`MspApp` 与 `AppearanceSettingsScreen`）。这样后续改默认值时，老用户「明确关掉」的选择不会被悄悄翻回去 —— 这也是 `ThemeSettings` 已经在用的约定。

键名 `display.scroll_long_titles` 是**写入用户设备的契约**：改名等于把这个开关对所有人重置（`internal object Keys` 上的 KDoc 写了这条警告）。

## 五、测试怎么盖住

`TitleScrollRulesTest`（8 例）：

1. 默认是开着的
2. 只有当前那一条算当前
3. 勾上的算当前（即使它不是正在播的那条）
4. 没有 id 的行不滚
5. 四个条件缺一不可（`enabled` / `animationsEnabled` / `isCurrent` / 非空文本 的笛卡尔否定）

1. 全新安装时是「没设置过」，不是「关着」
2. 持久化键名是写入用户设备的契约（断言字面量 `display.scroll_long_titles`）
3. 关掉和没设置过必须是两个不同的值
4. 别的分组的键不会漏进列表显示

未覆盖的部分（JVM 上测不了，只能实机）：marquee 的实际位移、`CompositionLocal` 的注入、开关行与 `DataStore` 的接线。第九节是用实机截图逐条盖住的。

## 六、被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 网格卡片 `MediaEntryTile` 也滚 | 卡片标题本就给两行、横向也够；滚动会破坏「一眼扫一片」的用途 |
| 播放页标题也滚 | 那里的标题本来就完整显示（放不下就折行），没有「看不全」问题 |
| `singleLine = true` + 自己 `animateScroll` 猜宽度 | 猜宽度必然在字体缩放、CJK/拉丁混排、字重变化上翻车；`basicMarquee` 已经量过了 |
| 所有行无条件挂 `basicMarquee` | 见第二节第 4 点：与 ellipsis 冲突 |
| 在 DataStore 里把默认值写成 `true` | 「没设置过」与「明确关掉」会被合并，后续改默认值时老用户的选择被覆盖 |
| 用 `remember { }` 存当前条目 id | 组合作用域会在滚动/重组中丢失，且每个调用点都要各自同步一份 |
| `LaunchedEffect` + `Animatable` 自己实现 | 需要额外处理「放不放得下」的测量、双份绘制、指针输入期间的暂停；等于重写一个 `basicMarquee` |

## 七、已知限制（工程视角）

- 依赖 `basicMarquee`（foundation 1.11.4）的行为：`measure` 传 `Constraints.Infinity`、内部画两份裁剪副本。升级 Compose 时需要复核这两点。
- `ValueAnimator.areAnimatorsEnabled()` 为 `false` 时整条路径退化为省略号，无法在 JVM 单测里覆盖（平台 API）。
- `selected` 的语义是「多选里被勾上」；勾选多行时被勾上的行都会滚。这是当前取舍，不是遗漏。
- `BrowserPane` 的 `entryId` 用的是 `entry.mediaId`（非空、由 `mediaIdOf(ref)` 计算得出），与 `MediaEntry.id` 共用同一个 id 空间；这一点若将来改动 id 生成规则需要同步核对。
