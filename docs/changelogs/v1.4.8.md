## 一、这一版做了什么

一行装不下的标题不再一律截断成 `…`，改为横向 marquee 滚动，并且**按页可配置**：

1. **主开关**：「长文件名滚动」，设置 → 外观 →「列表显示」 →「长文件名滚动」（子页）→ 子页最上方的总开关。默认**开**。
2. **按页开关**：「始终滚动的页面」7 项，multi-select，默认**一个都不勾**。勾上的页 ⇒ 该页所有放不下的标题都滚；没勾的页 ⇒ 只有当前播放/选中的那一条滚。
3. 总开关关闭时，7 项**整体置灰但保留勾痕**，重新打开后原样生效。

范围：7 个页面共 8 类行

| 页面（`TitleScrollPage`） | 落点 |
| --- | --- |
| `LIBRARY` | `LibraryScreen` → `MediaEntryRow`（含网格以外的列表态） |
| `BROWSE` | `BrowserPane` 的目录行 + 文件行 |
| `RECENT` | `RecentScreen` → `MediaEntryRow` |
| `FAVORITES` | `FavoritesScreen` → `MediaEntryRow` + `FolderRow` |
| `PLAYLISTS` | `PlaylistScreen` → `MediaEntryRow` + `PlaylistRow`（清单名） |
| `QUEUE` | `QueueSheet` 的队列行 |
| `NETWORK` | `NetworkScreen` → `NetworkUrlRow` |

**刻意不动**：网格卡片 `MediaEntryTile`（`maxLines = 2`）、播放页竖屏 `TrackInfo`、横屏 `PlayerControls` 顶部标题、`BrowseScreen` 最外层来源清单（`SourceRow` / `NetworkSourceRow`，标题来自固定 `@StringRes`）、`PlaylistPickerDialog`。

## 二、`ScrollingTitleText` 的实现细节

入口只有一个 composable：

```kotlin
ScrollingTitleText(text, entryId, page, modifier, selected, style, color)
```

### 1. 为什么用 CompositionLocal

调用点在 6 个文件、8 处；每处都需要三个「全局」信息（主开关、当前条目 id、始终滚动的页面集合）。若走参数传递，`MediaEntryRow` / `BrowserPane` / `QueueSheet` 的签名都要加三个参数，再一路往上穿过五个 Screen。用 `LocalTitleScrollState` 一次性注入，`MediaEntryRow` 只多了一个必须由调用方交代的 `page`。

### 2. 为什么 `page` 是**必填**参数、不给默认值

`MediaEntryRow` 本身是媒体库 / 最近 / 收藏 / 播放列表**共用**的一行。它是哪一页的行，从行数据里推不出来（同一个 `MediaEntry` 在四个页面都会出现）。给默认值的结果是：新增调用点时忘传，静默退化成「只有当前那一条滚」，而这正是本版要修的那类问题。所以改成必填 —— 编译器替我们做这项检查。

### 3. 为什么 `enabled` 默认 `false`，而真正的默认值在 `TitleScrollRules.DEFAULT_ENABLED`

`TitleScrollState()` 的默认值只服务于 **Compose preview 与忘写 provider 的场景** —— 那种情况下让它别动，比在预览里狂滚好。真正的产品默认值只在 `MspApp` 里读：`display.scrollLongTitles ?: TitleScrollRules.DEFAULT_ENABLED`。两处默认值刻意不是同一个含义，KDoc 里写清了这一点。

### 4. 为什么用 `ValueAnimator.areAnimatorsEnabled()`

`basicMarquee` 自己不看系统的「移除动画」（animator duration scale = 0）。无障碍用户关掉动画后，滚动的标题会变成一块持续抖动的噪声。所以把系统设置显式并进判定：`shouldScroll(enabled, animationsEnabled, isCurrent, alwaysScroll, text)` 五个条件缺一不可。

### 5. `alwaysScroll` 与 `basicMarquee` 的自检如何配合

`basicMarquee` 自身**不看放不放得下就排版**（`measure` 给子项 `Constraints.Infinity` 的 maxWidth，自己画两份裁剪副本），但它内部会在 `containerWidth` 与 `contentWidth` 比较后停止动画 —— KDoc 原话是 "has **no effect if the content fits**"，源码里对应 `if (contentWidth <= containerWidth) return@snapshotFlow null  // Don't animate if content fits.`。

⇒ 「勾了始终滚动，但名字很短」这一格不需要我们额外测量：**照常挂修饰符即可，短名字自己不会动**。实测确认：勾选「媒体库」后，长名 `[电影天堂www.dygod.net]中文片名 HD1080p 国语中字 修复版` 在滚，而同屏的 `100% 完成` / `aac` / `ac3` / `Alarm01` 一帧不动。

若改成「自己量宽度决定挂不挂」，就要在 `SubcomposeLayout` 或 `onTextLayout` 里复制一遍 Compose 的测量，还得处理字体缩放与 CJK/拉丁混排 —— 收益为零。

### 6. 为什么必须**条件性**加 `basicMarquee`，而不能总是挂着

同上：`BasicMarqueeModifier.measure` 无论放不放得下都按 marquee 逻辑排版（文本被认为没有宽度上限）。如果无条件挂上、再靠 `overflow = Ellipsis` 去兜，两者会打架 —— ellipsis 永远不会发生。所以：

```kotlin
modifier = if (scrolling) modifier.basicMarquee(...) else modifier
overflow = if (scrolling) TextOverflow.Clip else TextOverflow.Ellipsis
```

注意这与第 5 点不矛盾：**「是否挂 marquee」由纯规则决定**（开关 / 系统动画 / 是否当前 / 是否整页滚），**「挂了之后动不动」由组件自己按实际宽度决定**。

### 7. 滚动时 `softWrap = false` / `maxLines = 1` / `TextOverflow.Clip` 三者必须一起换

marquee 的位移是「单行内容整体平移」。若还允许折行，被平移的是一段折好的多行文本，第二行会跑到第一行的位置下面 —— 必须钉成单行。而单行 + `Ellipsis` 会让 marquee 量到的是「已经加了省略号的字符串」，所以滚动期间用 `Clip`。三者是一组，不能只改其中两个。

### 8. 纯函数为什么单独抽出来

`feature/library` / `feature/player` / `core/ui` 都**没有** `compose-ui-test` 依赖 ⇒ 这些模块里的 Compose 行为在 JVM 上测不了。能测的只有不依赖 Android 的部分：`isCurrent` / `alwaysScrolls` / `shouldScroll` / `DEFAULT_ENABLED` / 两个节奏常量。`TitleScrollRules` 就是为此存在的，与仓库里 `LyricsScrollRules` / `ReorderDragState` 同一套路。

## 三、DataStore：两个键、`Boolean?` 与 `Set<String>?`

`DisplaySettings`：

```kotlin
data class DisplaySettings(
    val scrollLongTitles: Boolean? = null,
    val alwaysScrollPages: Set<String>? = null,
)
```

- `null` = **没设置过**（全新安装 / 从没动过那个开关）
- `true` / `false` = 明确打开 / 明确关掉
- `alwaysScrollPages` 同理：`null` = 从没动过；`emptySet()` = 用户明确一个都不勾

`Preferences.toDisplaySettings()` 对它**一个字都不加 `?:`**：

```kotlin
alwaysScrollPages = this[Keys.ALWAYS_SCROLL_PAGES]?.toSet()
```

如果写成 `?: emptySet()`，「没设置过」和「明确一个都不勾」会被合并 —— 而这两件事在将来改默认值时含义相反。默认值只在 UI 层出现一次。

键名 `display.scroll_long_titles` / `display.always_scroll_pages` 是**写入用户设备的契约**：改名等于把这些设置对所有人重置（`internal object Keys` 上的 KDoc 写了这条警告）。`DisplaySettingsTest` 用字面量断言把两个键名都钉住了。

**写入按单项做**，不整集合覆盖：

```kotlin
suspend fun setAlwaysScrollPage(pageId: String, enabled: Boolean) = edit { prefs ->
    val current = prefs[Keys.ALWAYS_SCROLL_PAGES].orEmpty()
    prefs[Keys.ALWAYS_SCROLL_PAGES] = if (enabled) current + pageId else current - pageId
}
```

理由：整集合覆盖需要调用方先持有一份最新快照，而设置页的开关是**连点**场景（用户会连着勾三四个页面），快照一过期就会把前一勾抹掉。读改写放在同一次 `edit` 里由 DataStore 串行化，天然免疫。

## 四、设置页的结构：为什么必须开子页

`AppearanceSettingsScreen` 原本只有「主题基底 / 强调色 / 取色来源 / 列表显示」四组。加上「长文件名滚动」的总开关 + 7 个页面开关 = 8 个开关行，会把「主题基底 / 强调色」这两组挤到首屏以外 —— 而它们是这个页面**最常被点的两项**。

所以拆成两个目的地：

- `settings/appearance` —— 外观页，保留原四组 + 一个 **`SettingActionRow`**（不是 `SettingsSwitchRow`）：图标 `Icons.Outlined.SwapHoriz`，标题「长文件名滚动」，副标题显示当前状态摘要，点它进子页。
- `settings/appearance/scrolling` —— 子页 `TitleScrollSettingsScreen`：总开关 + 「始终滚动的页面」分组 + 7 个 switch + 一条 `InfoNote`。

用的是**真目的地 + `popBackStack`**，不是「同一个页面里 if (showX) 切换内容」—— 后者在子页里按返回键会直接退出设置，而不是回到外观页。

### 副标题摘要（`SettingsSummaries.scrollTitles`）

```kotlin
if (!enabled)         → 已关闭
else if (pages == 0)  → 只有当前播放或选中的那一条滚动
else                  → %1$d 个页面始终滚动
```

它必须回答「现在到底是什么状态」，否则用户从子页出来就再也看不到自己改了什么。这也是外观页那行**用 `SettingActionRow` 而不是 `SettingsSwitchRow`** 的原因：一个既能点开又有状态的开关，会让人以为点一下就能切换。

### 置灰但保留勾痕

总开关关闭时，7 个页面行 `enabled = enabled`（不可点、视觉置灰），但 `checked` 仍按真实数据渲染。这是刻意复刻外观页已有的处理（「系统取色被封面取色盖住」那一行也是这个做法）：

- 直接 `checked = false` 会让用户以为自己的选择被清空了；
- 直接可点会让「总开关关着却还能勾」这种状态出现，勾了也不生效，更难理解。

同时每行副标题在总开关关闭时统一换成「总开关已关闭，这一页也不会滚」—— **置灰却不说话的开关，用户只会以为它坏了**。

## 六、测试怎么盖住

`TitleScrollRulesTest`（13 例）：

1. 默认主开关是开着的
2. 只有当前那一条算当前
3. 勾上的算当前（即使它不是正在播的那条）
4. 没有 id 的行不滚
5. 未勾选的页：只有当前那一条滚
6. 勾选的页：当前那一条滚
7. 勾选的页：**不是**当前那一条也滚 ← 本版的核心新行为
8. 未勾选的页：不是当前那一条不滚
9. `page = null`（不在 7 页之内的行）永不整页滚
10. 主开关关着时，勾了页也不滚（优先级）
11. 系统「移除动画」时不滚（勾了页也一样）
12. 空标题不滚
13. 节奏是两个正数，且 `INITIAL_DELAY_MILLIS < REPEAT_DELAY_MILLIS`
14. `TitleScrollPage.fromId` / `known` 的容错：未知 id 被丢弃、重复 id 去重、`null` 得空集、**并保持枚举声明顺序**（子页渲染顺序依赖它）

`DisplaySettingsTest`（7 例）：

1. 全新安装时主开关是「没设置过」，不是「关着」
2. 全新安装时逐页集合是「没设置过」，不是「空集」
3. 持久化键名是写入用户设备的契约（断言字面量 `display.scroll_long_titles` / `display.always_scroll_pages`）
4. 关掉和没设置过必须是两个不同的值
5. `setAlwaysScrollPage(id, true)` 只加一项、不动其他项
6. `setAlwaysScrollPage(id, false)` 只减一项，减到空仍是**空集**而不是 `null`
7. 别的分组的键不会漏进列表显示

未覆盖的部分（JVM 上测不了，只能实机）：marquee 的实际位移与自检、`CompositionLocal` 的注入、两个设置页与 `DataStore` 的接线、置灰状态的可点性。第九节是用实机逐条盖住的。

## 七、被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 全局「所有行都滚」一个开关 | 一屏七八行同时动，既看不出哪条在播也一条都读不进；用户真正的需求是「某几页要扫」 |
| 「始终滚动」放在外观页面上（不拆子页） | 8 个开关把「主题基底 / 强调色」挤出首屏 |
| 「始终滚动」用 `DropdownMenu` / 多选对话框 | 7 项需要**各自独立的勾选态**；`DropdownMenu` 关掉就看不到哪些已勾，对话框多一次跳转 |
| 逐页设置用 `Set<String>` 存在 UI 层再整份写入 | 连点场景下快照过期会抹掉前一勾 |
| `alwaysScrollPages` 缺省存 `emptySet()` | 「没设置过」与「明确一个都不勾」被合并，将来改默认值时含义相反 |
| 用页面的路由字符串当 `TitleScrollPage.id` | `settings/appearance/scrolling` 这类路由会随导航重构改名，而这个 id 落在用户设备的 DataStore 里 |
| 自己量宽度决定挂不挂 `basicMarquee` | `basicMarquee` 已经做了自检（`contentWidth <= containerWidth` 就停）；自己量等于重写一遍测量，还要处理字体缩放与混排 |
| 网格卡片 `MediaEntryTile` 也滚 | 卡片标题本就给两行、横向也够；滚动会破坏「一眼扫一片」的用途 |
| 播放页标题也滚 | 那里的标题本来就完整显示（放不下就折行），没有「看不全」问题 |
| `singleLine = true` + 自己 `animateScroll` 猜宽度 | 猜宽度必然在字体缩放、CJK/拉丁混排、字重变化上翻车 |
| 所有行无条件挂 `basicMarquee` | 见第二节第 6 点：与 ellipsis 冲突 |
| 用 `remember { }` 存当前条目 id | 组合作用域会在滚动/重组中丢失，且每个调用点都要各自同步一份 |
| `LaunchedEffect` + `Animatable` 自己实现 | 需要额外处理「放不放得下」的测量、双份绘制、指针输入期间的暂停；等于重写一个 `basicMarquee` |

## 八、已知限制（工程视角）

- 依赖 `basicMarquee`（foundation 1.11.4）的两条实现细节：`measure` 传 `Constraints.Infinity`、内部画两份裁剪副本、`contentWidth <= containerWidth` 时停动画。升级 Compose 时需要复核这三处。
- `ValueAnimator.areAnimatorsEnabled()` 为 `false` 时整条路径退化为省略号，无法在 JVM 单测里覆盖（平台 API）。
- `selected` 的语义是「多选里被勾上」；勾选多行时被勾上的行都会滚。这是当前取舍，不是遗漏。
- `BrowserPane` 的 `entryId` 用的是 `entry.mediaId`（非空、由 `mediaIdOf(ref)` 计算得出），与 `MediaEntry.id` 共用同一个 id 空间；这一点若将来改动 id 生成规则需要同步核对。
- `NetworkUrlRow` 的 `entryId = null` ⇒ 这一页**只能**通过「始终滚动」整页打开来滚；它的标题来自 `RemoteUrlRules.titleOf(url)`，通常不长。
- 子页的 7 行顺序直接取自 `TitleScrollPage.entries`，改枚举顺序会改 UI 顺序（`known()` 的单测断言了这一点）。
