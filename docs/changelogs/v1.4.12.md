# v1.4.12

发布日期：2026-10-31

## 变更

### 新增：媒体库文件夹偏好

「媒体库」从此可以只显示指定文件夹里的内容。入口在 **设置 → 媒体库文件夹**。

- **勾选的文件夹决定媒体库的内容。** 一个都没勾（含从没设置过）= 媒体库一条都不显示，
  并给出提示「还没有选择任何文件夹」+ 一个「去选择文件夹」的按钮直达本页。
- **勾选包含子文件夹。** 勾上 `Movies` 就显示 `Movies/AsrTest`、`Movies/BugA` 里的内容，
  不需要逐个勾子文件夹。
- **文件夹树可以折叠。** 还有子文件夹的行尾多了一个箭头，点一下把这层收起来，再点一下展开。
  首屏只展开顶层，所以进来先看到的是几个顶层文件夹，而不是一屏几十行；**已勾选的文件夹
  那条链会自动展开**，免得用户以为自己的勾丢了。
- **折叠只管「画几行」。** 收起来的子树里该进库的东西照样进库（收起来 ≠ 不选），
  勾选、设置页摘要、「全不选」都不受折叠影响；折叠状态也**不落盘**，离开这一页就回到默认。
- **顶栏「全不选」** 一键清空，效果等同于「都不显示」。
- **改选不重扫。** 改完立刻生效，媒体库只是换一次过滤条件（日志里是
  `媒体库文件夹偏好变化，重新过滤（不重扫）`）；MediaStore / SAF 都不会重新遍历。
- 设置页那一行的摘要分四种：`已选 N 个文件夹` / `一个文件夹都没勾` / `无法读取` /
  `系统不支持`（最后一种见「设计取舍」第 4 条）。

### 不变

- **「浏览」页完全不受影响**（实机核对：过滤生效时「内部存储」仍是 516 项、11 个目录）。
  这项偏好只决定「媒体库」这一页的内容。
- 播放、字幕、歌词、最近、播放列表的行为与之前一致。
- 没有新增权限，没有新增后台行为，没有改动文件格式或数据库。

## 设计取舍（否定过的方案）

**1. 偏好状态必须是三态，不能用两种。**

`LibraryFolderSettings.folders` 是 `Set<String>?`：

| 值 | 含义 | 媒体库 |
| --- | --- | --- |
| `null` | 从没设置过 | 空 + 提示 |
| `emptySet()` | 用户把勾全取消了 | 空 + 提示 |
| `unknown = true` | DataStore 读失败（IO 异常） | **不过滤** |

前两种对用户是同一件事，但在存储层必须能区分「没写过」和「写成空」——否则
「默认都不显示」这件事就得靠猜。第三种是**故意 fail open**：读不出偏好时宁可全显示，
也不要因为一次 IO 抖动把整个媒体库清空。同理，仓库里的 `folderPrefs` 初值是
`unknown = true` 而不是空集，否则启动瞬间会先闪一个空列表。

**2. 「合并」与「过滤」拆成两步（`publish()`）。**

`scan()` 结束后先存**未过滤**的 `merged`，再由 `publish()` 按当前偏好过滤后发布。
否定过的方案是「把 `LibraryFolderSettings` 传给扫描器，让它少扫一点」——那样改一个勾
就要重扫一遍 MediaStore（几十毫秒）或 SAF（几秒），而用户是在设置页里一行一行点的。

副产品是 **`scannedPaths` 必须是未过滤的那一份**。设置页要拿它建「可选文件夹」树；
如果拿 `state` 里已经过滤过的条目建树，用户勾掉一个文件夹，那一行就会从树上消失，
再也勾不回来（「用结果去描述选项」的经典死循环）。

**3. 已选集保持最小（`minimize`），否则有些操作无法表达。**

集合里同时存 `Music` 和 `Music/Live` 是冗余的：`Music` 已经覆盖了它。冗余的后果不是浪费
几个字节，而是**「取消勾选 `Music/Live`」变成不可能**——把 `Music/Live` 删掉，`Music`
还在，照样显示。所以 `toggle` 在「目标已被祖先覆盖」这一支上必须先**展开祖先**：
删掉 `owner`，再把 `owner` 底下除了 `target` 那一支以外的子文件夹显式加回来。
这里必须传完整的文件夹清单（`allFolders`），否则展开无从下手。

**4. 拿不到相对路径时：加 SDK 闸门（fail open），而不是严格排除。**

两个真实来源拿不到 `relativePath`：`MediaStore.RELATIVE_PATH` 是 API 29 才有的列
（本应用 minSdk 26），SAF 侧遇到非 `ExternalStorageProvider` 的 provider（各种云盘）也拿不到。
最初的写法是「拿不到就严格排除」，代价是 **Android 8.0/8.1（API 26–28）上只要用户勾了任何
文件夹，媒体库就永远是空的，而且没有任何出路**——这些版本上「一条都不勾」本身就等于
「都别显示」，用户被夹在两败俱伤的两个选择之间，界面上也没有一句解释。

三个候选：**A** 只在文档里写「这些设备请保持一个都不勾」（错：不勾才显示、勾了就是空，
逻辑正好反着，用户越看越糊涂）；**B** 用 SDK 闸门：`SDK_INT < 29` 时**整体关掉过滤、
照常显示全部内容**，并在偏好页写明「系统不支持」；**C** 把 minSdk 提到 29。
选 **B**：C 会为一功能丢掉一整段存量设备，A 是让用户去背一条自相矛盾的规则。
B 的立场是「设备做不到就说做不到，不把坏结果推给用户」；代价只是这类设备上勾选框里
点了不生效，所以那一页必须把原因写在提示区（`LibraryFolderSummaries` 的分支里
`!supported` 排第一位，就是为了不让用户误以为是权限问题而去查设置）。

闸门只落在一个字段上：`filtering = !unknown && supported`。仓库、`LibraryViewModel`、
界面全都只问 `filtering`，所以闸门开关不需要改第二处。
`internal fun folderFilterSupported(sdkInt: Int)` 把 `SDK_INT` 变成参数
（本项目单测里它是 0），边界 28 / 29 有专门用例。

另一类拿不到子目录的来源（云盘/网盘）仍然**严格排除**：它们不属于用户勾的任何文件夹，
没法归位；用户真要看就回「浏览」。这一点与闸门无关，列在发布说明的「已知限制」里。

**5. 勾父级会连带把后代行显示成勾选 —— 这是有意的。**

偏好页每一行的勾选状态是 `LibraryFolderRules.isCovered(selected, node.path)`，也就是
「**按当前偏好，这个文件夹里的内容会不会被显示**」，而不是「这个路径字符串在不在集合里」。
于是勾上 `Movies` 之后，`Movies/AsrTest`、`Movies/BugA` 这些子目录行也会显示成勾选。
它们是同一个问题的同一个答案；如果让子行显示成未勾选，界面就在说谎（点了它反而会触发
上面第 3 条那套「展开祖先」的逻辑）。DataStore 里始终只有一条 `Movies`。

**6. 界面判定的顺序：内容优先。**

`LibraryPane.Ready` 的分支是

```kotlin
lib.entries.isEmpty() && noFoldersSelected -> LibraryPane.NoFoldersSelected
lib.entries.isEmpty()                        -> LibraryPane.NoMedia
filteredOut                                  -> LibraryPane.FilteredOut
else                                         -> LibraryPane.Content
```

`noFoldersSelected` 来自另一个 Flow（偏好），重新过滤是**异步**的，中间存在「偏好已改、
条目还没换」的一帧。若把 `noFoldersSelected` 放在最前面，这一帧会把明明有内容的媒体库
判成「没勾文件夹」→ 界面上闪一下空态。所以它必须挂在 `entries.isEmpty()` 之后：
**有内容时内容永远赢。**

**7. 折叠状态不落盘，而且只影响「画几行」。**

最初这一页是**平铺整棵树 + 纯缩进**（没有折叠）。实测目录一多就不方便：所有层级的行都摊在
一个可滚动列表里，找顶层的另一个文件夹要滑过一长串子目录。加折叠有两条路：**A** 把折叠
状态一起存进 DataStore；**B** 只当会话内的界面状态。选 **B**：

- 折叠不是「用户的决定」，是「我这一眼想先看什么」。存下来之后，用户下次进来会看到一棵
  上次随手收起的树，还得先猜自己收过什么——比平铺更难解释。
- 落盘就要额外处理「存着的那条链已经不存在了」（文件夹被删、被移走）的清理，而它不产生
  任何行为差异。

与之配套的三条约束：

- **折叠集合里出现某个路径，只遮住它的子孙，不遮它自己**（`visibleFolderRows` 用
  `ancestorsOf(row.path).none { it in collapsed }`）。于是根行永远可见——`ancestorsOf("")`
  是空列表，任何折叠集合都遮不住它；否则把根收起来就再也没有展开它的入口。
- **默认「只展开根那一层」，但已勾选的链自动展开**（`defaultCollapsedPaths`）。`collapsed`
  是 `MutableStateFlow<Set<String>?>`，`null` 意为「用户还没动过手」：此时每次发射都按当前
  勾选重算一份（所以勾选一变，链就跟着展开）；用户一点箭头就变成显式集合，此后不再重算。
- **`rows` 始终是整棵树，折叠只裁剪 `visibleRows`。** `toggle` 必须拿到完整的路径清单才能做
  「展开祖先」那套操作（见第 3 条），拿可见行去算会把被收起的分支当成不存在。

另外，判断「这一行要不要带箭头」用的是新写的 `hasChildFolder`，而不是复用 `covers`：
`covers("")` 被定义成「只覆盖自己」（根不代表整棵树），直接拿它判子目录，根那一行就永远
没有箭头，而根恰恰是最需要能收起来的那一行。

> 界面树的坑：本应用的 Compose 树里 `class="android.widget.CheckBox"` 是**装饰用的**
> `Checkbox` 视觉节点，`checkable="false"` 且 `checked` 恒为 false；真正带勾选状态的是
> 合并后的**行节点**（`checkable="true"`）。所以上面所有勾选结论都是按 `checkable="true"`
> 取 `checked` 得到的——按控件类名去筛会得出一串假的「全未勾选」。
