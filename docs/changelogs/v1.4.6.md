## 一、这一版做了什么

`todo/bugs.txt` 的第一条：「音视频文件识别错误，如：会将 docx 文件识别为音频。」

只有一处改动，但它是**唯一一处会静默出错、且错误方向最难猜**的类型：文件类型判定。

| 问题 | 表面症状 | 真正坏在哪 |
| --- | --- | --- |
| Office 文档被当成音频 | 「浏览」里点 `报告.docx` 进了播放页，显示成一首歌（标题 + 空进度条），几秒后「无法播放」；日志里没有任何一条与「识别错了」有关的输出 | `kindOf()` 只问「后缀在不在音频表 / 视频表」，两张表都没有 ⇒ `MediaKind.UNKNOWN`；而 `UNKNOWN` 的语义是「交给内核去试」，于是判定为可播；播放页只有音频 / 视频两套版面，判据是 `kind == VIDEO`，UNKNOWN 落进**音频**版面 |

之所以说它「最难猜」：三件事（后缀、MIME、内核）只坏在**第一件和第二件之间的顺序**上，
而症状出现在第三件。修法集中在 `SafScanRules.NON_MEDIA_EXTENSIONS` 这一张表上——
把「本来就能一次说清的非媒体后缀」补齐，`UNKNOWN` 的含义就收窄回「我们真的不知道」。

## 二、为什么 UNKNOWN 会变成一首歌

`SafScanRules.kindOf()` 的四步判定：

```text
1. 后缀在 NON_MEDIA_EXTENSIONS 里吗？   → 是 ⇒ null（明确不是媒体）   ← 本版补的就是这一步
2. MIME 是 audio/* 或 video/* 吗？      → 是 ⇒ AUDIO / VIDEO
3. 后缀在 AUDIO_EXTENSIONS / VIDEO_EXTENSIONS 里吗？ → 是 ⇒ AUDIO / VIDEO
4. 都不是                               → UNKNOWN（让内核去试）
```

`.docx` 不在第 1 步的表里（v1.4.5 只有字幕 / 图片 / 文档文本类 / 压缩包 / 部分其他）、
不在第 3 步的两张表里，落到第 4 步 ⇒ `UNKNOWN`。

第 2 步本来可以兜住——但**兜不住**：

- 有些系统 / 部分国产 ROM 给 `.docx` 报 `audio/mpeg`，照着 MIME 走反而更糟；
- 线上真正拿到的是 `application/vnd.openxmlformats-officedocument.wordprocessingml.document`，
  不是 `audio/*`，第 2 步不命中；
- 于是结论稳定地是 `UNKNOWN`。

`UNKNOWN` 的语义是**刻意的**：「宁可漏不可错」。`VID_20240101`、`REC001` 这类没有后缀的视频
只能靠它播出来，所以它必须可点。真正的问题不在这个枚举值，而在
**「垃圾桶」里装进了本来可以一次说清的东西**。

消费侧的三个出口都跟着这个值走（都复核过，本版未改）：

| 位置 | 判据 | `UNKNOWN` 时 |
| --- | --- | --- |
| `BrowserEntry.playable` | `isFile && kind != null` | `true` ⇒ 可点、可多选 |
| `PlayerScreen` 版面 | `entry?.kind == MediaKind.VIDEO` | `false` ⇒ **音频版面** |
| `ExternalMediaRules.refOf`（分享） | `kind != null` ⇒ 收进 ref；否则 SHARED 源丢、REMOTE 源记 `UNKNOWN` | SHARED 丢掉、REMOTE 收下 |

第三个出口顺带解释了「为什么只补一张表就够了」：`kindOf` 是**一个**判据，改它等于同时改
浏览页、多选、队列、最近、分享五处的行为，不需要每处各加一条 if。

## 三、补表时遇到的两个「不能加」

这张表不只为浏览页服务：`RemoteUrlRules.looksLikeHost()` 借它判断「这串字像不像主机名」——
`xxx.com` 这种字符串的「后缀」是 `com`，如果 `kindOf("xxx.com", null) != UNKNOWN` 就会把它
判成「不是网址」。所以**往表里加一个后缀，等于收紧一次主机名判定**。

| 想加的 | 实际情况 | 决定 |
| --- | --- | --- |
| `psd` / `ai` / `sketch` / `fig` | `.ai` 是**安圭拉的国家顶级域名**，与 `xxx.ai` 撞车 | 不加，并在 KDoc 与用户文档里写明原因 |
| `et`（WPS 表格） | `.et` 是**埃塞俄比亚的国家顶级域名** | 不加 |
| `.docm` / `.dot` / `.xlsm` / `.xlsb` / `.pptm` / `.pps` / `.pot` 等 Office 变体 | 都是真后缀，不与任何 TLD 冲突 | 加 |

顺带把三张表从 `private` 改成 `internal`，让测试能对它们做**结构守卫**（见第五节）。

## 五、测试怎么盖住

| 测试 | 钉住的东西 |
| --- | --- |
| `办公文档和电子书不会被当成音频` | 25 个文件名（含 `.wps` `.dps` `.ofd` `.pages` `.numbers` `.key` `.vsdx` `.pub` `.xps` `.chm`）都判 `null`。**这是本版的核心回归**：v1.4.5 上它会全红（判 `UNKNOWN`） |
| `办公文档的后缀优先于说谎的 MIME` | `kindOf("报告.docx", "audio/mpeg")`、`(…, "video/mp4")`、`(…, docx 的官方 MIME)` 全为 `null`；`kindOf("表格.xlsx", "application/vnd.ms-excel")` 也为 `null` ⇒ 钉住「第 1 步在 MIME 之前」 |
| `三张后缀表两两不相交且都是小写无点的裸后缀` | 结构守卫：任何一个后缀同时出现在两张表里、或写成 `.docx` 带点 / 大写，都会红。**这是唯一能拦住「手滑加错表」的东西** |

### 没被单测盖住的部分，以及为什么

- **`DocumentFile` / `DocumentsContract` 在 JVM 单测里连构造都做不到**
  （`unitTests.isReturnDefaultValues = true` 时它们返回 null 或直接抛）。
  所以「扫描器真的按这张表判定了」这件事在单测里不可见——能测的只有 `kindOf` 这个纯函数。
  扫描器那一侧的保障是**它只调 `kindOf`，自己不写第二套判断**（已复核
  `SafDocumentSource`、`SafTreeWalker`、`FileSystemSource`、`RecentMediaResolver`、
  `ExternalMediaRules` 五处都只调它）。
- **「点不动」是 Compose 的 `enabled` / `clickable` 行为**，`:core:ui` 没有
  `compose-ui-test` 依赖，测不到；只能实机点（见第九节）。
- **`.docx` 被系统报成 `audio/mpeg`** 这件事本身依赖 ROM，单测里是靠手工传参模拟的，
  不能证明「线上每台机器都这样」——但结论与 MIME 无关了，所以这不影响正确性。

## 六、被否决的方案

| 方案 | 为什么否决 |
| --- | --- |
| **让 `UNKNOWN` 不可播** | 一行就能修好 docx，但会误伤所有**没有后缀**的真媒体：`VID_20240101`、`REC001`、相机导出的临时名。这是「宁可漏不可错」的反面，也是这次唯一不能碰的底线 |
| **只看 MIME 判定** | 正是现状的一半。`.docx` 常被报 `audio/mpeg`，照着 MIME 走只会更确定地错 |
| **读文件头（magic bytes）** | 每次判定要开一次 IO，而 `kindOf` 在列目录时按行调用（5000 条上限）。且媒体库条目根本没有可读的字节流 |
| **在播放页兜底：「解不出来就退回列表」** | 只治症状：用户还是得先点进去、等几秒、看一条错误；而且队列里会留下一个必然失败的条目 |
| **把 `psd` / `ai` / `sketch` / `fig` / `et` 一起加进去** | 见第三节：`.ai`、`.et` 是真 TLD，加了会让 `xxx.ai` 这种网址被当成「不是网络地址」 |
| **给文档类文件单独一个「文档」图标并允许点开（预览）** | 这是新功能，不是修 bug；本版只做「不要再假装它能播」 |

## 七、已知限制（工程视角）

- **后缀表是白名单式的枚举**，冷门办公格式（某些国产排版软件的专有后缀）仍会落到 `UNKNOWN`。
  代价已被接受：症状是「点开 → 音频版面 → 无法播放」，不是崩溃。
- **判定只看名字与 MIME，不读文件头**：把 `.docx` 改名成 `.mp3` 仍会被当成音频。
- **`kindOf` 是共享判据**：改这张表会同时影响浏览页、多选、队列、最近、分享、以及
  `RemoteUrlRules.looksLikeHost` 的主机名判定。改之前必须先跑结构守卫测试。
- **已经存在于播放列表里的旧条目不会被清理**：`PlaylistItem` 是序列化下来的快照，
  本版只改「现在还能不能加」。
- **`.et`（WPS 表格）仍未收录**，因为与埃塞俄比亚 ccTLD 冲突；WPS 的**表格**文件仍会被当成音频。
  这是明确接受的取舍，已写进用户文档的「已知限制」。
