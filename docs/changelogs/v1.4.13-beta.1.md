## 一、为什么慢

`core:data` 的 SAF 扫描原本走 `androidx.documentfile`。`TreeDocumentFile` 的
`name` / `type` / `isDirectory` / `length` / `lastModified` **各自发一次
`ContentResolver.query`**，而 `listFiles()` 虽然拿到了 `documentId / displayName / mimeType`
三列，却又把它丢进 `DocumentFile` 子类里逐个属性重新问一遍。

⇒ 授权树里**每个文档 ≈5 次跨进程调用**，且这个成本发生在「是不是点目录、要不要跳过」的
判断**之前**——`.thumbnails`、`.trash`、图片缓存这些永远不会进媒体库的东西也要全额付费。

授权整个卷（`primary:`）时典型 2 万份文档 ⇒ **≈10 万次 IPC**，而界面真正只需要几百首歌。

## 二、改了什么

1. **`SafTreeScanner` 改为单 cursor 枚举。** `SafTreeScanner.kt` 不再依赖
   `androidx.documentfile`，新增 `DocumentRowNode`：构造时吃进一行已经查好的
   `documentId / displayName / mimeType / size / lastModified`，
   `children()` 只发一次 `buildChildDocumentsUriUsingTree(...)` 的 `query`。
   IPC 复杂度从 `O(文件数 × 5)` 降到 `O(目录数)`。
   - 投影固定 5 列，列索引缓存；`idIndex < 0` 直接日志 + 返回空，不抛。
   - `query` 失败（provider 崩、权限被撤）⇒ `MspLog.w` + `emptyList()`，让上层当「这一层为空」处理，
     不中断整次扫描。
   - 跳过空 `documentId` 的行。
2. **`SafScanRules` 增加 `DIRECTORY_MIME` / `isDirectoryMime`。**
   目录判定原本靠 `DocumentFile.isDirectory`，现在必须靠 MIME。**不能写
   `DocumentsContract.Document.MIME_TYPE_DIR`**：它是静态字段，`unitTests.isReturnDefaultValues = true`
   时在 JVM 单测里是 `null`，判据会静默失效（目录被当成文件 ⇒ 整棵子树丢失）。
   所以硬编码字面量 `vnd.android.document/directory`，并加两条规则用例。
3. **新增 `SafScanPlan`（纯函数）。** 「这次 SAF 那半边要做什么」的唯一判据：

   ```kotlin
   fun of(treeUris: List<String>?, force: Boolean, hasCache: Boolean): SafScanPlan = when {
       treeUris != null && treeUris.isEmpty() -> NoTrees
       !force && hasCache -> Cached
       treeUris != null -> WalkTrees
       else -> ReuseCache
   }
   ```

   四个分支各自对应一条**真实**状态，仓库的「要不要先发中间态」与 `scanSaf` 都从它派生，
   保证两处永不冲突。`NoTrees` 必须排最前：**「确定没有授权目录」比「反正有缓存」更确定**。
   把 `Cached` 放前面会让 `NoTrees` 不可达——撤销最后一棵授权树后，`removeTree` 的强制重扫是对的，
   但任何**非强制**刷新（ContentObserver 触发的自动重建）都会命中 `Cached`，
   于是已经撤权的目录里的旧条目继续显示、点开即报错。这不是测试写错，是真实功能风险。
4. **渐进发布。** `MediaLibraryRepository.scan` 里，MediaStore 扫完先把
   `mediaStore.entries + safCache` 合并成 `Ready` 发出去，SAF 扫完再发一次完整结果。
   两次都是 `Ready`，所以不会闪一下 `Loading`。
5. **取消守卫。** 计时/发布路径上加 `isActive` 检查：被取消但仍在阻塞中的旧扫描
   不允许再覆盖新结果（`CoroutineScope` 取消是协作式的，`query` 不会立刻返回）。
6. **分段耗时日志。** 一条 `扫描耗时：MediaStore Xms/N 条，SAF Yms/M 条（目录树 K 棵，<plan>）`，
   后面一条 `扫描完成：合并 Z 条，总耗时 Wms`。真机取证就靠这两条。
7. **彻底移除 `androidx.documentfile` 依赖**（`core/data` 与 `app` 两侧），
   并在 `core/data/build.gradle.kts` 留注释说明为什么不许再用回去。
   `gradle/libs.versions.toml` 里的条目暂时保留，代码里已无引用。
8. **顺手修 bug**：撤销最后一个授权目录后旧条目残留（见上面 `NoTrees` 的说明）。

## 三、否定过 / 推迟的方案

- **B｜持久化快照（DataStore 或 Room 存一份上次的扫描结果，启动先出旧列表再后台校正）。**
  收益最大（冷启动直接出），但引入「缓存与真实文件不一致」的一整类问题：
  删了文件还在、挪了目录路径对不上、权限变了不知道。**这一版先只做风险最低的改动**，看效果再说。
- **C｜Paging / 分页只扫可见范围。** 与现有「拿到全量再过滤 + 合并」的架构冲突面太大，
  等于重写媒体库数据层。
- **D｜把 `buildLibraryUiState` 经 `flowOn` 搬离 Main。** 是真实热点（全量条目在 Main 上重排），
  但和本次 SAF 改动无关，混在一起会让「耗时变化到底是谁的功劳」不可归因，推迟。
  **这是下一版优先级最高的一项。**
- **E｜合并 observer 信号（MediaStore 与 SAF 各自触发重建，启动时可能连抢几次）。**
  同样等真机耗时数据出来再判断值不值。
- **不改 `MAX_ENTRIES = 20_000` / `MAX_DEPTH = 8`。** 它们只影响截断，不影响这次的成本结构。

- 这套改动**无法**用单测覆盖的部分：真实 IPC 次数、真实耗时、`ContentResolver` 行为
  （`isReturnDefaultValues = true` 下全是 null）。所以 `DocumentRowNode` 只是把代价挪到
  `SafTreeScanner` 一处，`SafTreeWalker` 仍然对着 `DocumentNode` 接缝跑纯 DFS。

## 六、真机核查

alpha 阶段已由用户确认：

- **速度有明显提升**（这是从 alpha 转成公开 beta 的依据）。

转 beta 前仍需补的项（本环境 ADB 不可用，日志需用户提供）：

1. `adb logcat -d | Select-String '扫描耗时'` ⇒ 记下 `MediaStore Xms/N 条` / `SAF Yms/M 条`
   与 `WalkTrees` 分支，与 1.4.12 的观感对比。
2. 授权一个**大**目录（含 `.thumbnails` 之类）⇒ 确认媒体库先出内容、随后补齐，不闪 `Loading`。
3. 撤销最后一棵授权树 ⇒ 确认列表里那个目录的条目**立刻消失**（这就是本版顺手修的 bug）。
4. 扫描途中切走再回来 ⇒ 确认不会出现旧结果覆盖新结果。
