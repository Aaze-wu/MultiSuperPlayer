## 一、这一版做了什么

需求④：**可开关的后台保活**。设置入口页新增第 7 行「后台保活」，进去是一页两段：

1. **电池优化**：一个开关，拨开就调用系统的
   `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。系统会弹
   「**要允许应用一直在后台运行吗？**」，允许之后本应用进入 Doze 白名单。
2. **厂商后台管理**：一个「去设置」按钮，按本机厂商跳到系统里那个管后台的页面
   （小米 / 华为 / 荣耀 / OPPO / vivo / 魅族 / 三星 / 一加，认不出时退到系统的「应用信息」页）。

顺带把新声明的权限登记进权限页的折叠区（`忽略电池优化`），清单覆盖测试保持双向一致。

为什么单独一页而不是塞进权限页：权限页列的是「**应用声明过什么**」（系统说了算、有 API 可查），
这一页处理的是「**厂商自己加的那层后台限制**」（连 API 都没有，只能按包名猜页面）。
合成一页会让用户以为「权限都给了就不会被杀」，而后台被杀的绝大多数情况恰恰是后者。

## 二、白名单只有「申请」，没有「退出」

Android 的白名单 API 是**单向**的：`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 只能让应用
**申请加入**，没有任何等价动作能把应用移出去。

所以这一页的开关是这样的：

| 用户动作 | 实际发生什么 |
| --- | --- |
| 拨开 | 真的发申请，弹系统框，允许即入白名单 |
| 拨回 | **不会**退出白名单，跳到系统的电池设置页让用户自己移出 |

文案照实说，不假装能关：

> 关掉这个开关不会立刻退出白名单——系统只允许应用申请加入，移出要你自己到系统的电池设置里操作。
> 拨回去会带你去那儿。

### 为什么不写「电池优化页」

原本这句写的是「带你去系统的**电池优化**页」。在 Android 17 / API 37 上实测，这个 Intent
落到的是 `com.android.settings.spa.SpaActivity`，页面标题是「**应用的电池使用情况**」，
里面是「所有应用 / 电话 / 个人安全 / 日历 …」这种新版列表，**不是**旧版那个「电池优化」页。

跳转类文案一旦点名具体页面，系统一改版面就变成假话。所以改成不点名（「系统的电池设置」）。

### 开关状态不存本地副本

状态每次都现读 `PowerManager.isIgnoringBatteryOptimizations(packageName)`，进页面
（`ON_RESUME`）重读一次。理由很实际：白名单**可以在应用外面被改**——用户完全可能自己去系统
设置里把我们移出去。存一份本地副本的结果是「界面说已加入、系统其实早就限制你了」，
而且这种不一致没有任何报错能暴露。

## 三、厂商那一层没有 API，只能挨个试页面

小米、华为、荣耀、OPPO、vivo 这些 ROM 都把「自启动 / 后台管理」塞在自己的设置应用里，
**没有公开的 Intent 契约**，只能按「包名 + 类名」去猜。做法：

1. `KeepAliveAccess.vendorIntents()` 返回**候选列表**——同一家厂商往往有好几个不同 ROM 版本
   的类名，全都列上；
2. 按顺序逐个 `startActivity`，用 `runCatching { … }.isSuccess` 判断成功即停；
3. 全部失败 → 退到系统的「应用信息」页（这个一定存在）。

**不用 `resolveActivity` 预判**：这些类在系统里经常是 `exported=false`、或者存在但受权限保护，
「能解析」不等于「能打开」。预判会给出一个乐观的假答案，然后 `startActivity` 抛异常——
用户看到的是「点了没反应」。

### 厂商识别是纯函数，顺序有守卫

`KeepAliveRules.vendorOf(manufacturer, brand)` 是**零 Android 依赖**的纯函数，所以能在 JVM 上
直接跑单测。两条容易写错、写错了却看不出错的规则各有专门测试钉住：

- **荣耀（`honor` / `hihonor`）必须先于华为判断**：不然走 `huawei` 分支，跳到华为那套页面（多半打不开），
  用户只会觉得「这功能不好使」，不会知道是识别错了。
- **一加（`oneplus`）必须先于 OPPO 判断**：同一个 `key` 前缀谁先匹配谁赢。

界面在认不出厂商时显示「本机不在已知的厂商名单里，会打开系统的「应用信息」页」，
说明退路是什么，而不是点下去才发现跳错地方。

## 四、真机验证结果

在 `emulator-5554`（Android 17 / API 37，zh-Hans-CN）上实测：

| 项 | 结果 |
| --- | --- |
| 设置入口页第 7 行 | `后台保活` / `未加入电池优化白名单，长时间后台可能被限制`，位置在「权限」与「关于」之间 ✅ |
| 拨开开关 | 系统框「要允许应用一直在后台运行吗？」+ 拒绝 / 允许 ✅ |

| 厂商分支 | 模拟器是 Google 系 ⇒ 走「认不出厂商」那条，显示应用信息页提示；点「去设置」落到系统页 ✅ |

## 五、已知限制

- **关闭开关不能停在应用内**（§二），这是系统 API 的限制，不是没做。
- **白名单只解决「电池优化」这一层**。厂商自建的那层（自启动管理、后台弹窗限制、锁屏清理）
  必须用户自己去点——「厂商后台管理」那段就是为它准备的入口，但我们只能把用户送到页面，
  没法替他改。
- **厂商候选类名会随 ROM 版本变化**。失败时的行为是退到应用信息页，不是一个不动的按钮。
- 模拟器是 Google 系，**厂商专属页面只有真机上才走得到**；这一版对它的验证止于「候选列表存在 +
  失败会退到应用信息页」。
