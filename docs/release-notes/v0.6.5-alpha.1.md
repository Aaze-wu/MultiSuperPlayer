## 一、这一版做了什么

v0.6.5 的主题是**云端语音识别（字幕生成）**：把音轨切块上传给服务商，让它来识别。

这是路线图上「音频识别（字幕生成）（本地 + 云端）」里的**云端那一半**，也是 v0.6「本机离线
ASR」的对称动作——那边把音频留在手机上算，这边把音频发出去算，两条路的产出是同一种东西：
一份落在私有目录、自动挂上并选中的 `.srt`。

### 1. 「识别方式」多了一条「云端识别」

设置 → 语音识别，最上面多一段**识别方式**：

| 识别方式 | 音频在哪 | 需要什么 | 默认 |
| --- | --- | --- | --- |
| 本机识别 | 留在手机上 | 先下模型（78.1 MB 起），慢 | ✅ |
| 云端识别 | **整段上传到你填的地址** | 服务地址 + 密钥，快 | |

默认仍然是**本机**。这不是随手定的：本机那条路的代价（下模型、慢）用户看得见也随时能反悔，
而云端那条路的代价是**整段音频离开这台设备，且不可逆**——要不要付这个代价，得用户自己选一次。

选了云端之后，页面变成四个字段：

| 字段 | 说明 |
| --- | --- |
| 服务商 | 预设四家：OpenAI / Groq / 硅基流动 / 自定义（中转站、自建兼容层） |
| 服务地址 | 换服务商会清掉这一栏（否则会把上一家的地址发给下一家）；下面是**实时算出来的最终请求地址** |
| 模型名 | 留空用预设的；占位符就是预设值 |
| 密钥 | 按服务商**分开存**（每家一把钥匙），系统密钥库加密后存本机 |

「服务地址」下面那一行 `将请求：https://…/v1/audio/transcriptions` 是这一版最实用的一处：
几乎所有的云端配置错都是**地址少写一段**（漏了 `/v1`），而这一行是唯一能在按下按钮之前
看出这件事的地方。地址填得不像地址时（不以 `http://` / `https://` 开头）标红并说明，
**顺手把播放页的按钮变灰**——同一个判定（`AsrSettings.cloudAddressLooksValid`）与
发请求前那道 `checkEndpointUsable()` 是同一个结论，所以不存在「按钮亮着、点了必错」。

四家预设各自的取舍直接写在选项说明里，不是让用户去试：

| 服务商 | 默认地址 | 默认模型 | 出时间轴 |
| --- | --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `whisper-1` | ✅ |
| Groq | `https://api.groq.com/openai/v1` | `whisper-large-v3-turbo` | ✅ |
| 硅基流动 | `https://api.siliconflow.com/v1` | `FunAudioLLM/SenseVoiceSmall` | ❌（选项上直接标「（不出时间轴）」） |
| 自定义 | 空，用户自己填 | 空，用户自己填 | 按支持处理 |

默认服务商是**硅基流动**：国内直连、密钥门槛最低。「默认」与「默认的识别方式」是两件事——
默认方式是本机，所以新装用户一开始根本看不到这一节。

### 2. 按固定 5 分钟切块上传，一块约 9.6 MB

整段音频不能一次发出去（服务商普遍有单次体积上限，两小时的片子也不该在内存里拼一遍），
所以先切成块、逐块上传、最后拼成一条完整时间轴。

- **按固定长度切（5 分钟），不按静音处切。** 按静音切（VAD）能得到更自然的句子边界，
  但代价是先在本机把整段音频解一遍——那正是「本机识别」要做的事，于是云端这条路
  一点时间都没省下，用户白等一遍。
- **为什么是 5 分钟**：16000 Hz × 2 字节 × 300 秒 = **9.6 MB**，刚好躲开 10 MB 这一档的常见
  请求上限。同一个端点上，一个超限的块会让**整次识别**失败（而不是「这块失败换下一块」），
  所以这个数字是按「不能撞线」选的，不是按「越少越好」选的。块再短则每块都要重付一次
  模型加载的固定开销，块数翻倍就是白等几秒。
- **切片是自己拼的 WAV**（16 kHz 单声道 16 bit，44 字节头）：不依赖设备有没有 AAC 编码器，
  也就少一个设备相关的失败点。代价是体积——有损编码能压到 1/10，但那是拿「省流量」
  换「多一个设备相关失败点」。
- **切片落在 `cacheDir/asr_cloud/`**，跑完就删；进程被杀留下的残片在下次开始时清掉
  （一块 9.6 MB，不清就是永久占着缓存目录）。
- **上传进度只在「这一块发完」时记一行日志**：按 512 KB 报进度会在 9.6 MB 上刷出 19 行，
  真正有用的那一行会被埋掉。

### 3. 时间轴：服务商给就按句，不给就整块一条

请求尽量要 `verbose_json`。两种回应都**不是错误**，而是这两家能力不一样：

- `{"segments":[{"start":0.0,"end":3.3,"text":" …"}]}` → 按句拆成多条字幕；
- `{"text":"…"}` → 整段音频就是**一条**字幕。

第二种正是 `AsrService.supportsSegments` 存在的理由：让「拿不到时间轴」变成一个**预期内的
分支**，而不是一次失败。三个坑都按实测处理了：

- **`start` / `end` 是秒的浮点**（`3.319999933242798`），要 `×1000` 取整再加块偏移。
  当毫秒直接用的话 3.3 秒会变成 3 毫秒，全部字幕挤在开头，看起来像「识别全错了」。
- **每一段 `text` 都带前导空格**（官方示例就是 `" The beach was a popular spot…"`），
  所以清洗走的是**与本机识别同一个** `AsrTextNormalizer.normalize()`——两条路必须一致，
  否则同一个文件换种引擎会得到风格不同的字幕。
- **服务商偶尔在末尾塞一条读不出来的哨兵项**：为它丢掉前面几十条正确时间轴不值得，
  所以逐条跳过、但**计数并记日志**（`找到 N 条、可用 M 条`），不做静默丢弃。

### 4. 失败原因按「下一步该做什么」分开

云端那条路新增 10 类失败，每一类的下一步动作都不同：

| 界面说的事 | 下一步动作 |
| --- | --- |
| 连不上识别服务 | 换个网络 / 稍后再试（这一块没花钱） |
| 「%s」拒绝了这次请求——API Key 没填或不对 | 去设置页填或换密钥（改这里立刻能好） |
| 服务商按**账户策略**拒绝（403） | 换服务商——**换密钥没用**（这句专门写出来） |
| 这个地址上**没有**识别接口（404） | 改地址——多数兼容服务要把路径写到 `/v1` |
| 服务地址还没填好 | 把地址填完，或改用本机识别 |
| 服务商不接受这次请求（400） | 换模型或预设（常见成因：这个模型不支持返回时间轴） |
| 这一块音频超过体积上限（413） | 改用本机识别（不上传、无体积限制） |
| 额度用完或被限流（429） | 充值 / 换服务商（`Retry-After` 会带出来） |
| 服务商侧故障（5xx） | 稍后重试——本地做什么都没用 |
| 返回的内容读不出来（200 但没文字） | 换预设 / 报 bug（典型成因是中转站自己包了一层） |

合并成一句「云端识别失败」的后果是具体的：**401 和 403 都变成同一句话，用户会去反复重填密钥**，
而 403 是账户策略挡的，改一万次密钥也不会好。同理 404 与 400 归成一类的话，用户会去换模型，
而真正该改的是那个填错的地址。

还有两处刻意的设计：

- **`Retry-After` 会带进文案**，但服务商不给原因时**不会留一个悬空的冒号**——
  空串换成一句专门的话（「服务商没有说明原因」）。错误体里读不出人话（`{"code":4001}`）
  也走这一句：平铺进提示只会得到「服务商不接受这次请求：{"code":4001}」，既难看又没信息，
  而**日志里已经有一份完整原文**（截断只发生在展示这一步）。
- **错误分析走的是 `when` 到具体类型，不是看消息文本**，与翻译那边同一套。

### 5. 两处隐私告知，都在「按下按钮之前」

设置页选云端时说一次、**播放页那个按钮上面再说一次**：

- 设置页：「云端识别会按 5 分钟一块把音频上传到你填的地址，传完才开始识别。上传是向外的，
  删不回来；识别结果只写在本机。」
- 播放页：「云端识别：整段音频会上传到「服务商」，传完才开始识别。」+ 按钮写着
  **「上传并生成字幕」**（不是「生成字幕」）。

播放页那句是必须的：选择发生在**另一页、另一次会话**，提示只出现在设置页就等于没出现。
按钮文案也刻意从「生成」改成「上传」——那是用户最后一个能反悔的位置。
顺带删掉了原来那句共享的「音频不会上传」（本机那一块保留它）：这句话在云端这条路上是**假的**。

### 6. 两条路共用一套落盘与展示

`AsrSubtitleGenerator` 现在收一份 `AsrJob`（`OnDevice(model)` / `Cloud(config)`），
两条路都从这一个入口出去，所以「存哪儿、怎么序列化、失败怎么报」仍然只有一份实现。

- **文件名是「媒体哈希」，与走哪条路无关**，于是一部片子只有**一条**生成字幕，
  换引擎重跑会覆盖上一条。两份并存会在面板里出现两个同名字候选（内容只有时间轴切分不同），
  用户没法从界面上分出哪条是哪条；而生成的字幕本来就是可以再跑一遍的东西，覆盖它不丢用户劳动。
- **失败不会留下半截结果**：第 3 块传失败时前两块的结果不会写出去，所以盘上仍然是
  上一次那份完整字幕，而不是一份只有前 7 分钟的残缺字幕。

## 二、真机验证结果

| 项 | 结果 |
| --- | --- |
| 入口摘要（本机） | 「中文离线（Paraformer 小模型）· 未下载 · 约 78.1 MB」 |
| 切到云端 | 隐私告知 + 服务商行 + 地址栏 + 模型栏 + 密钥空态 |
| 最终请求地址 | `将请求：https://api.siliconflow.com/v1/audio/transcriptions` |
| 服务商弹窗 | 四家齐全，硅基流动带「（不出时间轴）」徽标 |
| 换「自定义」 | 地址栏标红 + `将请求：` 那一行消失（没有合法地址可算） |
| 入口摘要（云端） | 「云端识别 · 硅基流动 · 未填密钥」→ 换自定义后「云端识别 · 自定义（中转 / 自建）· 未填服务地址」 |
| 切回本机 | 摘要恢复，云端那几栏的设置保留着 |

### 1. 一个与本版功能无关、但会让验证卡住的现象

模拟器原来的中文输入法会在 `adb shell input text` **往输入框里写网址时改写字符**：
`https://example.com/v1` 到达应用时变成了 `https：／／exampl。ecom／v1`
（`:` → `：`、`/` → `／`、`.` → `。`，字母数字不受影响）。

后果是**「手打一个合法 URL」和「粘贴一段密钥」这两条路没法用 adb 验证**。这一版的对策是
把这两件事改由**预设服务商**覆盖（预设自带合法地址），并在验证清单里标注清楚哪几项是
用预设验的、哪几项没有真机验证过（密钥保存/删除走的是单测与 v0.6.4 已有的那条路）。
写在这里是为了让下一个人不要把它当成产品缺陷去修——它不是。

### 2. 覆盖安装 debug 包会因签名不同失败

`adb install -r` 报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`：设备上那份是 release 签名装的。
先 `adb uninstall <包名>` 再装即可（会清掉应用数据，所以已下好的模型需要重下）。

## 三、已知取舍

1. **只支持 OpenAI 兼容的 `/audio/transcriptions`。** 阿里云 Qwen-ASR 这类把音频塞进
   `…/compatible-mode/v1/chat/completions` 的服务**本版不支持**——它的请求形态是另一套，
   要接得另写一条请求构造路径。
2. **块边界会切断一句话。** 固定 5 分钟一块，听感上是每 5 分钟多一条半截字幕。
   用重叠切片能补，但重叠区要去重（同一句话被识别两次、时间轴还差半个字），本版不做。
3. **容器不写时长就没法走云端这条路。** 云端必须先知道总长才能切块，而裸 ADTS AAC、
   部分流式封装不写时长。这时**不会**退化成「当成一整块发出去」（两小时的片子会先生成
   一个 230 MB 的临时 WAV，多半先把手机存储写满），而是明确报错并建议改用本机识别。
4. **「自定义」这一家不强制填密钥。** 自建服务可能不需要密钥，所以这个字段留空也允许提交；
   本地判断不了对面要不要，只能由服务商回话。
5. **整段音频都会上传。** 这是这条路的前提，不是可以优化掉的细节；两处告知都在按钮之前。
6. **不支持断点续传与「先给前半段」的流式产出。** 一次识别的结果是一次性拼好的，
   中途取消会丢掉已经传过的块（配额也已经花掉了）。
7. **没有真机验证过密钥的保存与删除**（原因见上面第二节）。这两条走的是 v0.6.4 已有的
   那条路 + 本版的单元测试。

## 四、升级提示

- 从 v0.6.4 升级**不需要任何迁移**：新增的是设置项与代码，老配置一律照旧。
- **不想上传音频的人什么都不会变**：默认识别方式仍是本机，云端那一段只有主动选了
  才会出现。
- 已经生成的字幕、人工修正、术语表、翻译缓存都**不受影响**（本版没有改动它们的存储格式）。
- 这一版**没有**新增需要用户手动开的系统权限（语音识别用的是已有的媒体读取权限）。
