## 一、这一版做了什么

两件事，一件是「多了一条通道」，一件是「多了一类能画出来的字幕」。

**内嵌位图字幕。** PGS（蓝光 .sup）、VobSub（.idx/.sub）、DVB 这三种内嵌字幕轨，带的是**图**
而不是字。以前它们会被判成「这条轨读不出来」——面板上什么都不说，用户看不出是片源没有字幕
还是播放器不认。现在它们能画出来了，走的是一条**独立的渲染路径**（见第二节）。

**更新通道分成两条。** 应用内检查更新现在分「正式版」和「测试版」：正式版通道只收不带后缀的
版本，测试版通道两条都收。`alpha` 从这一版起退回「内部构建」，任何通道都不收它（见第四节）。

除此之外，这一版不改既有行为。

---

## 二、位图字幕为什么必须是「另一条渲染路径」

文本字幕在我们这边是**一串字符串**，我们能拿它做任何事：改字号、加描边、整体平移、按比例拉伸、
双语并排、替换成译文。位图字幕是一张**已经画好的图**——字已经在图里了，我们拿到的是像素。

所以它不是「文本字幕的另一种格式」，而是另一种东西：

| | 文本内嵌轨 | 位图内嵌轨 |
| --- | --- | --- |
| 我们拿到什么 | 字符串 + 时间戳 | 一张 ARGB 位图 + 时间戳 + 摆放比例 |
| 谁来摆放 | 我们自己（`SubtitleOverlay`） | Media3 的排版公式，我们照抄（`BitmapSubtitleLayer`） |
| 能改字号 / 描边 | 能 | 不能（图里已经定了） |
| 能翻译 | 能 | 不能（没有字可翻） |

摆放这块**没有自己发明算法**：`BitmapCueLayout` 是 Media3 `SubtitlePainter.setupBitmapLayout`
的逐行移植。理由很直接——这条路径的输入本来就是 Media3 给的 cue，用别人的公式才能保证
「我们画的位置」和「Media3 自己画的位置」一致；自己写一版，差别会以「字幕偶尔偏半个屏」的
形式出现，而且要拿一堆片源才能试出来。

Media3 自带的 `SubtitleView` 仍然是遮着的：它一旦可见，内嵌**文本**字幕就会被画两份
（这是 v0.5.17 修过的问题）。所以两条路同一时刻只有一条在画。

## 三、四个开关刻意不进这条路径

位图轨**认「显示模式」这一个开关**：关掉字幕，位图也跟着清掉（否则会出现「字幕已经关了，
画面底下还压着一块半透明底图」）。其余四项一律不生效：

1. **字幕延迟 / 字幕速率**。那两项是我们在时间轴上做的**位移与缩放**，而位图 cue 由 Media3
   按自己的时间戳直接投递，插不进手。硬做的话得在 Media3 之外再建一条自己的时间轴，等于把
   「谁在管时间」这件事变成两个来源。
2. **字幕样式**（字号 / 行距 / 描边 / 底部距离）。图里的字已经画好了，改这些只会改到我们画的
   那一层边框，看上去像「设置坏了」。
3. **整轨预读**。预读存在的意义是「一次性拿到整张文本表」，对位图轨没有对应物：每一条 cue
   自带它那张图，按时间投递即可。
4. **双语 / 翻译**。没有字可以并排，也没有字可以翻。

**面板会把这几点写出来**，而不是让它看起来像「这条轨读不出来」——「功能没做」和「这条轨坏了」
是两种不同的坏消息，用户需要分得清。

## 四、更新通道：两个通道，三条线

| 版本号 | 是什么 | 正式版通道 | 测试版通道 | GitHub Release |
| --- | --- | --- | --- | --- |
| `X.Y.Z-alpha.N` | 内部构建 | 不收 | 不收 | 不建 |
| `X.Y.Z-beta.N` | 公开测试版 | 不收 | **收** | 建，标记为 Pre-release |
| `X.Y.Z` | 正式版 | **收** | **收** | 建，标记为 Latest |

几条规则值得单独说：

- **判据看 tag，不看 GitHub 的 `prerelease` 勾。** 勾是发布时手填的开关，tag 是构建流程写进
  包里的东西——前者可以忘，后者不会。
- **测试版通道必须收正式版**，否则装了 beta 的人永远退不回来：他得先收到正式版才能回到正轨。
- **alpha 是两个通道都不收的**（第二道闸）。第一道闸是「不建 Release」，这一道防的是
  「哪天顺手建了一个」。
- **切换通道会写进设置。** 手动选过某个通道之后，检查更新不再按「当前版本是不是预发行」
  自动改通道——否则你切到测试版装了个 beta，下次检查会因为「当前是 beta」而自动切回去，
  再之后又因为「当前变成正式版」切回来，来回横跳且没有任何提示。
- **`versionCode` 不随通道变。** `0.9.0-beta.1` 和 `0.9.0` 共用同一个 code（900），这是有意的：
  它们本来就是「同一个版本」，而 Android 只在**降级**时拒绝安装，同 code 覆盖安装是允许的。

## 五、VobSub / DVB 的边界，说清楚

三种格式的解析都由 Media3 负责（`PgsParser` / `VobsubParser` / `DvbParser`），我们没有自己写
解码器。但它们的**前置条件严格程度不一样**：

- **PGS** 是自包含的，实测样本通过；
- **VobSub / DVB** 的画形依赖片源初始化段里的调色板与尺寸（`VobsubParser` 的前置条件相当严），
  拿不到这些信息就画不出来。

所以这两个按「**能用就用、认不出来就当这条轨没有**」处理，而不是让整条轨变成一条永远读不出
内容的「坏轨」。目前有实测样本的只有 PGS。

## 七、新增与修改

**新增**

- `core:player`：`BitmapCues.kt`（`EmbeddedBitmapCue`、`BitmapCueSpec`、`CueAnchor`、
  `EmbeddedBitmapState` 与三组转换），把 Media3 的 `Cue` 折成干净的「比例 + 可空」结构
  ——没写过的值保持 `null`，不折成零。
- `feature:player`：`BitmapCueLayout.kt`（照抄 Media3 的排版算法，含 `width / 2` 的整除）、
  `BitmapSubtitleLayer.kt`（Compose 的位图层）。
- `docs/release-process.md`：发版流程（三条线、两个通道、发完要核对的四件事）。
- `core:data`：`UpdateChannel` 的命名与判据相关测试。

**修改**

- `app/build.gradle.kts`：版本号 `0.8.1` → `0.9.0-beta.1`。`versionCode`、`BuildConfig`、
  关于页显示的版本号全部由这一处推导。
- `PlaybackTracks.kt`：位图 MIME 判定排在最前，新增 `isBitmapRenderable`；
  自动挑选顺序不变（文本轨仍优先）。
- `ExoPlayerController.kt`：接住位图 cue（`onCues` 里先收位图再提前返回），切集时清空。
- `SubtitleViewModel` / `SubtitleUiState`：透传位图 cue，并在「显示模式 = 关」时清空。
- `SubtitleIssueText` / `SubtitleFormat`：DVB 的格式名与位图轨的说明文案（三语齐全）。
- 更新页：通道选择与文案（三语齐全）；关于页：测试版徽章。

## 八、已知限制

1. **位图字幕的延迟 / 速率 / 样式 / 双语 / 翻译一律不生效**（第三节解释了为什么）。
   这是设计取舍，不是「还没做」。
2. **VobSub / DVB 只在片源带够初始化数据时才画得出来**（第五节）。目前有实测样本的只有 PGS。
3. **封面是自动取的，没有手动换一张的入口**（v0.8.1 起，本版未变）。
4. **不含 32 位原生库**（ABI 只保留 `arm64-v8a` / `x86_64`，与上一版相同）。
