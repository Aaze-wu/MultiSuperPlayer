# v0.6.6-alpha.1 预发行测试版

> **这是预发行测试版（pre-release）。** 功能与界面文案仍可能调整，不建议作为日常主力使用。
> 遇到问题请到 [Issues](https://github.com/Aaze-wu/MultiSuperPlayer/issues) 反馈。

## 一、这一版做了什么

三件事，都是围绕「翻译模型不够用」这一个抱怨：

1. **设备上多了一档高质量模型**：腾讯混元 HY-MT2-1.8B（int8，约 1.7 GB，翻译专用）。
   0.6B 仍然是默认档，1.8B 是你自己去挑的那种。
2. **Ollama 预设换掉了默认模型**：从通用对话模型 `qwen3:8b` 换成翻译专用的
   `demonbyron/HY-MT1.5-1.8B`。
3. **翻译目标语言从 5 门扩到 15 门**：新增俄语 / 西班牙语 / 法语 / 德语 / 葡萄牙语 /
   意大利语 / 阿拉伯语 / 泰语 / 越南语 / 印尼语。

外加一处「防止用户白花流量」的小改动（内存提示，见下）。

## 二、设备上的第二档模型：为什么不是「直接把默认换掉」

### 1. 为什么加它

0.6B 那条只能算「能跑」：长句会掉成分、术语会自己改写、中英以外的语种基本靠猜。
混元那条是**翻译专用**模型（33 种语言），在这些方面是另一个量级。

### 2. 为什么默认仍然是 0.6B

**默认值是给所有人的**，而这台设备不一定跑得动 1.8B：

| | Qwen3-0.6B | 混元 HY-MT2-1.8B |
| --- | --- | --- |
| 下载体积 | 约 345 MB | 约 1.7 GB |
| 运行时峰值内存（官方实测，CPU 后端） | 上游没给 | 约 2.7 GB |
| 适合的机器 | 能跑起这个 App 的都行 | 8 GB 及以上 |

把 1.8B 设成默认，等于让所有 4 GB / 6 GB 机器上的用户**先下 1.7 GB 再发现跑不动**。
所以：默认留给能用的那条，好那条放在列表里等人去挑。

### 3. 内存需求写在下载之前，只提示不拦

模型卡片上多了一行「运行需约 2.7 GB 内存」——在**下载之前**就写出来，
因为「下完之后才发现跑不动」这件事没有退路：1.7 GB 流量已经花掉了。

超过本机总内存 40% 时再多一句红字：

> 本机总内存约 3.8 GB，这条模型可能跑不起来

**只是提示，不置灰任何按钮。** 理由有两个：

- 阈值只是估计，判不准。两种判错的代价差得远：该警告没警告 = 用户白下 1.7 GB；
  不该警告却警告 = 一句灰字被无视。
- 「能不能跑」最终由运行时的实际可用内存决定，不是由总内存决定。我们不知道用户此刻
  后台开着什么，所以无权替他决定。

阈值取 40%，是两个实测锚点卡出来的：官方文档说能跑的 Pixel 8a（7.75 GB）算出来是 0.34，
中端 6 GB 机算出来是 0.46；而 Android 系统自己大致要吃掉 40%。所以 0.4 这条线
既不冤枉官方说能跑的机型，也能把 6 GB 机标出来。

### 4. 上游没给实测内存的模型，一行都不显示

0.6B 那条上游没给峰值内存，所以**它的卡片上没有那一行**（不是写「0 MB」，也不是猜一个值）。
猜出来的数字会被用户当成事实，而这条「事实」错的方向恰好是危险的那一边。

## 三、Ollama 预设：换模型，不换地址

| | 改前 | 改后 |
| --- | --- | --- |
| 模型 | `qwen3:8b`（通用对话） | `demonbyron/HY-MT1.5-1.8B`（翻译专用，33 种语言） |
| 地址 | `http://10.0.2.2:11434/v1` | 不变 |
| 关思考参数 | 无 | 仍为空（翻译模型没有思考模式，多塞字段只会让严格的网关报 400） |

**为什么换**：字幕翻译用不上「世界知识」，要的只是逐行忠实与语种覆盖。
拿一个 8B 的通用模型去干这件事，用户付出 5 倍显存、5 倍等待，换回来的没有一样是他需要的。

**地址没换**的理由是 `10.0.2.2` 是模拟器映射到宿主机的地址，真机要改成电脑的局域网地址——
设置页那张卡片上写清了这一点。

⚠️ **注意这两条不是同一个模型**：设备上那条是 **HY-MT2**（`.litertlm`，1.82 GB，int8），
Ollama 那条是 **HY-MT1.5**（Ollama 格式，1.1 GB，Q4_K_M）。名字很像，格式不同，
不要互相拷贝。

## 四、目标语言 5 → 15 门

新增：俄语 / 西班牙语 / 法语 / 德语 / 葡萄牙语 / 意大利语 / 阿拉伯语 / 泰语 / 越南语 / 印尼语。

**为什么是 15，不是 33**：可选清单不等于模型能力上限。每加一门语言要配 3 套界面文案
（简中 / 英 / 繁中）加 1 条提示词示例，所以取的是「使用频率 × 可验证性」的交集——
一门我们没法判断译文对不对的语言，加进来只是把「模型译错」变成「我们译错且看不出来」。

**示例跟着目标语言走**，而且每条都刻意保留一个该语言特有的书写习惯：

| 语言 | 示例里的「招牌」 | 它防的是什么 |
| --- | --- | --- |
| 法语 | `Où vas-tu ?` | 法语在 `?` 前要留一格，不留就是没照抄示例 |
| 西班牙语 | `¿A dónde vas?` | 开头的倒问号是最容易漏的一处 |
| 阿拉伯语 | `إلى أين تذهب؟` | 用的是 `؟`（U+061F），不是 `?` |
| 泰语 | `คุณจะไปไหน` | 泰语不加句号、词间不加空格 |
| 越南语 | `Bạn đi đâu đấy?` | 声调符一旦丢了看起来就像英语 |
| 俄语 | `Куда ты идёшь?` | 源文是拉丁字母，译文必须是西里尔 |

单测会拿**其他 14 门语言的招牌词**当禁忌表去查每一门的示例：示例里出现别的语言的招牌词，
测试就红。所以「模型照抄示例 → 译错语言」这条链子上的每一环都是被钉住的。

## 五、真机验证结果

在 `emulator-5554`（Android 17 / API 37，**总内存 3.8 GB**）上实测：

| 项 | 操作 | 结果 |
| --- | --- | --- |
| 服务商列表 | 设置 → 字幕与翻译 → 切换 | ✅ 8 项，Ollama 那条的说明已换成 `ollama pull demonbyron/HY-MT1.5-1.8B` |
| 目标语言 | 点「译成：简体中文」 | ✅ 恰好 15 项，前 5 门顺序与文案未变 |
| 目标语言生效 | 选「俄语」 | ✅ 摘要行变成「译成：俄语」 |
| 设备上模型清单 | 服务商切到「本地（设备上运行）」→ 点本地模型 | ✅ 两条：`Qwen3 0.6B（本地） · 约 328.7 MB`、`混元 HY-MT2 1.8B（本地） · 约 1.7 GB` |
| 内存需求 | 看混元那张卡片 | ✅ 「运行需约 2.7 GB 内存」在描述下方 |
| 内存不足提示 | 同一张卡片 | ✅ 红字「本机总内存约 3.8 GB，这条模型可能跑不起来」（3.8 GB × 0.4 = 1.52 GB < 2.76 GB） |
| 不冤枉 0.6B | 看 0.6B 那张卡片 | ✅ **没有**内存那一行，也没有那句红字 |
| 选择生效 | 点混元那条 | ✅ 下载按钮变成「下载模型（约 1.7 GB）」（不再是 328.7 MB） |
| 选择持久化 | 返回上一页 | ✅ 入口行变成「混元 HY-MT2 1.8B（本地） · 未下载 · 约 1.7 GB」 |

**没有实测「1.8B 模型在这台模拟器上能不能真的加载起来」**：本机总内存只有 3.8 GB，
低于该模型 2.7 GB 的峰值需求，下载 1.7 GB 去验证一件大概率会失败的事不划算。
所以你在这台机器上看到的那句红字**是对的**，但它不是「实测结论」，是计算结果。

## 六、已知取舍

1. **1.8B 那条在本次验证的设备上跑不起来**（这是预期，不是 bug）。它在 8 GB 及以上的机器上
   才有意义；官方的实测机型是 Pixel 8a。
2. **内存阈值是「总内存 × 0.4」，不是「可用内存」。** 用当前可用内存会让同一台机器在
   「刚开机」和「后台一堆应用」两种状态下给出相反的结论，而那两次数值差异与模型能不能跑无关。
   代价是在一台后台很干净但总量很小的机器上会显得过于保守。
3. **翻译提示词模板没有换**（`TRANSLATION_PROMPT_VERSION` 仍是 2）。混元系列用现有模板的
   逐行 JSON 输出格式没问题；换模板就必须 +1，否则旧缓存会被当成新结果复用。
4. **0.6B 照抄提示词示例、翻译缓存没有「清空」入口**——这两个问题按既定决定保留，
   本版不动。
5. **15 门语言里没有阿拉伯语的 RTL 专门处理。** 字幕渲染由 Compose 按字符集自行判断方向，
   实测显示正常；但如果以后要做「译文和原文并排双语渲染」，RTL 需要单独再看一遍。

## 七、升级提示

- 从 v0.6.5-alpha.2 升级**不需要任何迁移**：
  - 目标语言的持久化用的是语言 `code`（`ru` / `es` / …），新增的 10 条**追加在枚举末尾**，
    原有 5 条的 code 和顺序一个都没动，所以已选的「简体中文」不会变成别的语言。
  - 设备上模型的持久化用的是清单 id，默认仍是 `qwen3-0.6b`，已下载的模型不受影响。
  - 翻译缓存的键是「内容 + 目标语言 + 模型」，提示词模板没变 ⇒ 旧缓存继续有效。
- **versionCode 从 605 涨到 606**：跨数值段（0.6.5 → 0.6.6）时 code 必须跟着涨，
  否则预发行版会变成用户永远装不上的「降级包」。
- 如果你之前把 Ollama 的模型名手动改成了别的：本次升级**不会**覆盖你填的值
  （只改了预设的默认值），你可以在设置页点「切换」重新选一次 Ollama 拿回新默认值。
