# v0.6.1-alpha.1 预发行测试版

> **这是预发行测试版（pre-release）。** 功能与界面文案仍可能调整，不建议作为日常主力使用。
> 遇到问题请到 [Issues](https://github.com/Aaze-wu/MultiSuperPlayer/issues) 反馈。

发布日期：2026-10-03
基于版本：v0.6.0

---

## 一、这一版做了什么

v0.6.1 是 v0.6.0 之后的**第一个公开发布准备版**，功能上与 v0.6.0 基本一致，改动集中在
「准备对外发布」这件事上：发行渠道、界面观感、文案质量。

### 1. 版本与发行渠道

- 版本号改为 **`0.6.1-alpha.1`**：数值段 `0.6.1` 推出 `versionCode`，后缀 `alpha.1` 进入
  `versionName` 与界面。构建脚本会校验后缀必须是 `alpha` / `beta` / `rc` 这类字母通道名。
- 「关于」页在预发行版上会显示**「预览版」徽章**与一行说明，正式版上整块不出现。
- 再次强调：预发行版与同数值段的正式版**共用同一个 `versionCode`**。Android 只在降级时
  拒绝安装，所以同 code 覆盖安装是允许的；但如果你之后装了 `0.6.2` 再想装回本版，会被系统拒绝。

### 2. 「关于」页改版

- 顶部新增品牌区：应用图标 + 名称 + 版本号（+ 预览版徽章）。
- 新增「使用与反馈」小节，三个入口：
  - **项目主页** —— 打开 GitHub 仓库；
  - **问题反馈** —— 打开 Issues 页面；
  - **本版更新说明** —— 就地弹出本版的内容摘要（一段写在文案资源里的摘要，与本文件
    人工同步，三份语言文件各有一份）。
- 「关于」页不再单独列出 git commit 与构建时间，顶部只留一行「版本号 (版本码)」。
  这三个值（版本 / 构建来源 / 构建时间）改为写进**导出的日志抬头**，让日志文件自己
  说清「这是哪个构建产生的」，排查问题时不必再回头问用户装的是哪一版。
- 移除了原先的「检查更新」入口：目前没有可用的更新检查后端，放一个点了没反应的按钮
  比没有按钮更糟。后续版本会重新设计这一块。
- 打开链接失败（设备上没有可用浏览器）时会**就地**显示失败提示并带上那个地址，
  而不是弹窗——弹窗一关地址就没了，行内提示可以直接长按复制。

### 3. 设置项帮助

设置页里「说明较长 / 容易被误解」的约二十项，标题右侧新增 **「?」帮助按钮**，点击弹出
详细说明；原来的副标题同时被精简为一行现状。

覆盖范围包括：强制软件解码、默认画面比例、默认倍速、记住播放位置、记录最近播放、
翻译服务地址与连通性测试、ASR 模型下载地址、封面取色与系统取色、强调色等。

### 4. 提示文本专业化与精简（三语言）

对简体中文 / 繁体中文 / 英文三份文案做了一次全量梳理：

- 去掉只适合开发期使用的措辞与记号。例如原文里 Markdown 的 `**加粗**` 与反引号在界面上
  是**原样显示**的（界面不解析 Markdown），现在改成正常标点；
- 提示里不再直接出现原始字段名（`finish_reason=`、`invalid_api_key`、`POST {baseUrl}/...` 等），
  换成可读的描述；
- 口语化表达改为书面语（「还没下载完」「随便填」→「尚未下载完成」「可任意填写」）；
- 术语统一：「尚未配置」「未识别到」「预期 / 实际」等在模块间保持一致。

涉及 `feature:settings`、`feature:player`、`core:translate`、`core:asr` 四个模块，共约
二百条文案 × 3 种语言。三份语言文件的 key 集合由单测守卫（`MspStringsTest`、
`AppLanguageTest`），不会出现某一种语言漏翻。

### 5. 签名与发布流程

- `keystore.properties.example` 扩写为完整的签名操作说明：keytool 命令与参数含义、
  自检方式、口令字符限制、忽略规则验证、`apksigner` 验签，以及**密钥丢失的后果**。
- 本仓库说明：没有 `keystore.properties` 时构建不会失败，release 包会自动回退用 debug
  签名，方便本地验证，但**不能用于分发**。为免「用的其实是 debug 签名」这件事悄悄发生，
  构建时会把本次 release 实际使用的签名打一行到构建日志。
- 签名方案定为 **v2 + v3**：v1 只服务 Android 7.0 以下，而本应用 `minSdk` 是 26，开着没用；
  v3 从**第一个**发布包起就必须打开——日后若要更换签名密钥，Android 9+ 要靠旧包自身携带的
  v3 签名（lineage）来证明「新密钥由旧密钥授权」。**第一个包只签 v2 的话，这把密钥就永远
  换不掉了**，届时要换只能在改包名重新发布（用户数据全部丢失）与不再升级之间二选一。

## 二、安装

从本页 Assets 下载 `app-release.apk`，在设备上允许「安装未知来源应用」后安装。

**这是本项目第一个公开发布的安装包**，此前只发布过源码标签，没有任何历史版本可供升级，
所以绝大多数人不会遇到升级问题。

需要特别注意的一种情况：**如果你在此版本之前自行构建并安装过**（那批包用的是 debug 签名），
本版**装不上去**，系统会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。这不是缺陷，而是 Android
的保护机制：签名不一致的包不允许覆盖安装，否则任何人都能伪造一个「升级包」来读取用户数据。
请先卸载旧版本再安装本版：

```powershell
adb uninstall com.multisuperplayer.player
```

**卸载会连同应用私有目录一起清掉**：播放记录、设置项，以及已下载的离线识别模型
（78～190 MB，需要重新下载）。从本版开始，后续版本都可以直接覆盖安装、不丢数据——
前提是签名密钥不变（见 5. 签名与发布流程）。

### 系统要求

| 项目 | 要求 |
| --- | --- |
| 系统版本 | Android 8.0（API 26）及以上 |
| CPU 架构 | `arm64-v8a` 或 `x86_64` |
| 存储空间 | 基础约 120 MB；使用离线语音识别另需 78～190 MB |

**不支持 32 位设备**（`armeabi-v7a`、`x86`）。这是有意的取舍：把四个 ABI 全打进一个包
会让 APK 无谓地大一倍，而 32 位设备在 2019 年之后已基本消失。如果你的设备装不上，
请开一个 Issue 说明机型。

### 首次使用提示

- **离线语音识别（字幕生成）的模型不打进安装包**：模型单条 78 MB（纯中文）到 190 MB
  （中英双语），打进包里会让不打算用这个功能的人白等一次下载。入口做成了
  「先选模型、再下载」，首次使用需要联网，之后完全离线运行，音频不会离开设备。
- 在国内网络下，模型下载可换用镜像地址（设置 → 语音识别 → 下载地址）。

## 三、已知限制

- **未提供音视频同步调整**（如音画延迟微调）。字幕时间轴偏移已经具备（播放页 → 字幕 → 同步）。
- **云端语音识别与音频翻译尚未实现**：本版只支持本地模型；云端方案在后续版本中规划。
- **更新检查未提供**：见上文，后续版本重新设计。
- 首次下载模型时会校验 SHA-256，校验不通过会重新下载；若反复失败，多半是镜像地址问题。
- 「关于」页的日志导出使用系统文件选择器，部分定制系统（如某些国产 ROM）对该入口的
  权限提示较激进，导出前会再确认一次文件名。
