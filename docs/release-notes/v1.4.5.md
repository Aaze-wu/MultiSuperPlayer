# v1.4.5 桌面歌词浮窗拖动 / 浮窗宽度固定 / 浏览页文件的播放记录

发布日期：2026-10-19
基于版本：v1.4.0

---

## 一、这一版带来了什么

这一版全是修，没有新功能。修的三处都属于「按了没反应 / 按了乱动」这一类——不看代码很难
说清是谁的错，但每天都会撞上。另外顺手把浮窗的**宽度固定下来**（以前它会随歌词长短伸缩）。

| 修了什么 | 以前的样子 | 现在的样子 |
| --- | --- | --- |
| **桌面歌词浮窗拖不动** | 手指按住浮窗一拖，它就往反方向窜、来回弹，整个屏幕乱跑，松手的位置和手指停下的位置对不上 | 拖着走就是走，一步跟一步，松手停在哪就是哪 |
| **浮窗大小跟着歌词变** | 五个字是一小块、一句话是一条长条，切歌时左右两边一起伸缩，看着像「它自己挪了」 | 宽度固定（屏幕的 92%），短句两侧留白；高度仍然跟着行数变 |
| **从「浏览」页播的文件不进「最近」** | 播完回「最近」看，一条都没有；内置文件浏览器和系统文件选择器都一样 | 播过就出现在「最近」最上面，点一下接着上次的位置继续 |
| **发版构建里的两条无效备份规则** | 每次 release 构建都会打两行「cache 不在被包含的路径里」的报错 | 这两行没有了，构建输出干净 |

既有能力全部不变：媒体库、浏览、最近、播放列表、收藏、字幕与歌词、桌面歌词、翻译、
网络播放、外部打开与分享、语音识别与清空识别缓存、播放时禁止熄屏、检查更新与自动检查间隔、
后台保活、权限页。本版**没有**新增任何系统权限，也没有新的系统行为。

## 二、怎么用

### 桌面歌词浮窗

1. 设置 →「桌面歌词」打开，回到播放页，点「歌词浮窗」。
2. 按住浮窗**任意位置**拖到你想放的地方，松手即可。歌曲切换、播放暂停都不会让它挪位。
3. 浮窗宽度固定（屏幕的 92%），不随歌词长短伸缩；高度会跟着行数变（有译文多一行）。
4. 想让它回中间：同一个设置页里有「重置位置」。
5. 锁屏上/主屏上它都在最上层（这是「悬浮窗」权限给的），**拖它不需要先解锁什么**。

### 「最近」里的浏览页文件

1. 底部「浏览」→「内部存储」或「存储卡」→ 找到文件 → 点开播放。
2. 退出播放页，底部切到「最近」。刚播过的那一条在最上面，副标题写着「上次播于 …」。
3. 点它，从你上次停下的位置继续。
4. 用系统文件选择器添加进来的目录也一样：`浏览 → 存储卡 / 你添加的目录 → 文件 → 播放 → 最近`。

## 三、几点说明

- **「最近」不会因为这件事把文件塞进媒体库。** 浏览页的文件仍然只在浏览页里可见；
  「最近」里那一条是从你的播放记录**临时**查出来的。所以媒体库的筛选、分组、
  数量都不会被它影响。
- **文件不在了，那一行就先不显示。** 文件被删掉、存储卡被拔出、或者用系统文件选择器
  添加的目录授权被撤销之后，这一条会从「最近」消失；文件回来后它自己重新出现。
  播放记录本身**没有**被删掉。
- **浮窗位置是「最后拖到的坐标」。** 换歌词字级、多出一行译文、或者横竖屏切换之后，
  它能保证自己不出屏，但不保证回到你原来放的地方（见「已知限制」第一条）。
- **备份规则这两条报错跟你的数据没有关系。** 它们说的是一条「排除某个从未被包含的目录」
  的规则，运行期本来什么也没多备份、什么也没少备份。删掉只是让构建输出不再有噪音。
- **本版没有改动**字幕匹配规则、翻译、语音识别、更新通道、状态栏图标的任何行为。

## 四、为什么以前一拖就飞

拖动一个浮窗，只需要回答一个问题：**手指往右走了 50 像素，窗口该往右挪多少**。

以前的算法是这样问的：先拿到「手指在窗口里的位置」，再拿「我们刚才请求窗口去的位置」，
两者相减当作窗口的位移。这套算法有个隐藏的前提——**窗口已经挪到我们请求的位置了**。
前提不成立：系统的窗口更新是异步的，实测窗口实际位置比请求值**慢大约两帧**。
于是「手指在窗口里的位置」算出来的偏差是错的，再拿错的位置做补偿，就**补过头**：
一帧多补几十到上千像素。手指匀速往下走 200 像素，窗口的纵坐标走成
1750 → 1650 → 1600 → 1557 → 1582 → 1649 → 1741 → 1894 → 1878 → 1545 → 982 → 811 →
1749 → 2150：先跟手、再倒着窜、再顺着窜。屏幕上看就是抖成一片。

这一版换了个问法：**手指在屏幕上走到哪了**。屏幕坐标跟窗口有没有动过完全无关，
所以窗口位置直接写成「按下那一刻的窗口位置 + 手指从按下点起走出的距离」，
算一次就到位，中间不读任何「窗口现在在哪」，也就没有反馈、没有误差累积。
贴到屏幕边缘被夹住之后再往回拖，也不会像以前那样粘住不动。

配套还有两件麻烦事：一是这个新写法必须把触摸事件「消费掉」，否则系统发了一次
按下就不再往下发（拖动完全不响应）；二是「消费掉」意味着浮窗上的按钮不能再靠
标准点击手势判断（标准手势正是用「事件有没有被消费」来决定要不要取消点击），
所以那几个按钮改成了自己判断「按下之后有没有移动超过一个手指抖动的容差」。

一个会自己动来动去的窗口，比一个位置不太理想的窗口更让人恼火——所以这一版的验收
标准很朴素：**拖着走就是走，一步跟一步，松手停在哪就是哪。**

## 五、已知限制

- **浮窗宽度固定后，短句两侧会留白。** 一句五个字也占屏幕的 92%，文字居中，两边是空的。
  这是「宽度不随内容跳」的代价——反过来就是以前那种「切歌时左右伸缩、看着像自己挪了」。
- **浮窗不自动归位**：改字级、多一行译文、横竖屏切换之后只保证不出屏，位置要自己拖一下；
  「重置位置」在设置页。
- **浮窗位置按屏幕存一份**：横屏拖到的地方，转回竖屏时会按竖屏的边界收进来，不会记住「横屏
  时那个位置」。
- **「最近」里浏览页的那几条只在文件还在时显示**：文件被删、卡被拔、授权被撤销时它先消失。
- **播放位置跟着文件的绝对路径走**：同一个文件挪到别的目录之后会被当成另一个文件。
- **「最近」里浏览页的条目没有缩略图**：它不是媒体库里的东西，取封面要另外解码一次，
  这一版没做。
- 本版不改变字幕匹配、翻译、语音识别、更新通道的行为。

## 六、升级注意

- `versionCode` **10405 > 10400**，可以直接覆盖安装 v1.4.0 及更早版本，不会提示降级。
- **升级之后不需要做任何事**：浮窗位置沿用你上次拖到的坐标；已有设置、播放记录、
  播放列表、收藏、字幕与译文都会沿用。
- **以前从浏览页播过的文件会自动出现在「最近」里**——记录一直都在，只是以前不显示。
- 想验证第一处修复，直接拖一下浮窗即可；它现在应该跟手。
- 关于页不显示「测试版」徽章（正式版不显示徽章）。
