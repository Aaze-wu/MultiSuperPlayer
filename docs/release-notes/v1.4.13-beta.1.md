# v1.4.13-beta.1 「媒体库」打开得更快了

发布日期：2026-11-01

基于版本：v1.4.12

> 这是**测试版**，可以通过「设置 → 关于 → 检查更新」里的**测试版**通道拿到。
> 想留在正式版就在更新页把通道切回「正式版」。

---

## 一、这一版带来了什么

这一版只做一件事：**让「媒体库」更快出现内容。**

以前打开媒体库，要等应用把你在「浏览」页里授权过的那些目录**整棵树**走完，才会显示任何东西。
目录里文件一多，这段等待就变成转圈。这一版做了两处改动：

| | 之前 | 现在 |
| --- | --- | --- |
| 什么时候才显示列表 | 等授权目录全部扫完 | **先把手机媒体库里的内容列出来**，授权目录扫完再补进来 |
| 扫一个授权目录要问系统多少次 | 每个文件大约 **5 次**（名字、类型、是不是目录、大小、修改时间各问一次） | 每个**目录** **1 次**，一次把这一层的信息全拿回来 |
| 文件很多的目录 | 等待时间和文件数成正比，越堆越久 | 等待时间主要跟**目录层数**有关，跟文件数基本脱钩 |

一句话：**同样是几百首歌，以前要替两万份文件挨个问系统，现在只问文件所在的那些目录。**

## 二、怎么用

装好以后，像平常一样打开「媒体库」，留意从点开到底部出现列表的等待时间。

这一版的改善**只在授权过目录时才明显**——也就是那些你用系统文件选择器加进来的目录。
如果你授权过，请重点拿这些目录做对比；纯粹用手机媒体库里的内容，本来就快，
看不出差别是正常的。

想拿数字的话：「设置 → 关于 → 导出日志」，日志里有一条「扫描耗时」，
写着手机媒体库那半边和授权目录那半边各自用了多少毫秒、各有多少条。

## 三、几点说明

- **能看到的内容不会变少。** 扫描方式换了，但扫出来的结果还是同样的那些文件。
- **没有新增权限，没有新增后台行为**，也没有改动任何设置项和数据格式。
- 这一版的代码与之前的内部预览包一致，真机上确认过改善明显；这次公开出来是收更多设备上的反馈。

## 四、（顺带修正的）

- 修好了「撤掉最后一个授权目录之后，媒体库里还留着那个目录里的条目」。
  以前这些条目会一直在，点开还会报错；现在撤掉就会一起消失。
  这条是改动扫描判据时顺手挖出来的，不是这次专门去查的。

## 五、已知限制

- **还没有做「记住上次的扫描结果」。** 每次冷启动仍然要把两个来源扫一遍，只是这一次
  每一步都便宜很多。要让下一次启动直接出列表，还要再做一次改造，等这版收完反馈再说。
- **授权目录特别大的时候，第一次扫描仍然要时间**（少了，但没有归零）。
  这版把成本从「按文件数」压成了「按目录数」，没有改变「要遍历一遍」这件事。
- 改善幅度**跟设备、存储类型、目录结构有关**，不会是同一个数字。

## 六、升级注意

- 版本号 `1.4.12` → `1.4.13-beta.1`，versionCode **10412 → 10413**，可直接覆盖安装。
- 测试版会同时收到正式版和测试版的更新；不想留在测试版，就在更新页切回「正式版」。
- 不需要重新设置任何东西，之前勾过的文件夹偏好、播放列表、最近播放都照旧。
