## 一、这一版做了什么

**内嵌字幕的「互斥文案」修正**。三处，都是「同一个面板自己跟自己矛盾」那一类问题：

1. **标题位写轨名，不再写语言标签。** 内嵌轨原来走的是通用的「标签 → 语言 → 兜底」取名规则，
   而容器里的内嵌轨通常**没有名字**、语言是 `zh`，于是那一格显示出来的是一个语言标签。
   它既不像「一条字幕」，也回答不了「这是哪一条」。现在固定写成 `内嵌字幕 1`
   （序号从 **1** 开始数，是给用户看的那个），轨自带名字时用它的名字、名字是空白时退回序号。
2. **一条台词都还没读到时的进行时文案。** 摘要行原本只有「格式 · 语言 · 默认 · 强制」。
   内嵌轨是**边播边读**的：第一句台词要等播放头走到有字幕的地方才到，之前面板上只剩轨名和格式，
   看起来和一份**空字幕**一模一样。这一段窗口里补一句 `尚未读到台词`，读到第一句之后它立刻消失。
3. **「片源里有字幕轨，但一条都没挂上」不再说「当前没有挂上任何字幕」。**
   改说 `片源包含字幕轨，请在上面选一条。`——原来那句话是一句**全局断言**，
   用户看到它会认为这个文件里没有任何字幕可用，于是去改字幕文件名，而字幕其实好好的。

## 二、为什么内嵌轨要「先把轨认下来，再等台词」

修正 2 和 3 是同一个根因的两面，所以一定要一起改。

轨道清单在 `onTracksChanged` 那一刻就齐了（候选列表里已经列着那几条轨），
而第一句台词要等播放头走到有字幕的地方才到。中间这段时间以前是这样：

- `embeddedTrack` 仍是 `null`（认领要等第一条 cue 到达），
- 于是同一个面板**上面**写「没有挂上任何字幕」、**下面**列着两条可选的内嵌轨。

实测（`multi.mkv`，40 秒片段、字幕从 23 秒起；`embedded-test.mkv`，字幕从 20 秒起）这个窗口有 **4 秒以上**。
现在改成：

- **只要轨道清单里有一条被内核选中的文本轨，就立刻认领**，不要求先读到台词；
  文档允许为空（`cues.isEmpty()` ⇒ 不造文档），译文状态写成「没有译文」而不是未知——
  「还没有译文」和「有译文但我不知道」是两件事，只有前者是真的。
- **手选内嵌轨同理**：点中那一刻就认领。
- **扫描阶段（`SCANNING` / `READING`）不认领**，扫描结果说了算。
- 认领时**清掉扫描阶段算出来的 issue**：那是「一条都没挂上」时才成立的判断，认领之后它已经过期了。

代价是「认领了轨但还没读到台词」成为**合法状态**，所以必须配套修正 2 的那句进行时文案——
否则界面上会出现「挂着一条字幕、条数 0 条」的静默状态。

## 三、字幕速率：本来在这一版，已推迟到 alpha.3

原计划这一版同时发**字幕速率**（整片越到后面偏得越多时用的比例微调，与时间轴偏移的「整体平移」互补）。
真机实测把它拦了下来，原因**不是速率算术写错了**，而是它撞上一个既有缺陷：

**内嵌轨的 cue 表只覆盖「已经播过」的那一段。** Media3 的 `onCues` 语义是「**此刻**该显示什么」，
它不给未来的行，所以这张表是流式攒出来的；而表尾那条 cue 的结束时间是 `Long.MAX_VALUE`
（`OPEN_CUE_END_MS`——`Cue` 本身只有开始时间，「到现在为止有效」只能用无穷表示）。
速率要把「当前播放位置」乘一个比例再查表，于是查询点会跑到这张表**之外**：

| 场景（`embedded-test.mkv`，每秒一条内嵌字幕） | 速率 | 实际显示 | 应为 |
| --- | --- | --- | --- |
| 00:26 | 1.00× | `第 26 秒的台词` | ✅ |
| 00:26 | 0.90× | **无任何字幕** | `第 23 秒的台词` ❌ |
| 00:37 | 1.10× | `第 37 秒的台词` | `第 40 秒的台词` ❌ |
| 00:37 | 0.96× | `第 35 秒的台词` | ✅（37 × 0.96 ≈ 35.5） |

1.00× 时看不出问题（查询点基本落在最新那句上）。一旦乘上比例：
调大 ⇒ 落在表尾之后，只能退回那条结束时间为无穷的 cue ⇒ **空操作**（读数一动不动）；
调小 ⇒ 落在表起点之前的空档 ⇒ 整句字幕消失。
判定实验：暂停 → seek 到 50 秒 → 立刻 seek 回 10 秒 → 面板显示 `尚未读到台词`
⇒ 表里只有 10 秒前后那一段，50 秒那条 cue 根本不在表里。

（更正：这一节的初版把根因写成「`EmbeddedSubtitleState.receive` 每次只保留刚读到的那一批」，
那句话是错的——`receive` 是**累加**的。上面三行才是真实原因，实测数据本来就没写错。）

所以速率要真生效，前提是**内嵌字幕整轨预读**（把整条文本轨一次读全，而不是只在播放中被动接收）。
那是一个独立改动（后台扫描 `MediaItem` / `Extractor`，或按需 seek 遍历），不该塞进一次文案修正里。
⇒ **这一版只发互斥文案修正**；速率代码（界面 + 状态管线 + 单测）**一行都没丢**，
原样保存在分支 `wip/subtitle-rate-alpha3`（commit `8fd4687`），与整轨预读一起排进
**v0.8.0-alpha.1**（原排 v0.7.0-alpha.3，版号已按用户要求直接升到 0.8）。

速率语义（已在上一轮与用户确认，alpha.3 直接照做，不再讨论）：

- **档位 + 累加都做**：固定档位（0.96 / 0.98 / 1.00 / 1.02 / 1.04）快速选，累加按钮（±0.01 / ±0.10）细调。
- **作用范围与时间轴偏移一致**：换条目归零、不记住。

## 四、真机验证结果

在 `emulator-5554`（Android 17 / API 37，zh-Hans-CN）上，装这一版的 debug 包实测。

| 项 | 结果 |
| --- | --- |
| 内嵌轨标题位 | `内嵌字幕 1` ✅ |
| 还没读到台词时的摘要 | `SubRip · zh · 默认 · 尚未读到台词` ✅ |
| 读到台词后摘要 | `SubRip · zh · 默认`（进行时那句消失）✅ |
| 内嵌字幕跟随播放 | 00:29 画面显示 `第 29 秒的台词` ✅ |
| 时间轴微调 | 点 `+0.5 秒` → 当前值变 `+0.5 秒`；点 `归零` → 回到 `0 秒` ✅ |
| 面板整页无速率痕迹 | 含「语音识别」「字幕时间轴」「字幕样式」「翻译」全段扫描，`速率` / `×` 在视图树里零命中 ✅ |
| 外挂字幕路径未受影响 | `TestClip.mp4` 在 00:12 正常显示 SRT 文本，时间轴区块照常 ✅ |

一条**没能在真机复现**的：「请在上面选一条」需要「片源有内嵌轨 + 一条都没挂上」这个窗口，
而模拟器上「自动选择」是开着的（内核会选中那条 `chi` 轨、立刻认领）。
这句文案由单测 `SubtitleAttachedSummaryTest` 覆盖，真机上只验证了它的「兄弟状态」
（认领成功时的 `内嵌字幕 1` + `SubRip · zh · 默认`）。

## 五、已知限制

- **字幕速率不在这一版**，原因见 §三；它与「内嵌字幕整轨预读」一起交付于 **v0.8.0-alpha.1**。
- **内嵌轨的 cue 表仍只覆盖「已经播过」的部分**：从中间续播（或 seek 到后面再回来）时，
  面板里能用的内嵌字幕只有当前位置之后的段落。这正是 v0.8.0-alpha.1 的整轨预读解决的。
- **内嵌位图字幕（PGS / VobSub / DVB）仍然不列出、不显示、也不解释原因**，排在 v0.9.0-alpha.1。
- 更新系统与后台保活的限制同 v0.7.0-alpha.1（未变）。
