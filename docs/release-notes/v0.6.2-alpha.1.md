## 一、这一版做了什么

v0.6.2 的主题是**多语言支持（日语优先）**。为了让日语真正可用，这一版同时修掉了两个
在验收过程中暴露出来的缺陷：**离线识别的切句**与**字幕解析缓存的命中规则**。

### 1. 离线语音识别支持日语

- 内置模型目录新增**日语离线识别模型**（ReazonSpeech Zipformer，约 169 MB），与原有的
  中文 / 中英模型并列，可分别下载、切换。
- 模型信息（名称、体积）改为**从模型清单读取**并展示，而不是在各处硬编码；引擎类型也
  按清单里的字段判定，新增模型不必再改代码。
- 识别前会明确提示**本次将使用哪个模型**：

  > 将使用「日语离线（ReazonSpeech）」识别，它只认自己训练过的语言。

  这一行是有意加的：用日语模型去识别中文音频不会报错，只会得到一串没有意义的近似发音，
  用户很难自己反应过来是模型选错了。
- 模型下载地址支持镜像（设置 → 语音识别 → 下载地址），国内网络下可用。

### 2. 离线识别的切句修复

**症状**：一段 18.5 秒、清清楚楚分成 6 句的日语录音，识别结果永远是 **2 条**——句子被
并成了两三个大块，字幕时间轴因此毫无用处。

**原因**：语音活动检测（VAD）必须按 **512 采样**（16 kHz 下约 32 ms）的窗口逐步喂入，
模型在内部按窗口维护状态；此前的实现按 16384 采样的大块一次性喂进去，silero VAD 判定
「整块都是语音」，于是整段音频只被切出一两次。

**修复**：新增 `VadWindowFeeder`，把音频严格按 512 采样切窗喂入，并把窗口尾部的不足一块
补齐。同一素材复验：**2 条 → 6 条**，与录音里的 6 句话完全对应。另外两段日语素材
（3 句连读 / 3 句独立短句）也分别从 1 条变为 3 条。

> 这是**所有语言都受益**的修复，不只是日语。

### 3. 字幕解析缓存改为按「地址 + 体积」命中

**症状有两个，根因是同一个**：

- 用「生成字幕」重新识别一遍之后，日志里明明写着 6 条，界面上却仍显示上一次的 2 条；
  **杀掉进程重开应用**才是对的。
- 在应用外把字幕文件改好，回来点「重新扫描字幕」，界面读到的仍是文件修改前的内容。

**原因**：解析结果的缓存键只有文件地址。而「生成字幕」产出的地址是按媒体算出来的、
重跑不变，于是第二次解析直接命中了第一次的结果；「重新扫描字幕」也被同一个缓存吃掉——
用户点它往往正是因为文件刚被改过。

**修复**：缓存键改为**地址 + 体积**（`ParsedSubtitleCache`）。同一地址只保留当前体积那一份，
否则文件被写回旧体积时会端上更早的解析结果；体积拿不到（为 0）时干脆不缓存。

**顺带修掉的一处**：重新扫描后，手动选中的那份字幕要换成**本次扫描**的新对象。旧对象
带着旧体积，会继续命中旧缓存——「手选字幕 + 重新扫描」这条路径同样静默失效。

设备复验（不重启应用）：把同一地址的字幕文件换成另一份（160 B / 3 条 → 268 B / 5 条），
点「重新扫描字幕」，面板当场从 `3 条` 变为 `5 条`；再点「生成字幕」，与日志里的
「生成完成：6 条 / 生成字幕完成：6 条」一致。

### 4. 字幕文本编码：Shift-JIS 兜底

日语字幕在外部工具里另存时经常落成 Shift-JIS（CP932），此前会整片显示为乱码。现在读取时
会检测并**按 Shift-JIS 解码**，同时给出一行可见提示：

> 文件不是 UTF-8，已按 Shift-JIS 解码；若显示为乱码请另存为 UTF-8 再试。

设备上用一份 CP932、无 BOM、3 条字幕的文件复验：条数、三行文本、假名间距都正确。

### 5. 文案与提示词

- 翻译提示词版本提升到 **2**（配合多语言方向的调整）。
- 简中 / 繁中 / 英文三份文案同步新增与修订（模型提示、识别与字幕相关说明等）。
- 「关于」页的**「本版更新说明」正文换成了本版内容**。上一版发布时漏改了它，弹出的仍是
  「首个对外发布的预览版」——而这条文案的源码注释里写着「每次发版都要改这一条」。

### 6. 测试

自动化测试共 **115 个测试套件 / 1410 个用例**，新增 `VadWindowFeederTest`、
`ParsedSubtitleCacheTest`、`TranslationPromptTest`，并扩充了模型目录、识别文本规范化、
字幕编码与字幕选择相关的用例。Debug 与 Release 两个变体的结果一致，全部通过、无跳过。

## 二、安装

从本页 Assets 下载 `app-release.apk`，在设备上允许「安装未知来源应用」后安装。

**如果你装过 v0.6.1-alpha.1，可以直接覆盖安装，不需要卸载、不会丢数据**——本版与上一版
使用同一把签名密钥（指纹见第四节）。播放记录、设置、已下载的识别模型都会保留。

如果你装的是更早的、用 debug 签名自行构建的包，本版**装不上去**，系统会报
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`。这不是缺陷，而是 Android 的保护机制：签名不一致的
包不允许覆盖安装。请先卸载旧版本再安装本版：

```powershell
adb uninstall com.multisuperplayer.player
```

**卸载会连同应用私有目录一起清掉**：播放记录、设置项，以及已下载的离线识别模型
（78～190 MB，需要重新下载）。

### 系统要求

| 项目 | 要求 |
| --- | --- |
| 系统版本 | Android 8.0（API 26）及以上 |
| CPU 架构 | `arm64-v8a` 或 `x86_64` |
| 存储空间 | 基础约 120 MB；使用离线语音识别另需 78～190 MB |

**不支持 32 位设备**（`armeabi-v7a`、`x86`）。这是有意的取舍：把四个 ABI 全打进一个包
会让 APK 无谓地大一倍，而 32 位设备在 2019 年之后已基本消失。如果你的设备装不上，
请开一个 Issue 说明机型。

### 首次使用提示

- **离线语音识别（字幕生成）的模型不打进安装包**：模型单条 78 MB（纯中文）到约 190 MB
  （中英双语），日语模型约 169 MB。入口做成了「先选模型、再下载」，首次使用需要联网，
  之后完全离线运行，音频不会离开设备。
- 在国内网络下，模型下载可换用镜像地址（设置 → 语音识别 → 下载地址）。

## 三、已知限制

- **模型语言不匹配时只做提示，不会自动切换模型**。本版新增了一行提示告诉你「将使用哪个
  模型、它只认自己训练过的语言」，但不会替你换模型：判断音频语言本身需要额外的检测模型，
  而误判之后自动切换的后果（把用户选好的模型换掉）比不换更糟。请自行按素材语言选择模型。
- **中文素材在本版未在设备上重跑验收**。本版改动集中在切句窗口与字幕缓存，两处都与语言
  无关，但上一版验证过的中文素材配方未在本版设备上复验。
- **未提供音视频同步调整**（如音画延迟微调）。字幕时间轴偏移已经具备（播放页 → 字幕 → 同步）。
- **云端语音识别与音频翻译尚未实现**：本版只支持本地模型；云端方案在后续版本中规划。
- **更新检查未提供**：后续版本重新设计。
- 首次下载模型时会校验 SHA-256，校验不通过会重新下载；若反复失败，多半是镜像地址问题。
- 「关于」页的日志导出使用系统文件选择器，部分定制系统（如某些国产 ROM）对该入口的
  权限提示较激进，导出前会再确认一次文件名。
