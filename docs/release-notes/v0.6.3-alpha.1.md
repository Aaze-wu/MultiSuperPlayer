## 一、这一版做了什么

v0.6.3 的主题是**列表排序与播放控制的可用性修复**。三个改动都来自实际使用中
「明明有这个功能、但用起来不对劲」的地方：播放列表排不了序、多选加进去的顺序
不是自己点的顺序、窄屏上播放按钮被压没了。另有一处网络放行，是为了连局域网里的
NAS 与本地模型服务。

### 1. 播放列表可以拖动排序了

**清单页与详情页**（列表里的条目）现在都支持**长按整行拖动**重排，顺序会保存下来，
杀掉进程重开仍然保持。

两处共用同一套手势实现（`core:ui` 的 `ReorderDrag`）：之前播放队列里那套拖动逻辑
被提到公共模块，清单页、详情页、播放队列三处用的是同一份。各写一份的代价不是多几十行，
而是以后改手感（长按要多久、落点要提前几格）只改到其中一处，三个页面拖着不一样，
而那种差异没人会去复现。

**顺序是怎么保存的**：用的是**一个独立的顺序键**（一串 id），而不是给每条列表加一个
「序号」字段。这样只需要改一个地方，且三种不一致全都无害——删掉的列表、还没排过序的
新列表、顺序里重复出现的 id，读取时与实际列表一合并不需要任何特判。因此**列表的存储
格式没有变**，老用户升级后不需要迁移。

**新列表排在最后**：顺序键里没有的列表按创建时间排在已排好的后面。升级前的老用户
看到的顺序与升级前完全一致，直到自己拖动过一次。

设备实测（Android 17 / 1080×2400）：三个列表 A、B、C 中把 A 往下拖到 C 的位置，
顺序变为 **B、C、A**；再把 A 往上拖回顶部，恢复 **A、B、C**；`am force-stop` 重启后
顺序仍然保持。

### 2. 媒体库多选改为按「点选的先后顺序」生效

多选之后点「加入播放列表」，条目按**你点选的先后顺序**追加；点「播放」则以**第一条点选的**
为起点。

**问题在哪**：选择集原先是一个 `Set`。当时它恰好是 `LinkedHashSet`，而「加入一个新的」
恰好会放到末尾，所以「按点选顺序」这条契约在当时的实现下**碰巧**成立。但类型上没有任何
东西承诺这一点——一次看起来无关的重构（比如改用 `intersect`、`minus` 这类集合运算）
就会把它悄悄变成「按屏幕顺序」，而这两种顺序在列表本来就排得整整齐齐时**看起来一模一样**，
只有刻意逆序点选才会发现队列反了。

**修复**：选择集的类型改为 `List`，顺序成为类型的一部分而不是实现细节；同时把「按 id
去查一遍整份列表」改成先建一次索引，全选一个大库时不再是平方复杂度。

### 3. 播放控制行溢出修复

**症状**：在 360dp 宽的手机上，播放页底部那行控制按钮的**最后一个按钮变成一条缝**——
看不出报错、也不崩，就是最后多出一个空按钮，里面有个像逗号一样的点。

**原因**：七个按钮按 Material 的最小可点区域算，天然宽度是 352dp，而 360dp 宽的屏
扣掉两侧 24dp 内边距只剩 312dp。Compose 的 `Row` 遇到子项总宽超限时会把多出来的部分
**全部压给最后一个子项**，于是「全屏」按钮只剩 8dp，里面 24dp 的图标跟着缩成一个点。

**修复**：新增 `TransportLayoutRules`，按这一行**实际拿到的宽度**排版（而不是猜屏幕宽度），
让步顺序固定为：

1. 先收内边距——纯装饰，收到 0 也不影响任何操作；
2. 再缩播放键——它是这一行唯一「小一点还不损失功能」的按钮；
3. 可点区域 48dp 是硬下限，**永远不让**。

第 3 条意味着侧按钮 6 个时这一行的真下限是 336dp。比这更窄的窗口（分屏、或把
「显示大小」拉到最大）无论如何都排不下，这时**如实溢出**而不是把数字凑好看——
那种「算出来放得下、实际还是溢出」的假象正是这个 bug 一开始能藏住的原因。

### 4. 允许明文 HTTP

新增网络安全配置并挂到应用清单：**允许 `http://` 明文连接**。

**为什么**：网络播放、云端翻译、云端识别都要连用户自己填的地址——局域网里的 NAS、
自己跑的本地大模型服务、内网媒体服务器，这些通常就是 `http://192.168.x.x:端口`。
而 `targetSdk` 28 起 Android 默认**拒绝一切明文流量**，表现是「地址明明能通，应用里就是连不上」。

**没有顺带放松的部分**：HTTPS 的证书校验策略**完全保留**（不是「信任所有证书」的
一刀切放行），本版只放开「不加密连接能不能用」这一件事。

顺带删掉了翻译界面里一句已经过期的提示——它原先写着「只有 localhost 与 10.0.2.2 被放行」，
那是旧策略下的说法。现在这句话反过来了：真再出现明文被拦，说明是系统或安全软件在应用
之上又加了一层策略，这时提示的作用是告诉用户「去查那一层」，而不是给一个已经不对的名单。

### 5. 文案

- 「关于」页的**「本版更新说明」正文换成了本版内容**（简中 / 繁中 / 英文三份同步）。
  这条文案的源码注释里写着「每次发版都要改这一条」，上一版就是靠它兜住的。

### 6. 测试

自动化测试共 **117 个测试套件 / 1440 个用例**，Debug 与 Release 两个变体结果一致、
全部通过、无跳过。

新增或迁移的测试：

- `ReorderDragRulesTest`：拖动落点换算的算术（跨过半行才换位、越界钳制、
  落点与起点相同时算不算移动）从 `feature:player` 迁到 `core:ui`——它现在服务
  三个列表，放在任何一个 feature 里都名不副实。
- `QueueReorderDragTest`：播放队列改用公共手势后仍然按把手拖动、并与另外两处共用
  同一套落点规则。
- `TransportLayoutRulesTest`：拿着「352dp 按钮 / 312dp 可用宽度」这组真实数字校验
  「放得下」，并锁住让步顺序与 48dp 硬下限。
- `LibrarySelectionRulesTest` / `BrowserSelectionTest`：扩充了「按点选顺序」的用例，
  包括**刻意逆序点选**这一条（正是这条用例区分了「按点选顺序」与「按屏幕顺序」）。

## 二、安装

从本页 Assets 下载 `app-release.apk`，在设备上允许「安装未知来源应用」后安装。

**如果你装过 v0.6.2-alpha.1，可以直接覆盖安装，不需要卸载、不会丢数据**——本版与上一版
使用同一把签名密钥（指纹见第四节）。播放记录、设置、已下载的识别模型都会保留。

如果你装的是更早的、用 debug 签名自行构建的包，本版**装不上去**，系统会报
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`。这不是缺陷，而是 Android 的保护机制：签名不一致的
包不允许覆盖安装。请先卸载旧版本再安装本版：

```powershell
adb uninstall com.multisuperplayer.player
```

**卸载会连同应用私有目录一起清掉**：播放记录、设置项，以及已下载的离线识别模型
（78～190 MB，需要重新下载）。

### 系统要求

| 项目 | 要求 |
| --- | --- |
| 系统版本 | Android 8.0（API 26）及以上 |
| CPU 架构 | `arm64-v8a` 或 `x86_64` |
| 存储空间 | 基础约 120 MB；使用离线语音识别另需 78～190 MB |

**不支持 32 位设备**（`armeabi-v7a`、`x86`）。这是有意的取舍：把四个 ABI 全打进一个包
会让 APK 无谓地大一倍，而 32 位设备在 2019 年之后已基本消失。如果你的设备装不上，
请开一个 Issue 说明机型。

### 首次使用提示

- **离线语音识别（字幕生成）的模型不打进安装包**：模型单条 78 MB（纯中文）到约 190 MB
  （中英双语），日语模型约 169 MB。入口做成了「先选模型、再下载」，首次使用需要联网，
  之后完全离线运行，音频不会离开设备。
- 在国内网络下，模型下载可换用镜像地址（设置 → 语音识别 → 下载地址）。

## 三、已知限制

- **拖动排序不会自动滚动**。列表比一屏长时，拖到屏幕边缘**不会**自动滚过去，需要先滚到
  目标位置附近再拖。当前实现只处理「视线范围内换位」，加入边缘自动滚动要牵扯到拖动状态
  与列表滚动的同步，留到后续版本。
- **播放列表清单页与详情页的拖动都是「长按整行」**，没有拖动手柄。这是有意选的：
  手机列表行宽有限，再塞一个把手会挤掉标题；长按整行的代价是第一次用需要提示，
  所以列表上方保留了一行「长按条目可拖动排序」。
- **模型语言不匹配时只做提示，不会自动切换模型**。判断音频语言本身需要额外的检测模型，
  而误判之后自动切换的后果（把用户选好的模型换掉）比不换更糟。请自行按素材语言选择模型。
- **云端语音识别与音频翻译尚未实现**：本版只支持本地模型；云端方案在后续版本中规划。
- **不提供音视频同步调整**（如音画延迟微调），**也不再计划**：字幕时间轴偏移已经具备
  （播放页 → 字幕 → 同步），而音视频同步需要重建整条渲染管线，与当前的取舍不符。
- **更新检查未提供**：后续版本重新设计。
- 首次下载模型时会校验 SHA-256，校验不通过会重新下载；若反复失败，多半是镜像地址问题。
- 「关于」页的日志导出使用系统文件选择器，部分定制系统（如某些国产 ROM）对该入口的
  权限提示较激进，导出前会再确认一次文件名。
