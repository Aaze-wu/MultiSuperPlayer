# v1.4.10 顶端的路径与「回到原处」的收尾

发布日期：2026-10-29

基于版本：v1.4.9

---

## 一、这一版带来了什么

v1.4.9 想做的两件事（回到原处、顶端路径停到当前这一层）方向是对的，但**做得不够彻底**。
这一版把剩下的一半做完：

| | v1.4.9 的样子 | v1.4.10 的样子 |
| --- | --- | --- |
| 从子目录返回上一层 | **有时**停在原来那一行，**有时**还是跳回顶上 | 每次都停在原来那一行 |
| 顶端路径的当前层 | 路径一长，当前层还是被挤到右边看不见 | 一定完整露在最右端 |
| 顶端路径里超长的目录名 | 画到屏幕外被**硬切**，连省略号都没有 | 露出「…」，看得出后面还有字 |
| 顶端路径最左边那一层 | 被边缘切成**半个字**（「储」只剩半边，看着像「诸」） | 用一个「…」把它**盖住**，并向右渐隐 |

一句话：**返回上一层真的每次都回到原处；顶端的路径无论多长，当前这一层都完整可见。**

## 二、怎么验证的（这一版连了实机）

上一版发布时说明了「未连实机逐项验收」，这一版补上了。所有结论都在 Android 虚拟机
（`Medium_Phone`，Android 15，1080×2400）上逐项操作并读取界面树确认：

| 场景 | 结果 |
| --- | --- |
| 从 `子文件夹27` 进子目录 → 点左上角返回箭头 | 停在 `子文件夹27` 原来的位置 ✓ |
| 从 `子文件夹18` 进子目录 → 系统返回键 | 停在 `子文件夹18` 原来的位置 ✓ |
| 连续快进快出 3 次 | 每次都回到 `子文件夹19` 原来的位置 ✓ |
| 在 `Movies` 点一个视频进播放页 → 返回 | 停在 `embedded-test.mkv` 原来那一行 ✓ |
| 3 层 / 5 层深目录的顶端路径 | 当前层完整、无半字、无粘连 ✓ |
| 名字超过一屏宽的目录 | 露出省略号 ✓ |

## 三、为什么 v1.4.9 是「有时」而不是「总是」

两处都是**时序**问题，不是漏写了某段逻辑 —— 这正是它表现成「不是百分百触发」的原因：

1. **恢复的位置被自己抹掉。** 新列表刚建好时会先报告一次「我还没滚动，在第 0 行」。
   那不是用户动作，但它和「恢复到我该在的那一行」是两条竞速的路径：谁先落地决定了
   最后留下来的是哪一个。现在的做法是恢复落地之前一律不记录。
2. **顶端路径的「滚到最右端」读到的宽度是占位值。** 界面还没测量时，可滚动量是一个
   表示「还不知道」的极大值，照着它滚等于没滚。现在先等一帧、测量落定之后再滚。

## 四、几句说明

- 只改「浏览」页的列表与它顶端的路径条，**没有新增权限、没有新增后台行为**，
  也没有改动文件格式或数据库。
- 记住的位置仍然**只活在内存里**：退出应用再进来是全新的一次。最多记住 20 个目录。
- 没有开关：这两项修的是「本来就该这样」的行为。

## 五、已知问题（本版未处理）

- **切换底部标签会把当前标签的页面状态整个重置。** 例如在「浏览」里进到某个子目录、
  滚到中途，点「媒体库」再点「浏览」，会回到浏览的第一屏（来源清单），再进那个目录
  是从第一项开始。「最近」「播放列表」同理。这是从 v0.1.0 起就有的行为，与本版改动无关，
  已单独记录，将在后续版本处理。
- 之前列出的其他限制（最多记住 20 个目录、不跨进程、记位置而不是记文件）保持不变。

## 六、升级注意

- 升级后行为立即生效，不需要任何开关，也不需要重新选目录。
