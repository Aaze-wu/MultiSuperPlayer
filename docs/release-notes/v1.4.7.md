# v1.4.7 长句歌词不再藏一截

发布日期：2026-10-28

基于版本：v1.4.6

## 一、这一版带来了什么

这一版只修一件事：**听歌时那句很长的歌词，自动滚动之后总有一截藏在歌词区下面。** 现在它会完整地待在歌词里。

| 修了什么 | 以前的样子 | 现在的样子 |
| --- | --- | --- |
| 一句歌词特别长（折成两三行甚至四行） | 滚完以后只能看到前面一部分，尾巴贴着下沿被切掉，得自己往上滑才能读完 | 自动滚到整句可见：放得下的句子居中，上下都留一点余量 |
| 双语模式（原文 + 译文）时 | 译文那一行更容易被切掉，中文一句配英文一句的时候最明显 | 原文和译文一起算进这一行的高度，一起滚进歌词 |
| 上面两行也是长句、把当前行顶出去 | 当前行可以整行都不在屏幕上，只剩上一句的尾巴 | 按「当前行现在在哪、多高」来滚，回到「这一句整句可见」 |
| 一句长到整块歌词区都放不下 | 居中处理会把开头也切掉 | 顶边对齐，至少从第一个字开始读得到 |
| 短句 | 滚到中间偏上、高亮跟着进度走 | **完全不变** |

既有能力全部不变：点歌词跳转、逐字高亮、字幕与歌词共用一套渲染、拖动进度条之后歌词重新对齐、手指正在滑动时自动滚动不抢——都跟以前一样。

本版没有新增任何系统权限，也没有改变任何设置项的含义。

## 二、怎么用

不需要做任何设置，更新之后就是新行为。

想自己确认一下：

1. 把一段音频（比如 `测试.mp3`）和它同名的歌词（`测试.lrc`）放进同一个文件夹。
2. 在歌词里故意写一句特别长的（三四十个字以上，手机上会折成好几行）。
3. **从应用里的「媒体库」打开这段音频**（不是从系统文件管理器用「打开方式」打开，那条路径不会自动挂歌词）。
4. 播到那句长句前面。看一眼整句是不是都在歌词里——不用自己往上滑。

## 三、几点说明

- **以前是按「第几行」滚的，不是按「多高」滚的。** 旧代码的意思是「让当前行停在歌词上方第 2 行的位置」，这只有在每行一样高的时候才成立。歌词的行高根本不是常数：长句会折行、双语会多一行、当前行还用大一号的字。
- **当前行自己也会变高。** 它一旦成为当前行，字号从正文换成标题级别——同一句歌词在「开始唱」的那一刻会长高一点。按行号算的滚动看不见这个变化，所以越往后越容易差一截。
- **短句没有被牺牲。** 新的算法在「这一句放得下」时给的仍然是居中偏上的位置，观感跟以前一致；只有真的放不下时才改成顶边对齐。
- **手指优先。** 你在滑歌词的时候自动滚动不会把你拽回去，等下一句换行时才自然接上——这条一直是这样，这一版没有动它。

## 四、为什么长句会被藏起来

想象歌词区能显示 8 行。旧的做法是「滚到第 index−2 行」，于是当前行永远落在第 3 行的位置——**按行数**是对的，但一行可能有两层楼高。当前行折成 3 行的时候，它占掉第 3、4、5 行，后面的内容被挤出可见范围；如果那句话折成 5 行，第 6 行以后就整段看不见了。

新做法不再问「滚到第几行」，而是先量出这一行**现在**有多高、现在在哪，再算出「还差多少像素才让它整行待在歌词里」，按这个像素数滚过去。行高变了它就重新量一次，所以折行、译文、字号变化都不会让结果跑偏。

还有一处必须分两步：如果目标行**还没被显示出来**（比如你拖了进度条跳到很远的地方），屏幕上没有任何关于它的尺寸信息，只能先按行号把它带进视野，量完再补上剩下的像素。所以看到的是「一次连续的滚动」，而不是「先跳到某处再挪一下」。

## 五、已知限制

- **竖屏是实机验证过的；横屏和紧凑排版只做到「代码路径相同 + 布局能正常渲染」。** 模拟器的旋转在这个环境里一直没生效（试了四种办法），所以横屏下那句长歌词的实际观感没有用手指确认过。若你在横屏看到异常，把「这一页是不是横屏、是音频还是视频、那一句有多长」写进来就好。
- **自动滚动仍然只在「换到下一句」时发生。** 手动滑开之后，要等下一句开始才会回来；这是刻意的——否则会变成「怎么滑都被弹回当前行」。
- **桌面歌词浮窗（悬浮在其他应用上那一层）这一版没有改**，它有自己的行数与位置规则。
