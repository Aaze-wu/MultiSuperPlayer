# v0.9.0 内嵌位图字幕（PGS / VobSub / DVB）、更新的两条通道、启动时检查更新

发布日期：2026-10-04
基于版本：v0.8.1

---

## 一、这一版做了什么

三件事，一件是「多了一类能画出来的字幕」，一件是「多了一条通道」，一件是「更新的那条
通道自己会响了」。

**内嵌位图字幕。** PGS（蓝光 .sup）、VobSub（.idx/.sub）、DVB 这三种内嵌字幕轨，带的是**图**
而不是字。以前它们会被判成「这条轨读不出来」——面板上什么都不说，用户看不出是片源没有字幕
还是播放器不认。现在它们能画出来了，走的是一条**独立的渲染路径**（见第二节）。

**更新通道分成两条。** 应用内检查更新现在分「正式版」和「测试版」：正式版通道只收不带后缀的
版本，测试版通道两条都收。`alpha` 从这一版起退回「内部构建」，任何通道都不收它（见第四、五节）。

**启动时自动检查一次更新。** 以前「自动检查更新」这个开关**只写不读**——值存进了设置，
但全项目没有一处读它，所以它是个纯装饰。现在它真的生效：程序启动时查一次，有更新就弹窗，
弹窗上三键「立即更新 / 以后再说 / 忽略此版本」；**没有更新什么都不提示**（见第六节）。

---

## 二、位图字幕为什么必须是「另一条渲染路径」

文本字幕在我们这边是**一串字符串**，我们能拿它做任何事：改字号、加描边、整体平移、按比例拉伸、
双语并排、替换成译文。位图字幕是一张**已经画好的图**——字已经在图里了，我们拿到的是像素。

所以它不是「文本字幕的另一种格式」，而是另一种东西：

| | 文本内嵌轨 | 位图内嵌轨 |
| --- | --- | --- |
| 我们拿到什么 | 字符串 + 时间戳 | 一张 ARGB 位图 + 时间戳 + 摆放比例 |
| 谁来摆放 | 我们自己（`SubtitleOverlay`） | Media3 的排版公式，我们照抄（`BitmapSubtitleLayer`） |
| 能改字号 / 描边 | 能 | 不能（图里已经定了） |
| 能翻译 | 能 | 不能（没有字可翻） |

摆放这块**没有自己发明算法**：`BitmapCueLayout` 是 Media3 `SubtitlePainter.setupBitmapLayout`
的逐行移植。理由很直接——这条路径的输入本来就是 Media3 给的 cue，用别人的公式才能保证
「我们画的位置」和「Media3 自己画的位置」一致；自己写一版，差别会以「字幕偶尔偏半个屏」的
形式出现，而且要拿一堆片源才能试出来。

Media3 自带的 `SubtitleView` 仍然是遮着的：它一旦可见，内嵌**文本**字幕就会被画两份
（这是 v0.5.17 修过的问题）。所以两条路同一时刻只有一条在画。

## 三、四个开关刻意不进这条路径

位图轨**认「显示模式」这一个开关**：关掉字幕，位图也跟着清掉（否则会出现「字幕已经关了，
画面底下还压着一块半透明底图」）。其余四项一律不生效：

1. **字幕延迟 / 字幕速率**。那两项是我们在时间轴上做的**位移与缩放**，而位图 cue 由 Media3
   按自己的时间戳直接投递，插不进手。硬做的话得在 Media3 之外再建一条自己的时间轴，等于把
   「谁在管时间」这件事变成两个来源。
2. **字幕样式**（字号 / 行距 / 描边 / 底部距离）。图里的字已经画好了，改这些只会改到我们画的
   那一层边框，看上去像「设置坏了」。
3. **整轨预读**。预读存在的意义是「一次性拿到整张文本表」，对位图轨没有对应物：每一条 cue
   自带它那张图，按时间投递即可。
4. **双语 / 翻译**。没有字可以并排，也没有字可以翻。

**面板会把这几点写出来**，而不是让它看起来像「这条轨读不出来」——「功能没做」和「这条轨坏了」
是两种不同的坏消息，用户需要分得清。

## 四、更新通道：两个通道，三条线

| 版本号 | 是什么 | 正式版通道 | 测试版通道 | GitHub Release |
| --- | --- | --- | --- | --- |
| `X.Y.Z-alpha.N` | 内部构建 | 不收 | 不收 | 不建 |
| `X.Y.Z-beta.N` | 公开测试版 | 不收 | **收** | 建，标记为 Pre-release |
| `X.Y.Z` | 正式版 | **收** | **收** | 建，标记为 Latest |

几条规则值得单独说：

- **判据看 tag，不看 GitHub 的 `prerelease` 勾。** 勾是发布时手填的开关，tag 是构建流程写进
  包里的东西——前者可以忘，后者不会。
- **测试版通道必须收正式版**，否则装了 beta 的人永远退不回来：他得先收到正式版才能回到正轨。
- **alpha 是两个通道都不收的**（第二道闸）。第一道闸是「不建 Release」，这一道防的是
  「哪天顺手建了一个」。
- **切换通道会写进设置。** 手动选过某个通道之后，检查更新不再按「当前版本是不是预发行」
  自动改通道——否则你切到测试版装了个 beta，下次检查会因为「当前是 beta」而自动切回去，
  再之后又因为「当前变成正式版」切回来，来回横跳且没有任何提示。
- **`versionCode` 不随通道变。** `0.9.0-beta.1` 和 `0.9.0` 共用同一个 code（900），这是有意的：
  它们本来就是「同一个版本」，而 Android 只在**降级**时拒绝安装，同 code 覆盖安装是允许的。

## 五、VobSub / DVB 的边界，说清楚

三种格式的解析都由 Media3 负责（`PgsParser` / `VobsubParser` / `DvbParser`），我们没有自己写
解码器。但它们的**前置条件严格程度不一样**：

- **PGS** 是自包含的，实测样本通过；
- **VobSub / DVB** 的画形依赖片源初始化段里的调色板与尺寸（`VobsubParser` 的前置条件相当严），
  拿不到这些信息就画不出来。

所以这两个按「**能用就用、认不出来就当这条轨没有**」处理，而不是让整条轨变成一条永远读不出
内容的「坏轨」。目前有实测样本的只有 PGS。

## 六、启动时检查更新：先修好那个开关

### 「自动检查更新」以前是个装饰品

它把值写进了设置（`DataStore`），界面也正确反映了开关状态——但**没有任何一处代码读它**。
13 处出现，全是「写」和「映射」，零个「读」。症状很隐蔽：界面看着完全正常，关掉开关也不会
有任何变化，因为本来就没有东西在跑。

这类「只写不读的字段」比「根本没有这个字段」更糟：它看起来像功能已经做好了。

现在由 `UpdateRules.skipsAutoCheck(trigger, autoCheck, lastCheckAt, at)` 这个纯函数判定，
`UpdateManager.check(trigger)` 在**发请求之前**先问它，所以关掉之后**一个网络请求都不会发**。

### 两个值，不是三个

触发方式只有 `MANUAL` 和 `AUTO` 两个值。没有第三个「进更新页自动查」的值：界面只有一个开关，
如果「进页面」和「启动」各算一种，就会出现「开关明明关着，进更新页却还是查了」这种在界面上
解释不清的状态。关掉开关 = 这两种自动检查一起关；用户亲手按「检查」永远有效。

### 跳过不等于「已是最新」

被节流跳过时返回 `null`，界面**什么都不改**。把「跳过」当成「已是最新」的后果是：
每次进更新页都把你上次查到的「有新版」擦掉一次——而那是最重要的一条信息。

**跳过那一次不写 `markChecked`。** 否则开关一关一开就把 12 小时窗口烧掉了，重新打开后启动
检查会静默地永远不跑——又一次「看起来正常、实际什么都没发生」。

### 弹窗：三个键，三件不同的事

| 按钮 | 它做什么 | 下次启动 |
| --- | --- | --- |
| 立即更新 | 关弹窗 → 进更新页 → 才开始下载 | 照常检查 |
| 以后再说 | **只关掉这一次的弹窗** | 还会再弹 |
| 忽略此版本 | 记下这个 tag（持久） | 只要还是这一版就不再弹 |

- **「以后再说」刻意不落盘。** 它表达的是「现在不想处理」，而不是「以后都别提」。
  真要「以后都别提」，旁边那个键才是。
- **「立即更新」不在弹窗里直接下载。** 安装器那个 `Intent` 的接收点必须是**常驻的界面**
  （下载完成后要拉起安装器），弹窗一关它的接收点就没了，用户会看到「下载完成」但安装器
  永远不出现。所以先导航到更新页再开始下载——那一套（进度条 / 「安装未知应用」授权 / 重试）
  已经验过了。
- **失败完全静默。** 启动检查失败只写一行日志，绝不弹「网络错误」——用户只是打开了应用，
  没有请求任何东西，不该被一次后台请求的失败打扰。
- **等权限流程走完再弹。** 冷启动时安装权限申请弹窗还没处理完就弹更新弹窗，两个弹窗会叠在
  一起，用户会以为「点了没反应」。
- **只建一个 `UpdateViewModel`。** 它在应用根部创建，显式传给更新页和弹窗。否则
  「更新页拿到的实例」和「弹窗用的实例」是两个（`NavBackStackEntry` 作用域各有一个），
  于是「在弹窗上点了忽略，更新页还显示有新版本」。

### 什么情况下会重复提示

只要还有更新的版本，判定结果就是 `Available`，所以弹窗**可能**每隔 12 小时再出现一次。
这是有意的：v0.9.0 之前根本没有提示，「安静地不再提」比「多提一次」更容易让用户错过更新。
真要安静下来，用「忽略此版本」。

## 七、验证

- **单元测试**：`UpdateRulesTest` 22 条（新增 6 条：手动检查永不被跳过 / 关掉开关后两种自动
  检查都不查 / 开关没关但从未查过时要查 / 12 小时窗口内跳过 / 满 12 小时之后要查（卡边界）/
  时钟回拨不当作已经查过很久），外加位图字幕那一系列的 `BitmapCuesTest`（9 条，`core:player`）、
  `BitmapCueLayoutTest`（10 条，`feature:player`）、`SubtitleStateResolutionTest` +3、
  `SubtitleEmbeddedTrackTextTest` +3、`PlaybackTracksTest` 补位图分支、`UpdateChannelNamingTest`。
- **全量**：155 个测试类 / 2027 条用例，0 失败 0 错误 0 跳过。
- **`assembleDebug` / `assembleRelease`** 通过。
- **模拟器（1080×2400，API 37）实测启动检查的六条路径**：冷启动有更新 → 弹窗出现（标题 +
  版本号 + 说明可滚动且超长省略 + 三键）；「以后再说」→ 只关弹窗、冷启动**又弹**；
  「忽略此版本」→ 更新页显示「已忽略 vX」+「撤销忽略」、冷启动**不弹**；「撤销忽略」→ 恢复
  「有新版本」；**开关关掉 → 冷启动不弹，开关打开 → 冷启动又弹**（这条正是那个装饰开关的
  端到端证据）；「立即更新」→ 跳到更新页且下载已开始。
- 位图那两条渲染路径的**互斥**有专门用例钉住（判的是「关掉字幕」这个开关本身，而不是
  「此刻有没有在画东西」——后者会把「这句和下一句之间的空隙」误判成「字幕被关了」）。

## 八、新增与修改

**新增**

- `core:player`：`BitmapCues.kt`（`EmbeddedBitmapCue`、`BitmapCueSpec`、`CueAnchor`、
  `EmbeddedBitmapState` 与三组转换），把 Media3 的 `Cue` 折成干净的「比例 + 可空」结构
  ——没写过的值保持 `null`，不折成零。
- `feature:player`：`BitmapCueLayout.kt`（照抄 Media3 的排版算法，含 `width / 2` 的整除）、
  `BitmapSubtitleLayer.kt`（Compose 的位图层）。
- `feature:settings`：`StartupUpdateDialog.kt`（启动提示弹窗，三键）。
- `core:data`：`UpdateCheckTrigger { MANUAL, AUTO }`、`UpdateRules.AUTO_CHECK_INTERVAL_MS`
  （从 `UpdateManager` 挪进来，好让判据是纯函数、可单测）、`UpdateRules.skipsAutoCheck(...)`。
- `docs/release-process.md`：发版流程（三条线、两个通道、发完要核对的四件事）。

**修改**

- `app/build.gradle.kts`：版本号 `0.8.1` → `0.9.0-beta.1` → **`0.9.0`**。`versionCode`、
  `BuildConfig`、关于页显示的版本号全部由这一处推导（`versionCode` 仍是 900，与 beta.1 相同）。
- `UpdateManager.check(trigger)`：接住触发方式并在发请求前判定是否跳过；节流常量迁至 `UpdateRules`。
- `UpdateViewModel`：新增 `startupPrompt`（与 `availability` 分开，否则「以后再说」会连
  「有新版本」一起擦掉）、`checkAtLaunch()`（失败静默）、`dismissStartupPrompt()`、
  `ignoreStartupPrompt()`。
- `MspApp`：在应用根部建**唯一一个** `UpdateViewModel`，权限流程结束后调用 `checkAtLaunch()`，
  并挂上启动提示弹窗。
- `PlaybackTracks.kt`：位图 MIME 判定排在最前，新增 `isBitmapRenderable`；
  自动挑选顺序不变（文本轨仍优先）。
- `ExoPlayerController.kt`：接住位图 cue（`onCues` 里先收位图再提前返回），切集时清空。
- `SubtitleViewModel` / `SubtitleUiState`：透传位图 cue，并在「显示模式 = 关」时清空。
- `SubtitleIssueText` / `SubtitleFormat`：DVB 的格式名与位图轨的说明文案（三语齐全）。
- 更新页：通道选择与文案（三语齐全）；自动检查开关的说明改成「每次启动时查一次，进这一页
  也会查一次，最快 12 小时一次」（三语齐全）；关于页：测试版徽章。

## 九、已知限制

1. **位图字幕的延迟 / 速率 / 样式 / 双语 / 翻译一律不生效**，这是刻意取舍不是没做完（第三节）。
2. **VobSub / DVB 只在片源带够初始化数据时才画得出来**，目前有实测样本的只有 PGS（第五节）。
3. **封面仍是自动取的**，没有「手动换一张」的入口。
4. **更新提示可能每隔 12 小时再出现一次**，只要还有更新的版本（第六节末尾）。
5. 32 位设备仍然装不上（ABI 只保留 `arm64-v8a` / `x86_64`，与上一版相同）。
