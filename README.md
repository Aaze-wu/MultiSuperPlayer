# MultiSuperPlayer

一个 Android 本地音视频播放器，重点在**字幕/歌词系统**与**字幕翻译**。

- 语言：Kotlin + Jetpack Compose（Material 3）
- 播放内核：AndroidX Media3 (ExoPlayer) + NextLib FFmpeg 软件解码扩展
- 最低支持：Android 8.0（API 26）
- 当前版本：**0.9.0**（正式版）
- 许可证：[GPL-3.0](LICENSE)

发行说明：[docs/release-notes](docs/release-notes/)

English documentation: [README.en.md](README.en.md)

---

## 一、功能特性

### 1. 播放（基础目标）

- **格式覆盖**：容器格式由 Media3 的解复用器负责，编码格式不够用时自动回退到
  NextLib 自带的 FFmpeg 软件解码器；也提供「强制软件解码」开关给少数解码器误判的片子。
- **画面比例**四档：适应 / 裁剪 / 拉伸 / 原始。播放页里改的是**临时覆盖**，不写回设置。
- **手势**：左半屏上下滑调亮度、右半屏上下滑调音量、左右滑动找进度、双击两侧 ±10 秒。
- **倍速**：0.25×~4× 共 10 档；长按屏幕可临时切到「长按倍速」。
- **A-B 循环**：三态（设 A → 设 B → 清除）。
- **均衡器**：开关 + 8 条内置预设（平直 / 低音增强 / 高音增强 / 人声 / 摇滚 / 流行 / 爵士 / 古典）
  + 5 根增益滑块（±12dB，与设备上报范围取交集）+ 一键恢复默认；拖动时声音实时跟着变。
  曲线按频率存，所以换一台设备还是同一条曲线；建不出效果的设备（模拟器等）会明说「不支持」。
- **续播**：音视频都记；看到 95% 视为看完，**下次从头播**（记录不再删掉，所以「最近播放」里还看得见）；
  不足 15 秒只记「播过」、不记位置。
- **两个开关分开**：「记住播放位置」管「位置写不写」，「记录最近播放」管「列表里会不会多出新条目」。
  四种组合都有意义（这是两个独立选择，不是同一位的两个名字）：

  | 记住播放位置 | 记录最近播放 | 结果 |
  | --- | --- | --- |
  | 开 | 开 | 默认：记住位置，播过的都会进列表 |
  | 开 | 关 | 位置照记（接着播不受影响），所以看过一段的内容仍会留下续播记录；「只表示播过」的空条目不再产生，已有条目也不再刷新时间戳 |
  | 关 | 开 | 每次从头播，但**看得见看过什么**（位置一个字节都不写） |
  | 关 | 关 | 都不记 |

  第三条靠的是「记播过」和「写位置」是两个动作（`markPlayed` 保住已有位置、只推时间戳），
  共用一个写入就永远做不到。
- **全屏与锁定**：沉浸式全屏 + 横屏布局 + 误触锁屏。
- **横屏音频有自己的一套版面**：左边封面与曲目信息，右边歌词。屏幕够宽（≥ 711dp）时功能芯片与传输控制
  搬进左栏封面底下，右栏整栏留给歌词（只剩进度条）；不够宽（分屏、小屏老设备）才退回「控制条压在歌词底下」。
  音频没有画面可挡，所以约束正好和视频相反——控制条是**常驻**的，不做成会自动淡出的浮层，
  也就不存在「淡出之后再也唤不回来」（横屏音频没有手势层，浮层淡出就真的没了）。
  没有歌词时那一栏会说清是哪一种：正在加载 / 已关闭 / 暂无歌词 / 加载失败，并给一个去选字幕的入口。
- **竖屏留足歌词**：音频页那几段（封面 / 标题 / 进度条 / 功能芯片 / 传输控制 / 会话芯片）**都是定高的**，
  只有歌词拿剩下的，所以屏幕一矮先被挤掉的总是歌词。规则改成「**谁让位**」写死：空间不够先缩封面
  （上限 112dp，缩到 < 32dp 就整个不画，连那道空隙一起收掉），歌词保底 200dp；
  歌词区被压到 260dp 以下时把歌词自己的内边距从 24dp 收到 16dp / 8dp（换回来半行），**字号不变**。
- **明确的出口**：竖屏画面左上角的「收起」是看得见的退出入口——系统返回手势之外还有一个
  写了字的按钮，不必靠猜（横屏那边左上角是「退出全屏」，不重复摆第二个）。收起只弹掉播放页，
  播放继续，底部换成迷你播放器。
- **多音轨选择**：片源里有多条音轨时，控制栏下方多出一个「音轨」芯片（写着当前那条音轨的名字/语种），
  面板里可以逐条切换，也可以切回「自动」。这条选择**只对当前这个文件有效**，换一个文件就回到自动——
  否则上一个文件选的音轨会跟到下一个文件，而屏幕上看不出它已经被手动改过（与手选字幕不被记住是同一个理由）。
- **其他**：随机/列表循环/单曲循环、上一首/下一首、音量与亮度指示、播放服务与通知栏控制。

### 2. 歌词与字幕（基础目标）

- **解析格式**：SRT / WebVTT / ASS / SSA / LRC / 增强型 LRC（逐字）/ TTML(DFXP, SMPTE-TT) / VobSub / PGS。
  未支持的格式不会瞎猜——注册表会给出「格式判定为 X 但内容更像 Y」这类可读的诊断。
- **自动发现与关联**：按媒体**来源**分三条路找同目录字幕，然后按文件名相似度、语言标记、`forced` 标记等打分选出最合适的字幕；同分时按尾部标签数量等规则稳定排序。
  - 媒体库条目：查系统媒体库的相对路径；
  - SAF 授权目录里的条目：问 SAF provider 要兄弟目录（`.nomedia` 目录、媒体库看不见的文件都算在内）；
  - 内置文件选择器打开的条目：**直接列磁盘目录**（连后缀不在索引里的 `.lrc`、`Download/` 根都算在内）。

  三条路的判据是**来源本身**，不是「哪个字段恰好有值」——如果看字段，文件浏览器进来的条目会被当成媒体库条目，然后安静地一个字幕也找不到。
- **编码兜底**：非 UTF-8 字幕按候选编码逐个尝试，并在解析告警里说明用了哪一种。中文按 GB18030 兜底；
  日语字幕常见的 **Shift-JIS（CP932）**另有单独一条判定，而且**不是**「候选表里排前面的先试到就算」：
  先拿 GB18030 的结果当基准，只有 Shift-JIS 解出来的文本**更像日语**（假名与汉字变多、半角片假名与私用区变少）
  才采用——否则两个都是双字节编码，谁先试谁赢，GBK 的中文字幕会被日语抢走。
  已知取舍：**一个假名都没有、全是汉字**的日语仍会落到 GB18030（两种编码都解得通，没有判据可选）。
- **显示模式**：隐藏 / 仅原文 / 仅译文 / 双语。
- **不显示空白**：选了「仅译文」而这份字幕没有译文时，自动降级显示原文**并给出原因**，而不是画出一片空白让用户以为字幕坏了。
- **人工修正**：任意一行译文都可以手改，修正内容单独持久化，重新翻译不会被覆盖。
- **手动指定字幕**：字幕面板里有一个「选择字幕文件…」按钮，走系统文件选择器任意位置挑一个文件。
  这条路的候选是**满分**（用户点的就是它，不需要猜「名字像不像」），所以它排在自动找到的候选前面。
  手选的字幕**不记住**：换一部片子就回到自动选择——否则上一部选的字幕会跟到下一部，
  看起来像「字幕错位」，而且用户没有任何地方可以看出它已经被手动改过。
- **片源自带的字幕**：**容器里内嵌的字幕轨**和同目录的字幕文件一样，会被接进**我们自己的字幕层**，
  所以显示模式、双语、翻译、时间轴微调对它一视同仁。
  内嵌轨与候选文件并列显示在同一张面板里，标着语种、格式、是否默认/强制。
  `PlayerView` 自己还带着一个 `SubtitleView`，`setPlayer()` 之后它会一直跟着 `onCues` 把同一批 cue
  再画一遍。播放页因此把那一层显式设成 `GONE`：不遮的话内嵌字幕在屏幕上是**两份**（错位叠在一起，
  看着像重影），而且显示模式选「隐藏」也藏不住它。外挂字幕不走 Media3 的解析器，不受这一点影响。
  格式取自 `Format.codecs` 而不是 `sampleMimeType`：Media3 会把**从容器里解出来的文本轨**统一报成
  `application/x-media3-cues`，真实格式（`application/x-subrip` 等）放在 `codecs` 里。
  照 `sampleMimeType` 判会把它们判成「未知格式」，然后整条轨在面板里**消失**——
  而顶部那行「已自动选中「zh」」照旧显示，两边自相矛盾。
  上面这一整套（显示模式、双语、翻译、时间轴微调、速率、样式）只覆盖**文本**内嵌轨：
  位图内嵌轨（PGS / VobSub / DVB）带的是图、没有字，走的是**画在画面矩形上的位图层**，
  所以除了「显示模式」之外的那些开关对它都不生效——理由与代价见第五节第 12 条。
- **字幕时间轴微调**：±0.1 秒 / ±0.5 秒可累积，另有「归零」。正数表示字幕**晚出现**
  （字幕比声音早了就往正数调）。微调只整体平移时间轴，**不改变**每句台词的长度。
- **字幕速率（比例微调）**：0.96× / 0.98× / 1.00× / 1.02× / 1.04× 五档，另有 ±0.01 / ±0.10 的累加细调，
  可调范围 0.90×~1.10×。与时间轴微调是**两件事**：那个是整体**平移**（全片每句都早/晚同样多），
  这个是按**比例缩放**——片子越到后面偏得越多时用它（片源和字幕帧率对不上）。用平移把开头调准，
  就一定会把结尾调错，这种偏法只有速率能修。同样只管这一次播放：换条目回 1.00×（与时间轴微调一致）。
- **片源内嵌字幕可以整轨预读**：容器里那条文本轨会被**后台完整读一遍**，拿到的是**整张**台词表，
  而不是「播到哪算哪」。于是切进片子立刻就有字幕，速率也才有完整的依据（见上一条）。
  读不出来（网络流、位图字幕、认不出的容器）会**静默退回**原来的流式表——预读只是更好的那条路，
  不是唯一的路。面板上会写明状态：读的时候是「正在预读字幕…」，失败时是「预读字幕失败，速率调整可能不准」。
- **字幕样式**：字号（小 / 标准 / 大 / 特大）、行距（紧凑 / 标准 / 宽松）、描边（无 / 细 / 标准 / 粗）、
  底部距离（贴边 / 标准 / 抬高 / 很高）四组档位。**播放页字幕面板**与**设置页「字幕与翻译」**两处都能改，
  两边共用同一份设置、改完立即生效并全局记住；另有「恢复默认样式」一次把四项复位。
  恢复走的是一次事务，而不是连发四个写入——后者一旦中途失败会留下「一半默认、一半自定义」的状态，
  而界面上看不出哪一半没写成。用档位而不是连续滑块：滑块上没有任何一个刻度有资格叫「默认值」，
  用户也不敢随便拖，而且事后没人能解释存进去的「1.37 倍字号」是从哪来的。
  **四组默认档位换算出来的数字与 v0.5.15 写死的渲染参数逐项相同**（16sp 字号 / 24sp 行高 / 无描边 /
  底部 12dp），所以升级之后没人会看到字幕突然变了样子——这条由单测守着。

### 3. 字幕翻译（进阶目标）

- **任意 OpenAI 兼容服务**：填服务地址、模型名、API 密钥即可；内置若干常见服务商预设，也可完全自定义。
  其中 **Ollama 预设默认指向腾讯混元的翻译专用模型 `demonbyron/HY-MT1.5-1.8B`**（33 种语言）——
  字幕翻译用不上「世界知识」，要的只是逐行忠实；拿通用 8B 模型去干这件事，用户付出 5 倍显存、
  5 倍等待，换回来的没有一样是他需要的。
- **15 门目标语言**：简体中文 / 繁體中文 / English / 日本語 / 한국어 / 俄语 / 西班牙语 / 法语 / 德语 /
  葡萄牙语 / 意大利语 / 阿拉伯语 / 泰语 / 越南语 / 印尼语。不是 33 门也不是 5 门：可选清单不等于
  模型能力上限，每加一门要配 3 套文案加 1 条示例，所以取「使用频率 × 可验证性」的交集。
  示例跟着目标语言走：译法语就示范 `Où vas-tu ?`（法语在 `?` 前要留一格）、译阿拉伯语就示范 `؟`、
  译泰语就示范「不加句号也不加空格」。
- **也可以完全不联网**：服务商列表里另有一项「本地（设备上运行）」，模型跑在这台手机上，
  字幕内容不离开设备（见第九节）。
- **批量翻译 + 缓存**：按行分批、带上文语境、带术语表；结果按「内容 + 目标语言 + 模型」哈希缓存，重复内容不重复付费。
- **术语表**：人名/专有名词先替换成占位符再交给模型，避免模型擅自改写，译后还原。
- **提示词里的示例跟着目标语言走**：那段「输入 / 输出」示范是按目标语言现算的（译日语就示范日语、
  并示范「一行里两个人对话要保留分段」），而不是不管目标语言都示范中文。模型是照抄示例的：
  示例是中文，它就稳定输出中文——不报错、不解析失败，只是悄悄译错语言，看起来像「模型能力不行」。
  目标语言清单与示例在编译期一对一绑定（加了语言不补示例，编译不过）。
- **失败可诊断**：把失败分成「没配置 / 未授权 / 额度用尽 / 限流 / 被拒 / 服务端错误 / 网络 / 响应不合法 / 空回复 / 被截断」
  这些**各自有不同处理方式**的类别，界面给的是能真正执行的动作，原始报错可以展开看。
- **只重试失败的行**：整批失败不会让成功的行白翻一遍。
- **导出**：SRT / ASS，仅译文或双语，文件名带目标语言代码。

### 4. 界面与主题（进阶目标）

- **主题基底**：跟随系统 / 浅色 / 深色 / 纯黑（OLED）。
- **取色来源**：系统动态取色（Android 12+）/ 从封面取色 / 固定强调色（6 种预设）。
- **深色与纯黑的差异**在真机上才看得出来：纯黑是纯 `#000000`，为 OLED 省电与对比度服务。
- 主题是**整棵树一起换**而不是只换自己画的控件：`MspTheme` 在最外层把底色调色板（`ColorScheme`）
  和强调色一起往下发，所以 `Scaffold`、对话框、下拉菜单、滚动容器不会漏出白色底。

### 5. 多语言（本项目已完成）

- 支持**跟随系统 / 简体中文 / 繁體中文 / English**，应用内即可切换（设置 → 外观 → 语言）。
- 简体中文是资源兜底语言（住在 `values/`），另外两种各自有 `values-en/`、`values-b+zh+Hant/`；
  系统语言不在支持列表里时回落到简体中文。
- Android 13+ 会把这些语言注册给系统，于是**系统设置里的「应用语言」也能改**，两边不会不一致。

### 6. 媒体库与播放列表

- **五个标签**：媒体库 / 浏览 / 最近 / 播放列表 / 设置。「正在播放」不再是标签，而是一个**真正的页面**——
  返回键能回到你进来的那个列表，而不是把整个应用退掉。
- **迷你播放器**常驻在导航栏上方（播放页里不显示）：点它回到播放页，点暂停键就地暂停，
  左右两边的上一首 / 下一首**就地切歌、不跳页**（只想换一首不用先回到播放页）。
  上面那条进度线是**唯一**订阅播放位置的控件（200ms 一次），所以整页列表不会跟着每秒重绘。
  这两个键**不做灰置**：当前播放状态里没有「有没有下一首」这个信息，而猜错（灰着却切得动、
  或者亮着却点了没反应）比一直可点更糟——真的到头了，切走就是停在原地，不会有副作用。
- **视图选项**：列表 / 网格；排序 6 种（标题升 / 标题降 / 最新 / 最早 / 最长 / 最大）；
  分组 4 种（不分组 / 艺术家 / 专辑 / 文件夹）。分组头**始终按标题排序**，不跟着排序方式抖；
  分不出艺术家/专辑/文件夹的条目归一为「未知」并永远排最后。
- **封面**：列表行、网格瓦片、播放页（竖屏圆形封面 / 横屏左栏）**共用同一套取图规则**。音频取文件里
  内嵌的那张（Android 10+ 上优先问系统媒体库要缩略图，这样不必把整个文件读进内存），视频取内嵌封面、
  没有就按**时长 10%** 抽一帧；那一帧太暗（平均亮度低于 0.12）就退到 40% 再试一次，两次都暗就**用最后那张**
  ——一张黑封面至少还能认出是哪一片，什么都不画用户会以为功能没生效。取到的图压到最长边 512px 后写进
  私有目录的磁盘缓存（键按「类型 + 文件」算，重复进列表不会重新解码），同时最多解 2 张；取图失败一律安静
  退回类型图标，绝不让列表因此出错。取不到图时垫在底下的图标**沿用该行本来那个颜色**：可播放的文件紫色、
  字幕紫色、压缩包与文本等灰色——颜色本身就在说「这个能不能点」。
- **多选**：长按进入选择模式，可全选 / 取消全选 / 加入播放列表 / 直接播放。操作按**点选的先后顺序**
  生效——「加入播放列表」按这个顺序追加，点「播放」以第一条点选的为起点，逆序点选得到的就是逆序队列。
  重复条目会被跳过，并且**如实告诉你跳了几个**（「已加入 10 项，另有 1 项已经在列表里」），
  而不是静默变成 10 项。**内置文件选择器里也是同一套多选**（见第七节），两边共用同一条操作栏。
- **SAF 文件夹浏览**：用系统的目录选择器授权文件夹并持久化。授权目录的内容会与系统媒体库**合并**
  显示，按「相对路径 + 文件名 + 大小」去重，所以同一个文件不会出现两次；SAF 条目的标识符带
  `saf:` 前缀，与 MediaStore 的数字 id 不可能撞车。扫描有四条护栏（最大深度 8 层、最多 20000 条、
  只认音视频扩展名、同一目录不重复进入），避免个别畸形目录把扫描拖死。
- **SAF 目录里的字幕照样能找到**：在 SAF 授权范围内播放时，同目录的字幕文件会被枚举出来参与打分——
  即 `.nomedia` 目录里、系统媒体库根本看不见的媒体，字幕也不会漏。
- **最近播放**：来自续播记录（位置 + 时间），最多 50 条；点进去从上次的位置继续，而不是从头。
- **不确定位置也要留在列表里**：看了几秒就退出的条目**位置记 0，但记录留**，列表里写成
  「上次播于 … · 不记位置」而不是「播放到 00:00」——「不值得当续播点」和「没播过」是两回事，
  早期版本把两者挤成同一个分支，短媒体在「最近播放」里永远不出现。
- **在设置里可以关掉**：关掉后不再记新内容，**已有的记录不会被删**（否则这个开关就是一次不可逆的
  删除，而用户点它时想的是「别再记了」）。关掉时「最近播放」页会说明是开关关着，而不是装作列表为空。
- **可以删单条、也可以清空**：每行右侧的 ✕ 删掉那一条（顶部工具条的清空虚线图标清空全部，
  会先弹确认框）。**删掉一条播放记录 = 连它记住的续播位置一起忘掉**，因为这一行**本身就是**续播记录；
  删完顶部会给出「撤销」，撤销是把原记录**连原时间戳一起**写回去，所以它在列表里的位置不会变。
  清空时说明里同时讲清两件事：续播位置会一起忘掉（下次从头播），**媒体库里的文件不受影响**——
  「删了什么」和「没删什么」必须一起说，否则用户会以为清空等于删文件。
- **播放列表**：存的是「id 主键 + 显示快照（标题 / 艺术家 / 时长）」。库暂时扫不到某个文件时，
  条目**不会凭空消失**，列表里会标明它当前不在库中，但队列里的位置保留 ——「库查不到」不等于「放不出来」。
  上限是 100 个列表、每个 5000 项、名称 80 字；达到上限时新建会被拒绝并说明原因。
  从播放列表恢复出来的条目，来源按 id 前缀（浏览器条目带 `file:`）判定，所以「从播放列表里放的文件」
  仍然能找到同目录字幕——不然它会按媒体库去查，然后在「无法确定这个文件所在的文件夹」上碰壁。
  「这条还在不在」也是**分来源判**的：先查媒体库；库查不到而 id 带 `file:` 前缀的（浏览页加进来的），
  就按它自己记下的绝对路径去文件系统确认一次。只查库会把**每一条**浏览页条目都误标成「文件已不在」，
  而媒体库本来就不收录这些路径。文件系统探测失败一律算「不在」（宁可多标一条，也不要把删掉的文件说成还能播）。
- **播放列表可以拖动排序**：清单页里的列表本身、以及某个列表里的条目，都是**长按整行**拖动重排，
  顺序会保存（杀掉进程重开仍保持）。清单的顺序单独存成一串 id，**不写进列表本身**，
  所以存储格式没变、老用户升级不需要迁移；顺序里没有的列表按创建时间排在后面，也就是**新建的列表排最后**。
  **拖到列表上/下边缘附近时列表会自己滚**（离边缘 72dp 内启动，越贴边越快，最快约一秒一屏），
  所以比一屏长的列表也能一次拖到底。滚动是按「速度 × 这一帧的真实间隔」算的，不是每帧固定像素
  （否则 120Hz 的机器会滚快一倍）；真正滚掉多少会记进落点计算，不会出现「列表滚了、落点却没动」。

### 7. 内置文件选择器

系统的 `ACTION_OPEN_DOCUMENT` 只让用户在**授权过的位置**里挑文件，而 Download、存储卡根目录这类地方
系统根本不给授权。所以「浏览」标签里除了 SAF 授权目录，还有一个**内置的文件选择器**：它自己列目录，
不经过系统的文件选择器。

- **两条来源并列**：`内部存储` 与 `存储卡`（需要「所有文件访问」权限），以及每一个 SAF 授权目录。
  每条来源都带一句**状态说明**，权限不对时说的是「未开启，点这里去系统设置开启」而不是一句干巴巴的失败。
- **权限是显式的、可选的**：「所有文件访问」（`MANAGE_EXTERNAL_STORAGE`）**默认不开**，也**不在首次启动时请求**。
  它归设置页的「权限」页管：那一页把应用能申请的四项（媒体读取 / 所有文件访问 / 通知 / 蓝牙）
  连**状态**（已允许 / 只允许了一部分 / 未开启 / 已被拒绝 / 本机不支持）和**动作**一起列出来——
  能就地弹系统框的直接申请，需要跳系统页的跳系统页，**已经被系统拒绝过的给的是「去设置」
  而不是一个按了没反应的「申请」**。页而下那一段折叠区列出六条**安装即授予、应用自己关不掉**的
  权限（网络、前台服务等），列出来是为了让人看到这个应用一共申请了什么。
- **首次启动申请一次**：安装后第一次打开会依次申请**通知**与**媒体读取**（音乐和音频、照片和视频），
  「所有文件访问」与蓝牙**不在这批里**。之后不再自动弹框——系统在用户拒绝后本来也不会再弹，
  再弹就是骚扰。从系统设置页返回时**自动刷新**状态，不会停在旧结论上。
- **面包屑导航**记的是**来路**而不是现算的路径：从 SAF 目录进去再往回走，走的是同一棵树的同一条链，
  不会因为路径拼接规则不同而在中途跳到一个不存在的位置。
- **目录内排序 4 种**（名称升 / 名称降 / 最新 / 最早）+ 显示隐藏文件。**目录始终排在文件前面**，
  与所选排序无关。
- **单目录上限 5000 条**：超过就截断，并且**如实说明截断了**，而不是安静地少给几条。
- **点可播放文件**：队列取**当前目录里所有可播放的条目**（不是整个媒体库），点哪个都从那个文件开始。
- **多选**：长按任意一行进入选择模式，可全选 / 取消全选 / 加入播放列表 / 直接播放（与媒体库同一条操作栏）。
  能选的只有**可播放的文件**：目录和字幕文件照常显示，但复选框是禁用的——
  它们本来就不进队列，选中了也没有下一步动作可做。选择模式里点一行是**勾选**而不是进目录，
  返回键先退出选择模式（而不是退到上一级目录）。进入另一个目录时选择自动清空，
  因为选中的是「这个目录里的这几个文件」。
- **点字幕文件**：`.srt` / `.ass` / `.ssa` / `.vtt` / `.lrc` / `.ttml` / `.dfxp` 等不会进播放队列，
  而是被当成**外挂字幕直接挂到当前播放的视频上**——这正是「手动为某个视频指定字幕」这条路的入口。
  手选的字幕**不依赖目录扫描**，所以即使自动找字幕的条件不成立，它照样能被挂上。
- **不写媒体库**：浏览只是浏览。用它打开的文件不会因此进媒体库、也不会进「最近播放」。

> 目录行显示的是**带后缀的原名**（`Movie.zh-CN.ass` 就显示 `Movie.zh-CN.ass`），因为这个列表的用途
> 是让人找到具体那一个文件，这时候后缀和语言标记恰恰是最重要的信息。

**同目录字幕照样自动发现**：从这里打开的媒体会**直接列它自己所在的那个目录**找字幕
（不经过系统媒体库——这条来源存在的理由正是「媒体库看不见的地方」）。于是 `Download/` 根、
`.nomedia` 目录、存储卡里的音视频都能自动找到同名的 `.srt` / `.ass` / `.lrc`。
需要「所有文件访问」权限：**读不到目录时说的是「读不到这个文件夹」，而不是「这个文件夹里没有字幕」**
——两种情况的下一步动作正好相反（一个去开权限，一个去改名）。

### 8. 本机离线语音识别字幕生成（高级目标）

不联网、不上传音频，用本机算力把音轨转成字幕；生成的文件直接进字幕面板并**自动选中**。

- **三个模型可选**：中文离线（Paraformer 小模型，约 78.1 MB）、日语离线（ReazonSpeech，约 169.0 MB）、
  中英双语流式（Zipformer，约 189.8 MB）。体积与用途写在选项上；**只下载选中的那一个**，别的不会顺手被拉下来。
  日语那个是**日语专用**的整段解码模型：中文和英文都识别不出来，反过来在日语上比流式模型更准——
  这个取舍写在选项的说明里，不是让用户自己去试。
- **下载源可改**：默认走国内镜像 `hf-mirror.com`，填 `https://huggingface.co` 就是官方源，**留空即回到默认源**。
  地址只提示不拦截：写得不对劲时标红并说明要以 `http://` 或 `https://` 开头，但不禁止点「下载」——
  镜像站是不是活的只有网络库知道，前端做格式校验判不出来。
- **逐文件校验 sha256**：对不上按「校验失败」处理，并把已经下到的那半截删掉，
  不留一个「看着下好了但装不上」的模型。
- **可以只删模型**：删除只清这个模型的那几个文件，**已经生成的字幕一个都不受影响**
  （确认框里就是这么写的，真机验证过）；VAD 切分模型是**共用资源**，删模型时留着不动。
- **识别全程离线**：音频不出本机。
- **日语结果不留假名之间的空格**：ReazonSpeech 是**逐字**输出的，直接落盘会得到「こ ん に ち は」。
  后处理只折叠**假名与假名之间**的那个空格；假名与空格与英文之间（`こんにちは world`）照旧保留，
  否则会把正常的词间空格一起吃掉。
- **失败原因分开说**：「这个文件里没有可用的音轨」/「没有识别到人声」/「字幕已识别出来，但没能保存」/
  「解码失败」——四者的下一步动作完全不同（换文件 / 换一段有人说话的音频 / 清存储空间 / 换片源），
  挤成一句「识别失败」就等于没解释。
- **边解码边识别，不落中间文件**：33 秒素材的中间 wav 就是几 MB，长片会到 GB 级；
  整段只构造**一个**引擎实例（构造一次要几秒，逐段重建比识别本身还慢）。
  进度按**已处理采样点**上报，所以进度条显示的是「已处理 / 总时长」，而不是一个永远转圈的圈。
- **生成物放哪里、叫什么**：文件落在应用私有目录 `files/generated_subtitles/<媒体地址哈希>.srt`；
  面板里显示成 `<片名>.asr.srt`、标「本机识别 · SubRip」并**自动选中**——
  生成完还要用户自己去列表里翻一遍，等于「生成好了」这句话没说。
  存私有目录的取舍（写片子旁边更通用，但媒体库条目只有读权限）与「文件名用哈希不用片名」的理由
  （片名里有 `/`、`:`、空格，还会重名）见 `GeneratedSubtitleStore` 的 KDoc。
- **不覆盖任何东西**：写的是新文件，同目录原有的外挂字幕与容器的内嵌轨一个都不动。

### 9. 本机离线翻译（设备上运行）

设置 → 字幕与翻译 → 服务商列表里的**「本地（设备上运行）」**。与云端那几家并列，
但**一次都不出网**：不需要服务地址、不需要密钥，字幕内容不离开手机。

- **模型按需下载**：默认那档是 **Qwen3-0.6B（int4 量化，约 345 MB）**，默认走国内镜像 `hf-mirror.com`，
  下载完成后**校验 sha256**，对不上把那半截删掉，不留「看着下好了但装不上」的模型。
  下载源与语音识别那边是**分开存的两个键**——一个源指错了不该悄悄改掉另一个源的配置；
  留空即回到默认源。支持中途停止；**不支持断点续传**，所以「上次没下完」会如实说已收到百分之多少、
  并讲清会从头开始。
- **两个档次可选**：轻量那档是 Qwen3-0.6B（约 345 MB），另有一档**腾讯混元 HY-MT2-1.8B
  （int8 量化，约 1.7 GB）**——它是翻译**专用**模型（33 种语言），译文质量明显好于 0.6B。
  默认仍是 0.6B：**默认值是给所有人的**，而 1.8B 在 8 GB 以下的机器上很可能跑不起来。
  选它的人确实多付 5 倍体积，但换回来的是他能看出来的差别。
- **内存需求写在下载之前**：模型卡片上直接写「运行需约 2.7 GB 内存」。不写清楚，
  用户要花掉 1.7 GB 流量之后才知道自己这台机器带不动，而那时候他没有退路。
  如果实测需求超过本机总内存的 40%，再多一句红字「本机总内存约 3.8 GB，这条模型可能跑不起来」——
  **只是提示，不拦**：阈值只是估计（判不准时该警告没警告＝白下 1.7 GB，不该警告却警告＝一句灰字，
  两种错代价差得远），所以把判断权留给用户。
- **为什么不进 APK**：就是那 345 MB 起步的模型，而整个安装包约 135 MiB。本地翻译是「用的时候才需要」的功能，
  让每个用户为它多付近三倍体积不划算。
- **但安装包本身还是变大了**：v0.6.3 约 88.6 MiB → 现在约 134.7 MiB。涨的是**推理运行时**
  `liblitertlm_jni.so`（arm64-v8a 21,802,960 B + x86_64 25,968,008 B，`.so` 不压缩存放），
  这一份省不掉——没有它就跑不了本机模型；模型本身仍然是按需下载的。
- **为什么是 0.6B**：这是能在手机上跑得动的量级。字幕翻译不需要世界知识，更大的模型在同一批字幕上
  要慢好几倍——宁可先给一条能用的，也不要给一个「点了要等十分钟」的选项。
- **只跑 CPU**：不挑机器、结果可复现，代价是慢（一批 3～10 条实测几秒到几十秒）。
  好处是**一批一批地翻**，进度条能看到推进，不是一次等到天亮。
- **约束解码把输出结构钉死**：本机这一路的 JSON Schema 不是「建议」，而是真的被编译成**解码约束**，
  模型在解码期就走不到「不合法 JSON」那条路上。这与云端完全不同——云端那套
  `response_format` 只保证「是合法 JSON」，**字段名根本没发给模型**，实测模型会自己发明键名，
  所以云端靠的是提示词里那段格式说明。也就是同一件事的两种说法：提示词说一遍、本机解码器强制一遍，
  两处必须一致（改一处要同时改另一处，提示词那边还有 `TRANSLATION_PROMPT_VERSION` 要跟着涨，
  因为缓存键跟着它走）。
- **条数钉进 schema，而不是写进提示词**：这一批要翻几行是**调用方自己知道**的，
  所以它直接进 `minItems` / `maxItems`，不要求模型回显。理由有两个，都是实测换来的：
  0.6B 会**稳定地**把一整批译文并成**一个**字符串（数组长度 1，句与句之间用 `\n\n` 粘起来），
  靠重试不会变好；而「要求模型回显一个它无从决定的数字」本身就是一类典型错误——
  每多一个必填字段，就多一次被静默漏掉的机会。拆批之后条数跟着变小（每一批按它自己的行数算）。
- **失败原因按「下一步做什么」分开**：这三条各需要完全不同的动作，挤成一句「翻译失败」就等于没解释。

  | 界面说的事 | 下一步动作 |
  | --- | --- |
  | 本机模型「x」还没下载好 | 去「本地模型」把它下下来 |
  | 本机推理引擎没能启动 | **下载模型解决不了这一档**——多半是内存不足或本机不支持，先重启应用，或换更小的模型 / 改用云端 |
  | 本机模型这次没能给出结果 | 重试通常就好；反复出现就换更小的模型或改用云端 |

- **可以只删模型**：删除只清这一个模型的文件，**已经译好的字幕一个都不受影响**；
  可以重新下载。
- **一个已知的模型毛病**：它会把提示词里那段「输入 / 输出」示范**照抄**——
  遇到没有实义的短行（例如 `Line two.`）时直接输出示例的答案。
  相邻的行都翻对了，所以不是对齐问题。修法会牵动提示词的整套校准，留到后续版本。

### 10. 云端语音识别字幕生成（高级目标）

第 8 节的对称动作：**音频不再留在手机上**，而是切成块上传给服务商来识别。产出是同一种东西——
一份落在私有目录、自动挂上并选中的 `.srt`。设置 → 语音识别 最上面多一段**识别方式**。

- **默认仍然是「本机识别」。** 这不是随手定的：本机那条路的代价（下模型、慢）用户看得见也随时能反悔，
  而云端那条路的代价是**整段音频离开这台设备、且不可逆**——要不要付这个代价得用户自己选一次。
- **服务商预设四家 + 自定义**：OpenAI（`whisper-1`）、Groq（`whisper-large-v3-turbo`）、
  硅基流动（`FunAudioLLM/SenseVoiceSmall`，**不出时间轴**，选项上直接标出来）、
  以及「自定义」（中转站、自建兼容层）。默认服务商是硅基流动：国内直连、密钥门槛最低。
- **地址栏下面实时显示最终请求地址**：「服务地址」填什么，下面就有 `将请求：https://…/v1/audio/transcriptions`。
  这一行是这一版最实用的一处——云端配置错几乎都是**地址少写一段**（漏了 `/v1`），
  而它是唯一能在按下按钮**之前**看出这件事的地方。地址不像地址时标红并说明，
  **顺手把播放页那个按钮变灰**：这里的判定与发请求前那道检查是同一个结论，
  所以不会出现「按钮亮着、点了必错」。
- **换服务商会清掉地址与模型栏**：不清的话会把上一家的地址发给下一家。密钥则是**每家一把钥匙**，
  单独存、单独删，用系统密钥库加密后放本机，不写日志、不随设置导出。
- **按固定 5 分钟切块上传（每块约 9.6 MB）**。为什么按长度切而不按静音切：静音切分（VAD）
  要先在本机把整段音频解一遍，那正是「本机识别」在做的事，于是这条路一点时间都没省下。
  为什么是 5 分钟：16000 Hz × 2 字节 × 300 秒 = 9.6 MB，刚好躲开 10 MB 这一档的常见单次请求上限；
  一个超限的块会让**整次识别**失败，所以这个数字是按「不能撞线」选的。切片是自己拼的 16 kHz 单声道
  WAV（不依赖设备有没有 AAC 编码器，少一个设备相关的失败点），落在缓存目录，跑完就删。
- **时间轴：服务商给就按句，不给就整块一条。** 尽量请求 `verbose_json`：能拿到 `segments` 就逐句拆成多条字幕，
  只回 `text` 就整段音频算**一条**字幕——**两种都不是失败**，这几家的能力本来就不一样。
  两个实测细节：`start` / `end` 是**秒的浮点**（要 ×1000 取整再加块偏移，当毫秒用会让所有字幕挤在开头），
  每段 `text` 都**带前导空格**（清洗走的是与本机识别同一个 `AsrTextNormalizer`，两条路风格才一致）。
- **失败原因按「下一步做什么」分开**（共 10 类）：

  | 界面说的事 | 下一步动作 |
  | --- | --- |
  | 连不上识别服务 | 换个网络 / 稍后再试（这一块没花钱） |
  | 「%s」拒绝了这次请求——API Key 没填或不对 | 去设置页填或换密钥 |
  | 服务商按**账户策略**拒绝（403） | 换服务商——**换密钥没用** |
  | 这个地址上**没有**识别接口（404） | 改地址——多数兼容服务要把路径写到 `/v1` |
  | 服务地址还没填好 | 把地址填完，或改用本机识别 |
  | 服务商不接受这次请求（400） | 换模型或预设（常见成因：这个模型不支持返回时间轴） |
  | 这一块音频超过体积上限（413） | 改用本机识别（不上传、无体积限制） |
  | 额度用完或被限流（429） | 充值 / 换服务商（`Retry-After` 会带出来） |
  | 服务商侧故障（5xx） | 稍后重试——本地做什么都没用 |
  | 返回的内容读不出来（200 但没文字） | 换预设 / 报 bug（典型成因是中转站自己包了一层） |

  合并成一句「云端识别失败」的后果很具体：**401 和 403 会变成同一句话，用户会去反复重填密钥**，
  而 403 是账户策略挡的，改一万次也不会好。服务商不给原因时**不会留一个悬空的冒号**
  （换成一句「服务商没有说明原因」），完整原文仍然记在日志里。
- **两处隐私告知，都在按下按钮之前**：设置页选云端时说一次，**播放页那个按钮上面再说一次**
  （「云端识别：整段音频会上传到「服务商」，传完才开始识别。」），按钮文案也从「生成字幕」
  改成**「上传并生成字幕」**——那是用户最后一个能反悔的位置。
- **一部片子只有一条生成字幕，换引擎重跑会覆盖上一条**：文件名是「媒体哈希」，与走哪条路无关。
  两份并存会在面板里出现两个同名字候选（内容只有时间轴切分不同），用户没法分出哪条是哪条；
  而生成的字幕本来就可以再跑一遍，覆盖它不丢用户劳动。
- **失败不会留下半截结果**：第 3 块传失败时前两块的结果**不会**写出去，盘上仍是上一次那份完整字幕，
  而不是一份只有前 7 分钟的残缺字幕。

### 11. 应用更新（版本更新系统）

设置入口页第 8 行「检查更新」，进去是一页三段：**当前版本**（右侧一个「检查」按钮，
进页面时也会自动查一次）、**发现新版本**（只有真查到才出现：tag、发布时间、完整发行说明、
`下载并安装` / `忽略此版本`）、**更新设置**（更新通道 / 自动检查 / GitHub 令牌）。
**「自动检查」这一个开关同时管「启动时查」和「进这一页时查」**——两种自动检查一起关掉，
而用户亲手按「检查」永远有效；关掉之后一个网络请求都不会发。

- **更新源**：GitHub Releases（`Aaze-wu/MultiSuperPlayer`），走匿名 API。
- **令牌可选填**。不填也能用，填了只是把「每小时 60 次」提到 5000 次。
  令牌只存在本机、用系统密钥库（`Keystore`）加密，**不上传**；界面上直接写着这一句。

#### 三条线，两个通道

发版走三档，更新页里只有两个选项——这不是少做了一个：

| 版本号 | 是什么 | 正式版通道 | 测试版通道 |
| --- | --- | --- | --- |
| `X.Y.Z` | 正式版 | ✅ | ✅ |
| `X.Y.Z-beta.N` | 公开测试版 | ❌ | ✅ |
| `X.Y.Z-alpha.N` | 内部构建 | ❌ | ❌ |

- **`alpha` 不是「第三档」，而是根本不进公开发布的东西**。它只在本地编译、自己装上试，
  一个 Release 都不发。所以「只收 alpha」这一档在更新页里没有任何东西可收，
  放上去就是一个永远什么都不发生的选项——而用户会以为「选了没反应」是自己没点对。
- **测试版通道必须收正式版**。否则装了 beta 的用户永远退不回来：他得先收到正式版才能回到正轨。
- **判据看 tag，不看 GitHub 上那个 `prerelease` 勾**。勾是发布时手指点的开关，可以忘；
  `-beta.1` 后缀是构建流程写进包里的，不会忘。宽松的那一侧留给测试版通道：
  它同时接受「tag 带 `-beta.N`」和「勾了预发行但 tag 没有后缀」，正式版通道两条都不占。
  这样「忘勾一次」最多是把一个测试版漏给**已经选了测试版**的人，而不是推给所有人。
- **同一版本的 alpha / beta / 正式版 `versionCode` 是同一个数**（`major*10000 + minor*100 + patch`），
  这是故意的：`versionCode` 只管「能不能覆盖安装」，谁新谁旧交给 semver 判断，
  而 `0.9.0-alpha.1 < 0.9.0-beta.1 < 0.9.0` 在 semver 2.0 里本来就成立，
  `UpdateVersion` 那套比较一行都不用为它改。
- **老名字要显式翻译一次**。0.8.1 及以前这一档叫 `PRERELEASE`，现在叫 `BETA`。不翻译的话，
  装了预发行版的用户退回默认值恰好也是 `BETA`（看不出问题），但**一个手动选过这一档的正式版用户
  会被悄悄退回「只收正式版」**：他下次再也收不到测试版，而且没有任何提示。
- **关于页的徽章分两种词**。`beta` 写「测试版」，`alpha` 写「预览版」：前者是「可以用了，
  帮忙看看」，后者是「随时会变，别当回事」。一律写「预览版」等于把一个正常可用的公开版本说成实验品。

具体的操作步骤（改哪一行、敲哪条命令、发布完对什么）见 [`docs/release-process.md`](docs/release-process.md)。

#### 启动时的那一次检查

程序启动时会自动查一次更新（在安装后的权限申请流程走完之后，两个弹窗不叠在一起）。
查到更新就弹一个三键弹窗，**没查到什么都不提示**——启动检查失败只写一行日志，
绝不弹「网络错误」：用户只是打开了应用，没有请求任何东西。

| 按钮 | 它做什么 | 下次启动 |
| --- | --- | --- |
| 立即更新 | 关弹窗 → 进更新页 → 才开始下载 | 照常检查 |
| 以后再说 | 只关掉这一次的弹窗 | 还会再弹 |
| 忽略此版本 | 记下这个 tag（持久） | 只要还是这一版就不再弹 |

三个点的理由：

- **「以后再说」刻意不落盘**：它表达的是「现在不想处理」，不是「以后都别提」；真要后者，
  旁边那个键才是。
- **「立即更新」不在弹窗里直接下载**：下载完要拉起安装器，而安装器那个 `Intent` 的接收点
  必须是一个**常驻的界面**——弹窗一关它的接收点就没了，用户会看到「下载完成」但安装器
  永远不出现。所以先导航到更新页再开始下载。
- **只建一个 `UpdateViewModel`**（在应用根部），显式传给更新页和弹窗。否则「更新页拿到的实例」
  和「弹窗用的实例」是两个（`NavBackStackEntry` 作用域各有一个），「在弹窗上点了忽略、
  更新页还显示有新版本」。

只要还有更新的版本，判定结果就是 `Available`，所以弹窗**可能**每隔 12 小时再出现一次。
这是有意的：「安静地不再提」比「多提一次」更容易让用户错过更新；真要安静下来用「忽略此版本」。

#### 检查那层不认识 GitHub

用户已经说了「后续会加其他渠道」，所以检查逻辑里**没有一处 GitHub**：

```
UpdateSource（接口）       ← 只有 listReleases(): List<UpdateRelease>
    ↑
GitHubReleasesSource       ← 唯一知道 GitHub JSON 长什么样的地方
    ↑
UpdateManager              ← 版本比较、节流、忽略、设置，全在这里
```

`UpdateRelease` 是渠道无关的：tag、版本、是否预发行、发布时间、说明、
**一个（或零个）APK 资产**（地址 / 大小 / sha256）。换渠道 = 新写一个 `UpdateSource` 实现，
上层一个字都不用改。

#### 四种状态，各说各的话

`UpdateRules.decide(current, releases, channel, ignoredTag)` 是**零 Android 依赖的纯函数**：

| 状态 | 界面说的 |
| --- | --- |
| `NotChecked` | 还没有检查过 · 当前版本 x.y.z |
| `UpToDate` | 已是最新版本 · 当前版本 x.y.z |
| `Available(release)` | 有新版本 vX · 当前版本 x.y.z |
| `Ignored(release)` | 此版本已被忽略 · 当前版本 x.y.z |

两个不是「随手写」的地方：

- **「还没有检查过」和「已是最新」不是同一件事**。自动检查受 **12 小时节流**，
  被跳过时返回 `null`，界面**什么都不改**。把「跳过」当成「已是最新」的后果是：
  每次进这一页都把你上次查到的「有新版」擦掉一次，而那是最重要的一条信息。
- **解析不出当前版本时不猜**。`UpdateVersion.parse` 失败 ⇒ 直接是 `NotChecked`，
  而不是拿一个 `0.0.0` 去比（那会让每个版本都显示成「有新版本」）。

#### 下载与安装：四道防线

升级包是**要拿去执行安装**的东西，风险等级和「下载一个模型」不同：

1. **先写 `<name>.part`，校验通过才 `renameTo`**。直接写目标名的话，一次中断会留下一个
   「大小差不多、内容不全」的 APK，下次进来看到文件已存在就以为下好了——
   安装时才报「解析包时出现问题」，而那时已经没人会想到是下载的锅。
   同目录内的 rename 是原子的，所以**目标名出现 ⟺ 内容完整**。
2. **失败或取消必须删掉 `.part`**，否则用户看到「占了几十 MB 却什么都没有」，
   然后他会再点一次，再占几十 MB。清理放在统一的 `catch (Throwable)` 里，
   这样**将来新加的失败分支自动也享受这条规矩**。
3. **校验用 sha256**，不用「能不能打开」或「大小对不对」。发布信息里给了 sha256 就比对；
   没给就在日志里说明跳过，此时仍由下面第 4 条兜着。
4. **安装前校验包名与签名**：只允许「包名相同」且「签名与本机已安装版本相同」的包进入安装器。
   包名不同 ⇒ 装上去是另一个应用；签名不同 ⇒ 系统本来也会拒绝，但那要等用户在系统安装器里
   点完「安装」才报一句 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，不如自己先拦住并说清原因。

另外：**服务端给了长度、发布信息里也有长度、两者不一致**时立刻失败，不必等把 140 MB 读完
再让摘要失败——失败消息也会从「摘要不符」变成一句查得出真因的话。

#### 两条系统门

- **「安装未知应用」授权**：Android 8 起，一个应用要拉起安装器必须先去系统里打开这个开关。
  未授权时页面显示一行提示 + 「去允许」，点了直接跳到本应用的授权页。
  状态**每次回到页面**（`ON_RESUME`）重读系统，不存本地副本。
- **`FileProvider`**：安装器拿不到我们的私有目录，包必须通过 `content://` URI 递过去。
  `update_apk_paths.xml` 里**只放开了 `cache/updates/` 这一个目录**——放别处或放开整个 cache
  都会在调用安装器时抛 `Failed to find configured root`。包放 `cacheDir` 而不是 `filesDir`：
  升级包装完就没用了，放缓存里系统能在空间吃紧时自己回收。

#### 失败要分开说

`UpdateFailureText` 有八条：网络 / 限流 / 找不到 / 服务端错误 / 没有安装包 /
下载内容损坏 / 签名不符 / 没有安装器。**合并成一句「更新失败」的后果很具体**：
「GitHub 限流」和「网络不通」会变成同一句话，而前者要「过一会儿再试或填个 token」、
后者要「检查网络」——用户按错了方向就永远修不好。

## 二、构建与运行

### 1. 环境要求

| 项 | 版本 | 说明 |
| --- | --- | --- |
| JDK | **21** | 见下面的「JDK 坑」。源码 `jvmTarget` 是 17。 |
| Android SDK | **compileSdk 36**（需装 `android-36`） | `minSdk 26`，`targetSdk 36` |
| Gradle | 8.14.3（wrapper 自带） | 分发地址用腾讯云镜像 |
| AGP / Kotlin | 8.13.2 / 2.4.20 | 见 `gradle/libs.versions.toml` |

#### JDK 坑（务必先读）

**Gradle 的 daemon 必须跑在 JDK 21 上。** 跑在 JDK 25 上时构建会失败，而且报出来的东西只有一行版本号：

```text
FAILURE: Build failed with an exception.
* What went wrong:
25.0.1
```

修复方式：在**用户级** `~/.gradle/gradle.properties`（Windows：`%USERPROFILE%\.gradle\gradle.properties`）里加：

```properties
# 路径必须用正斜杠：.properties 里反斜杠是转义符，写成 C:\Program Files 会被吃成 C:Program Files
org.gradle.java.home=C:/Program Files/Microsoft/jdk-21.0.8.9-hotspot
# 顺便把 21 登记为已知工具链，Android Studio 的 Gradle JVM criteria（Version: 21）就不用依赖 JAVA_HOME
org.gradle.java.installations.paths=C:/Program Files/Microsoft/jdk-21.0.8.9-hotspot
```

写在用户级而不是项目里，是为了**不把本机绝对路径提交进仓库**（`gradle.properties` 里有一条注释专门说明这一点）。
Android Studio 侧对应设置：Settings → Build, Execution, Deployment → Build Tools → Gradle →
「Default Gradle JVM criteria」的 Version 选 **21**；默认推导出来的 25 会让同步直接失败。

> 注意区分：`JAVA_HOME` 只决定**启动器** JVM，`org.gradle.java.home` 决定**daemon** JVM。
> 本机 `JAVA_HOME` 指向 25 也能正常构建，因为 daemon 被钉在了 21。

### 2. 依赖镜像

国内网络下所有下载都已经走镜像，不需要额外配置：

  所以**不需要 jitpack.io**。

### 4. Release 签名

把根目录的 `keystore.properties.example` 复制成 `keystore.properties` 并填入真实值（该文件已被 `.gitignore` 忽略）。
**文件缺失时 Release 会自动回退到 debug 签名**，保证新克隆的仓库和 CI 依然能产出可安装的包，而不是直接构建失败。

### 5. 版本号只有一个来源

版本号写在 `app/build.gradle.kts` 顶部的 `appVersionName`，`versionCode` 与 BuildConfig 都由它推导：

```text
versionCode = major * 10000 + minor * 100 + patch      // 0.6.0 → 600
```

不要在 `defaultConfig` 里另写一份数字 —— 以前就是这么写的，结果 git tag 已经打到 v0.5.3 了，
包里还写着 0.4.0，而且**不会有任何东西报错**。构建时还会用 `git describe` / `git rev-parse` 把
commit、tag、构建时间注入 BuildConfig，供「关于」页显示；`git` 不在 PATH 上时全部降级成「未知」，不会构建失败。

### 6. 测试素材

`tools/make-test-media.ps1` 会用 ffmpeg 生成一套固定的验证素材（含空档、双语句式、逐字 LRC、
GBK 编码、中文文件名）。手动敲 ffmpeg 每次都会漏掉其中一两项，而漏掉的那项恰好就是这次要测的。

```powershell
pwsh -File tools\make-test-media.ps1
pwsh -File tools\make-test-media.ps1 -OutputDir D:\tmp\media -FfmpegPath D:\ffmpeg-build\bin\ffmpeg.exe
```

输出默认落在 `%TEMP%` 下，不进版本库。

几条**不要破坏**的规则：

1. **`core:model` 保持零模块依赖。** 它是所有人共享的词汇表；一旦它开始依赖别的东西，
   依赖图就会长出一个环。这条规则的实际代价见下面的「已知限制」。
2. **`feature:*` 之间互不依赖**，也**不能依赖 `:app`**（`:app` 依赖它们）。
   跨功能域要共享的东西放 `core:*` 或走导航。
3. **只有 `:app` 是 `com.android.application`**，其余 11 个模块都是 `com.android.library`。
4. **`android.nonTransitiveRClass=true`**：模块之间**不能互相引用 `R` 类**。
   同一条文案若两个模块都要用，就在各自模块里各写一份（例如 `core:common` 的
   `msp_wrapped_in_parens` 与 `feature:player` 的 `msp_player_wrapped_in_parens` 是同一句话）。
   这看起来是重复，但它是这条编译期约束下唯一不会出错的做法。

### 文案为什么是 `MspText` 而不是 `String`

JVM 单元测试里 `Resources` 是不可用的（`testOptions { unitTests.isReturnDefaultValues = true }`
让 `android.*` 一律返回 0/null）。如果纯逻辑层直接返回 `String`，那么「同一句话在不同语言下
是什么样子」就只能在真机上看，一条断言都写不了。

所以纯逻辑层（`core:common` / `core:player` / `core:translate` / `core:data` / 各 ViewModel）
返回 `MspText`：要么是 `Plain`（本来就跟语言无关，比如格式名 `SubRip`），
要么是 `Res(id, args)`（**到 UI 边界才解析**）。Compose 侧一律用

```kotlin
Text(row.label.string())          // import com.multisuperplayer.core.ui.text.string
```

一个句子由多段拼起来时，**不要**用 `buildString` / `"$a · $b"` —— 分隔符也是语言的一部分
（中文是 `·`、英文是 `,`），而且拼接顺序在别的语言里可能要调换。用：

```kotlin
MspText.join(SEPARATOR, listOf(partA, partB, partC))
```

## 四、测试

```bash
./gradlew test
```

- 全部是 **JVM 单元测试**（JUnit 4），不需要设备或模拟器。
- 测的是纯逻辑：字幕解析器、翻译失败分类、批量与缓存、导出、主题枚举、设置摘要文案、

  `tools/` 与各模块的 KDoc 里。

## 五、已知限制

这些是**当前版本有意留下**的，不是被忘掉的：

1. **部分老格式放不了。** NextLib 提供的是**解码器**（编码格式），不是**解封装器**（容器格式）。
   因此「本机没有解码器」能被它救回来，「无法识别封装格式」不能：WMV/ASF、RealMedia(RM/RMVB)
   至今仍不支持，升级这个库也解决不了。
2. **Matroska 里的 DTS / AC-3 会被 Media3 的解复用器丢掉**：有进度条、没声音、**不报错**。
   这是上游行为，本项目的错误映射看不到它。
3. **ABI 只保留 `arm64-v8a` 和 `x86_64`。** 四个 ABI 全打进一个包会让 APK 无谓地大一倍
   （实测 arm64-v8a 7.5MB + x86_64 11.1MB，未压缩）。代价是 32 位设备**装不上**——
   不是装上了用不了，是安装器直接拒绝。要覆盖老设备应该加 ABI split 或改发 AAB。
   语音识别引擎的 native 库（`core/asr/src/main/jniLibs/`）**同样只留这两个 ABI**：
   另外两套（约 57 MB）永远不会进 APK，也就没有理由占着仓库；要支持 32 位时从
   `sherpa-onnx-1.13.8.aar` 的 `jni/<abi>/` 里解出来放回去即可（目录名与文件名必须一致，JNI 按名字加载）。
4. **`core:subtitle` 的解析告警仍是中文。** 告警类型是 `List<String>`，与**零依赖的
   `core:model`** 绑在一起。正确修法是把 `MspText` 移到 `core:model`（它本身零依赖，符合该模块定位），
   再让告警变成 `List<MspText>`。留到后续版本做。
5. **日志报告与导出字幕里的机器可读骨架刻意不翻译。** 日志报告的抬头行（来自界面）跟着界面语言走，
   但 `===== … =====`、`导出时间:` 这些骨架保持固定：它是排查问题时给人搜索用的，混进译文反而
   会让按关键字搜索失效。同理，导出的 ASS 文件里那一行 `; 由 MultiSuperPlayer 导出` 是溯源标记，
   不是界面文案。
6. **翻译目标语言的「给模型看的名字」固定为中文**（`TranslationTarget.promptName`）。
   它描述的是「要翻成什么」，与界面语言无关，而且固定下来才能让缓存键稳定。
7. **媒体库按标题排序时，中文是按 Unicode 码点排的，不是拼音序。** 拼音排序需要额外的
   映射数据（否则「张」会排到「王」后面），代价与收益不成比例。标题相同的条目退化成按 id 排，
   这样至少是**稳定**的——顺序不会每次刷新都变。
8. **封面是自动取的，不能手动换一张。** 音频取文件里内嵌的那张（Android 10+ 上优先问系统媒体库要缩略图，
   这样不必把整个文件读进内存），视频取内嵌封面、没有就按时长抽帧。**没有「换到另一帧」或「自己挑一张图」的入口**，
   也没有「清掉这张封面」这个动作。一个直接后果是：**本身就是黑底的片段（纯语音录制之类）会得到一张黑封面**。
   这是刻意的取舍——一张黑图至少还能认出是哪一片，不画等于退回类型图标，用户会以为这个功能没生效。
   阈值（平均亮度低于 0.12 就算太暗）是启发式，不是「黑」的定义。
9. **Android 9 及以下的媒体库条目不会自动找同目录字幕。** 系统从 Android 10 才提供
   `RELATIVE_PATH` 这一列，之前拿不到媒体所在的相对路径，自动发现就没有起点。
   界面会**明说**原因（「无法确定这个文件所在的文件夹，没法自动找同名字幕」），
   而不是假装「这个目录里没有字幕」；用户仍可在面板里手动挑一个同目录的 `.srt` / `.ass`，这条路径是通的。
   （内置文件选择器打开的媒体**不受这条影响**：它走的是「直接列目录」那条路，见第七节。）
10. **内置文件选择器不写媒体库。** 浏览只是浏览：从这里打开的文件不会因此进媒体库、也不会进「最近播放」。
    v0.5.9 起它**参与多选**（可与媒体库一样「加入播放列表」），但选中的条目同样不会回写媒体库——
    「加入播放列表」是往播放列表里写，两者是不同的表。
11. **播放列表里的条目没有保存「显示名字」。** 条目按 id 主键存，恢复时只能拿回标题 / 艺术家 / 时长这几个
    快照字段。受影响的是**字幕发现的日志**：那里会用显示名字写一行「正在为 xxx 找字幕」，
    从播放列表恢复的条目这一行少一个名字（其它字段都有）。要补上得改存储格式并写迁移，
    而代价（改 schema）与收益（多一行日志里的一个名字）不成比例。
12. **内嵌位图字幕（PGS / VobSub / DVB）能画出来了，但字幕的微调与样式对它一律不生效。**
    位图字幕带的是图、没有字（`Cue.text` 是空的），所以它走**另一条渲染路径**：播放页在画面矩形上
    单独叠一层（`BitmapSubtitleLayer`），摆放公式逐行照抄 Media3 的 `SubtitlePainter.setupBitmapLayout`；
    Media3 自带的 `SubtitleView` 仍然遮着（否则内嵌**文本**字幕会画两份，见上文「片源自带的字幕」），
    两条路同一时刻只有一条在画。三件事刻意不进那一层：**字幕延迟 / 字幕速率**（那是我们自己在时间轴上
    做的位移与缩放，而位图 cue 由 Media3 按时间戳直接投递，插不进手）、**字幕样式**（字号 / 行距 /
    描边 / 底部距离——图里的字已经画好了）、**整轨预读**（预读是给文本准备的「一次性拿到整表」）。
    面板会为位图轨写明这一点，而不是让它看起来像「这条轨读不出来」。另外 VobSub / DVB 的实际画形
    依赖片源初始化段里的调色板与尺寸（`VobsubParser` 的前置条件相当严），目前只有 PGS 有实测样本，
    这两个按「能用就用、认不出来就当这条轨没有」处理。
13. **本机语音识别的模型不打进 APK，必须用户自己下。** 两个模型分别约 78.1 MB 与 189.8 MB，
   把 78 MB 塞进安装包只会让不打算用这个功能的人白等一次下载，所以入口做成了「先选模型、再下载」。
   代价是第一次用之前必须先下完（镜像站上实测 78.1 MB 约 1 分钟），而且**没有网络就装不上模型**
   （识别本身不需要网络）。识别跑在 CPU 上，速度取决于手机算力（33 秒素材在 x86_64 模拟器上约 8 秒），
   长片按比例更久，且结果是**一次算到底**的——没有「先给前半段、边播边识别」这种流式产出。
14. **识别质量完全取决于音源。** 纯音乐、强环境噪声、多人抢话、方言重的片段都可能识别成空
   或者错字，而**这些结果不会被自动纠正**，面板里也看不出「这一句置信度很低」——
   识别结果就是一份普通的 SRT。要改只能重新识别一遍、换一个模型，或者用外部字幕盖过去。
15. **均衡器能不能用、能拖到多少，取决于设备和当前音频会话。** 段数、每段中心频率、增益范围
   都是 `android.media.audiofx.Equalizer` 在这台设备上上报的：模拟器和部分设备根本建不出效果
   （面板会直接说「这台设备不支持均衡器」，这是安静降级，不会崩掉播放页），另一些设备只给一半的
   范围——界面取的是我们自己的 ±12dB 与设备范围的**交集**，所以拖不到的值会被限住，
   而不是「拖了没反应」（后者在真机上极难认出来）。滑块固定五根、画的是标准频率：设备段数
   只有在开始播放之后才知道，跟着它走的话面板会在用户眼皮底下从 5 根变成 10 根；曲线按频率存、
   下发时按频率插值，所以同一份设置换台设备仍是同一条曲线。
16. **本机翻译的模型不进 APK，必须用户自己下；而且只跑 CPU。** 模型约 345 MB，
   与语音识别那边是同一个取舍：塞进安装包只会让不打算用这个功能的人白等一次下载。
   代价是第一次用之前必须先下完（镜像站上实测约 83 秒），**没有网络就装不上模型**
   （翻译本身不需要网络）。推理固定走 CPU 后端，好处是不挑机器、结果可复现，代价是慢。
   另外这一栏目前**只有一条模型可选**，且翻译缓存**没有「清空」入口**——想强制重译
   得改字幕内容、或换目标语言 / 换模型。
   注意：**模型不进包不等于安装包没变大**——为了让本机推理能跑起来，安装包从 v0.6.3 的
   约 88.6 MiB 涨到约 134.7 MiB（`liblitertlm_jni.so`，两个 ABI 共约 45.6 MiB，`.so` 不压缩存放）。
17. **云端识别只支持 OpenAI 兼容的 `/audio/transcriptions`。** 阿里云 Qwen-ASR 这类把音频塞进
   `…/compatible-mode/v1/chat/completions` 的服务**本版不支持**——它的请求形态是另一套，
   要接得另写一条请求构造路径。四家预设之外的服务，只要接口形状一致，都可以用「自定义」接上。
18. **切块是按固定长度切的，块边界会切断一句话。** 表现是听感上每 5 分钟多一条半截字幕。
   用重叠切片能补，但重叠区要去重（同一句话被识别两次、时间轴还差半个字），本版不做；
   同样也**没有断点续传**——中途取消会丢掉已经传过的块（配额也已经花掉了），
   也没有「先给前半段」的流式产出，结果是一次性拼好的。
19. **容器不写时长就没法走云端这条路。** 云端必须先知道总长才能切块，而裸 ADTS AAC、
   部分流式封装不写时长。这时**不会**退化成「当成一整块发出去」（两小时的片子会先生成一个
   230 MB 的临时 WAV，多半先把手机存储写满），而是明确报错并建议改用本机识别。
20. **内嵌字幕整轨预读要顺序扫一遍整个文件，而它只对本地文件生效。** 字幕样本在容器里和
   音视频交错存放，「读完整条字幕轨」就等于把文件顺序读一遍——网络流不能为了字幕把整个流
   下载一遍，所以直接标成「不适用」，大体积片源则要读上一会儿。播放**不等它**（没读完就用
   原来的流式表），但面板上会写「正在预读字幕…」；失败时不报错、只写一句
   「预读字幕失败，速率调整可能不准」，**具体原因（认不出容器 / 找不到那条轨 / 一条台词都没有 /
   读取出错）只在日志里**。另外预读表是**整表替换**、不做渐进发布（换表会让 cue 序号漂移，
   而人工修正过的译文是按「序号 + 原文」存的）。

## 七、贡献

欢迎提 issue 与 PR。动手前请留意：

- 提交信息与代码注释使用中文；标识符、日志 key、资源 key 用英文。
- **新增文案必须同时补 `values-en/` 与 `values-b+zh+Hant/`**，否则守卫测试会失败。
- 纯逻辑层不要直接返回 `String` 形式的用户可见文案（见上文 `MspText` 一节）。
- 修改 `gradle/libs.versions.toml` 里的 AndroidX/Compose 版本前，先确认目标版本的 AAR 元数据里
  `minCompileSdk ≤ 36` 且 `minAndroidGradlePluginVersion ≤ 8.13.2`：
  这些约束写在 AAR 内的 `META-INF/com/android/build/gradle/aar-metadata.properties` 里，
  **Gradle 版本目录和 Maven 页面都看不出来**，只有在 `CheckAarMetadata` 阶段才会炸出来。
  同理，改 `media3` 时必须同步改 `nextlib`——它的版本号规则是 `<它支持的 media3 版本>-<自身版本>`，
  不匹配的组合会在**运行时**以 `NoSuchMethodError` / `AbstractMethodError` 出现，编译期完全看不出来。
